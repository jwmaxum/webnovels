# OP-01 관리자 메뉴 통합

작성일: 2026-11-01 (Asia/Seoul)

[관리자 CMS 개발계획](admin-cms-minimal-ux-plan-2026-11-01.md)의 첫 단계로 기존 업무 화면을 6개 상위 메뉴와 하위 메뉴로 통합한다. 기존 API·데이터·업무별 권한을 유지한다.

## 메뉴와 업무 연결

| 상위 메뉴 | 하위 업무 | 기본 주소 |
| --- | --- | --- |
| 운영 홈 | 실데이터 운영 현황, 업무 바로가기 | `/admin` |
| 콘텐츠·전시 | 작품·회차, 회차 조회, 추천·홈 구성, 공지·정책 준비 안내 | `/admin/content?tab=works` |
| 회원 관리 | 독자, 작가 | `/admin/members?kind=reader` |
| 결제·정산 | 결제·입금 준비, 환불·포인트 준비, 기존 작가 정산, 대사 준비 | `/admin/finance?tab=payouts` |
| 통합처리함 | 신고·공개본 변경 검토, 원고 복구, 이의제기, 문의·베타 운영 현황 | `/admin/inbox?tab=cases` |
| 설정 | 서비스 정책 안내, 외부 연동·기존 운영 설정, 운영자·권한, 감사 기록, 운영 상태 연결, 제한된 시험 도구 | `/admin/settings?tab=service` |

기존 14개 일상 항목은 상위 메뉴로 병렬 노출하지 않는다. 하위 기능은 실제 기존 권한으로 각각 필터링하며, 접근할 수 있는 하위 기능이 없는 상위 메뉴는 숨긴다. 독자/작가 권한도 구분한다. 가상 계정 시험 도구는 최고 관리자에게만 설정의 하위 메뉴로 제공한다.

‘메뉴·업무 찾기’는 접근 가능한 메뉴 이름을 현재 메모리에서 검색한다. 검색어를 서버·URL·브라우저 저장소에 보내지 않는다. 실제 회원·작품 통합 검색은 OP-02의 별도 서버 검색으로 개발한다.

## 호환과 접근 제어

- 기존 `/admin/works`, `/admin/authors`, `/admin/users`, `/admin/settlements`, `/admin/cases`, `/admin/review`, `/admin/comments`, `/admin/audit` 등의 주소와 `switchAdminSubTab()`·`AdminOperations.navigate()` 호출은 새 주소로 연결한다.
- 주소를 정규화할 때 기존 링크는 history replace, 사용자 메뉴 이동은 push를 사용한다. 뒤로가기에서는 전체 pathname·query를 전달하고 중복 대시보드 조회를 막는다. 일반 로그인에서 다른 페이지로부터 관리자 화면을 열어도 `/admin`을 기준으로 진입한다.
- `source`, `kind`, `offset`, `target` 등은 형식 검증 후 사용한다. 실제 렌더러에는 해당 업무가 지원하는 옵션만 전달하며, 미지원 식별자를 새 API 필터인 것처럼 보내지 않는다. 검색어·이메일·토큰 등 알 수 없는 query는 정규화 주소에서 제거한다. 외부 URL, 잘못된 query와 중복 매개변수는 거부한다.
- 기본 진입에서는 접근 가능한 첫 업무를 선택한다. 특정 독자/작가·기능을 명시한 권한 없는 주소는 접근 거부를 표시한다. 조회 응답은 화면·계정·권한이 유지될 때만 반영하고 로그아웃·전환 시 기존 초기화 체인을 유지한다.
- 신규 발행과 예약 발행은 작가가 직접 진행한다. 이미 공개한 본문의 수정·삭제 검토는 기존 공개본 변경 요청 흐름을 유지한다. 추천은 기존 관리자 선정 기능에 연결하며 자동 추천을 새로 만들지 않는다.
- Workflow 미활성 환경에서도 기존 Console의 회원 구분과 신고 출처를 외부 메뉴와 맞춘다. 해당 Console이 지원하지 않는 댓글 신고 출처는 연결 준비 상태로 명시하고 기존 신고 목록으로 이동하는 링크를 제공한다.

## 화면과 보존 범위

현재 위치·제목·업무 설명, 권한별 하위 메뉴, 운영 홈 바로가기를 추가한다. 탐색은 기본 링크를 사용하며 사용자 이동 후 작업 영역으로 키보드 포커스를 넘긴다. 관리자 범위의 별도 CSS에서 밝은 테마 토큰·최소 44px 조작 영역·줄바꿈·모바일 메뉴 배열을 적용한다. 기존 DOM ID, Author/Creator 경로와 계정 ID 계약은 유지한다.

공지·정책 편집기, 결제·환불·포인트·대사는 준비 화면으로 구분한다. 이번 단계에서 결제·광고 보상·PASS·정산 지급·개인정보 접수를 활성화하지 않는다. 운영 DB·스키마·환경변수·기능 플래그는 변경하지 않는다.

## 검증과 후속 단계

`build:compile`, 독립 `tsc --noEmit`, 신규 `test:op01`, 인증·명칭 계약·관리자 운영·17단계·운영 준비·UI-R5/R6/R7/R13·36단계·Cloudflare 번들 등 **14개 검증 명령이 통과**했다. 신규 메뉴·라우팅·권한·검색·레이아웃 검사는 **34개**, 최종 기존 관리자·Workflow·R6 묶음은 **26개**다. 문의 통합의 예전 소스 메뉴명 검사를 새 탐색 모델과 실제 렌더/초기화 연결 검사로 갱신한 뒤 36단계 **35개**가 통과했다. 결과와 범위는 [검증 기록](../../artifacts/op01-verification-2026-11-01.json)에 남긴다.

독립 소스 검토에서 로그인 진입 주소·키보드 포커스·Console 전환 환경의 회원/신고 출처 정합성을 보완했고 해당 회귀를 추가했다. 변경 파일 구문·비밀값 패턴·diff 검사를 수행한다. 테스트는 로컬 VM·정적 DOM·합성 DB를 사용하며, 운영 자료 변경이나 브라우저·휴대폰 인수를 대신하지 않는다. lint 명령은 없고 VM 소스의 수치 커버리지는 측정하지 않는다. push 이후 GitHub CI·Cloudflare 빌드와 실제 자산 반영 상태는 별도로 확인한다.

다음은 **OP-02 회원 관리**다. 작가·독자의 서버 검색, 상태 필터·페이지 이동, 계정 연결·작품·문의·결제 상태를 한 상세 화면에서 연결하고 정보 수정에 사유·동시 편집 방지·감사 기록을 적용한다. 실제 유료 독자와 집계 미준비 상태를 구분한다. 이후 **OP-03 추천·전시 CMS**에서 관리자 직접 선정 목록·순서·게시 기간·미리보기와 독자 추천 메뉴를 연결한다.
