# 15단계 첫 연재·자동 저장 계약

기록일: 2026-10-08. 실행 기록은 [improve15.md](../../improve15.md)에 남긴다. 구현·로컬 회귀 검증과 운영 활성화·실기기 인수를 구분한다.

## 기존 계약의 확장

[작품](creator-works-contract.md), [원고](creator-drafts-contract.md), [파일](creator-files-contract.md), [게시](creator-publication-contract.md), [연재 방식](creator-distribution-contract.md), [Author/Creator](author-creator-contract.md)을 따른다. 새 API·SQL·패키지·저장 포맷을 추가하지 않는다. Auth UUID·작가 ID·작품 ID·원고 UUID와 기존 경로·별칭을 유지한다.

제목만으로 비공개 생성 → 설정 → 원고 작성·사본 복구 → 표지/가져오기 → 같은 서버 revision의 PC/모바일 미리보기 → 직접 권리 확인 → 공개/예약 → 독자 링크 → 다음 원고를 연결한다. 기존 TXT/DOCX 변환 검토·원본 보존·재시도·취소·내보내기를 재사용한다. 웹툰 제작과 성인 게시를 이번 제공 범위로 안내하지 않는다.

## 저장 스케줄

- 입력 중단 후 700ms 기기 저장, 2.5초 서버 저장을 유지한다. 첫 미동기 입력부터 30초 deadline은 이후 입력으로 연장하지 않는다. 저장·확인은 기존 DraftEngine만 수행한다.
- 한글 조합 중 timer·수동 저장·online·게시 준비의 서버 전송을 유예한다. deadline을 유지하고 compositionend에서 최종 DOM 값을 수집한다. 이미 deadline이 지났으면 다음 실행 기회에 요청한다. 원고/계정 전환은 조합 상태를 초기화한다.
- 실행 중 저장 promise를 공유하며 병렬 PUT을 만들지 않는다. 기존 응답은 당시 seq만 확인한다. 후속 수정은 별도 deadline을 유지하고 이전 요청이 끝나면 다시 저장한다.
- 응답 유실의 pending은 원래 키·정확한 payload로 먼저 재전송한다. 확인 뒤 후속 수정을 새 키·revision으로 저장한다. 변경이 없으면 요청하지 않는다. 실패/충돌의 자동 재시도 루프는 만들지 않으며 다음 입력·수동 저장·online에서 재개한다. 충돌은 양쪽 사본 보존과 명시적 해결을 따른다.
- 화면/계정 전환은 timer 취소와 기기 checkpoint를 유지한다. 돌아온 원고는 미동기 내용을 다시 예약한다. 숨겨진 탭은 checkpoint하고 재표시 때 남은 deadline으로 재개한다. 늦은 응답은 원래 context에만 반영한다.

30초는 실행 가능한 탭에서 **요청을 시작하기 위한 최대 대기 목표**다. IME·진행 중 요청·브라우저 중단·네트워크 실패의 서버 성공 시한이 아니다. [HTML timer 표준](https://html.spec.whatwg.org/multipage/timers-and-user-prompts.html#timers)에 따라 브라우저 정시 실행을 보장한다고 안내하지 않는다.

## 체크리스트와 선택 입력

`CreatorReadiness`는 안내와 입력 보조를 제공한다. 작품 정보는 서버 `publication_missing`, 원고는 snapshot/seq/revision/충돌을 사용한다. 게시 권리는 매번 직접 확인하며 비독점 권리 진술을 전자 계약 동의로 대체하지 않는다. 최종 유형·등급·제재·권한·버전은 서버가 판정한다. 표지는 선택 사항이며 제목 기본 표지를 허용한다.

파일/게시 플래그가 꺼졌거나 제한 workspace이면 제공 중으로 광고하지 않는다. 비공개 직접 작성·복구는 계속 안내한다. runtime allowlist에 `authorFilesEnabled`를 추가하고 `AUTHOR_FILES_ENABLED === 'true'`일 때만 true다. 비밀·전체 환경 객체를 내보내거나 실제 플래그를 변경하지 않는다.

장르 선택은 현재 독자 필터의 한국어 값(예: `현대 판타지`)을 유지한다. 태그는 `src/config/tags.ts`의 32개 slug를 제공한다. 다른 필드만 수정하면 기존 배열을 보존하고, 직접 변경한 표준 태그 별칭만 slug로 정리한다. 사용자 지정 값을 삭제하거나 소문자·하이픈으로 바꾸지 않는다. 10개 초과는 오류로 안내하고 잘라 저장하지 않는다.

## 미리보기·게시 결과의 경계

저장 후 원격 대조를 기다리는 동안 계정·원고·seq·revision·화면 epoch·조합 상태가 바뀌면 준비를 거절한다. 기기 checkpoint를 기다린 뒤와 각 서버 sync 직전에도 조합·현재 원고·계정·epoch를 재검사한다. 공개 요청은 미리보기의 특정 revision을 유지한다.

sessionStorage의 응답 유실 요청은 같은 사용자·작품·원고에서 확인한다. 목록의 동일 revision/회차가 확인되면 결과를 표시한다. 미확정이면 **이전 게시 요청 결과 확인**으로 당시 키·payload를 재시도한다. 새 체크리스트 누락·후속 입력으로 이전 요청을 변형하거나 재확인을 막지 않는다. 현재 입력을 이전 요청의 미리보기로 표시하지 않는다. 서버는 재시도에서도 권한을 검증한다.

확정 결과는 목록 갱신·기기 백업 실패로 미확정으로 돌아가지 않는다. 확정 후 같은 화면에서 게시를 다시 호출하지 않는다. 공개에만 독자 보기/복사를 제공하며 예약 결과에서도 다음 원고를 시작할 수 있다.

이전 요청이 확인되어도 현재 상태가 `CANCELLED`이면 공개 완료로 안내하거나 원고를 다시 잠그지 않는다. 서버 원고의 lifecycle을 재조회하고 로컬 본문과 기준 revision은 보존한다. 다른 기기에서 revision까지 바뀌었다면 원격 사본을 보관하고 명시적 충돌 해결로 연결한다. 충돌 중 추가 입력도 기기에 저장한다. 예약 취소가 확정된 후 기기 상태/목록 갱신이 실패해도 취소 확정 안내를 유지한다.

게시 요청 이후 수정은 보관 원고와 `after-publish-edits` 기기 사본에 남긴다. 백업 실패 때도 최신 head 저장을 시도하고 실패 안내·다운로드를 유지한다. **보관 사본을 새 원고로 복사**는 명시적 선택으로 새 UUID·revision 0·pending 없음의 ACTIVE 원고를 만든다. 원본을 삭제하거나 다시 편집 가능으로 바꾸지 않는다.

## 검증·실환경 인수

fake clock + 실제 DraftEngine/VM에서 연속 입력·idle·IME·느린 요청·응답 유실·충돌·전환·미리보기 경쟁·보관 복사를 검사한다. 체크리스트·사전·선택 상한·재확인·확정 후 장애·runtime allowlist와 기존 인증·작품·파일·게시·DB 합성 회귀를 검사한다.

이는 실제 IndexedDB quota·강제 종료·모바일 IME·여러 기기·Supabase/RLS/Storage·Cloudflare Cron·배포의 증거가 아니다. 14단계 백업/공개 전환 및 기존 5~7단계 실환경 조건을 확인한다. 명시 요청에 따라 작가 A 등록→게시→독자 B 열람→다음 원고→기기 재접속, 타 작가·일반 관리자 접근 거절과 장애 인수를 수행한다. 로컬 검증만으로 서비스 GO를 기록하지 않는다.

롤백은 검토된 이전 클라이언트 배포와 기존 기능 플래그 중지를 사용하며 원고·사본·receipt·공개본을 보존한다. 관리자 CRUD나 이전 무조건 upsert로 저장을 우회하지 않는다.
