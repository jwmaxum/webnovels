# 작품 CMS 홈 노출 설정 — 2026-09-26

## 사용 방법

관리자 로그인 → 작품 CMS → 작품별 **홈 노출 설정**에서 추천·인기·신작을 선택 → **저장**.

- 추천: 홈 추천 배너의 선정 대상.
- 인기: 홈 인기 작품의 선정 대상(표시 수 최대 4개).
- 신작: 홈 신작의 선정 대상(최근 등록 순, 표시 수 최대 4개).
- 모두 해제하면 위 세 섹션의 선정 대상에서 제외한다. 작품의 공개 상태나 장르별 목록·검색·완결·무료 등 다른 섹션의 조건은 변경하지 않는다.
- **되돌리기**는 저장 전 선택을 마지막 저장 상태로 돌린다. 저장 후 다시 변경하려면 체크를 바꾸어 저장한다.
- 변경 사유는 선택 입력이며 비우면 기본 작업 사유를 감사 기록에 남긴다.
- 다른 관리자가 먼저 바꾼 행은 덮어쓰지 않고 충돌을 표시한다. 새로고침 후 최신 상태를 확인한다.

작품 공개 조건을 만족하는 작품만 실제 홈에 표시한다. 큐레이션 설정은 본문·회차·소유자·성인 등급·유료 권리를 변경하지 않는다. 기존 콘텐츠 서비스의 공개 전환 상태도 별도다.

## 구현

- `POST /api/v2/admin/console?action=curation-update`.
- 서버 Auth 검증 후 최고 관리자 또는 `CURATION_WRITE` 권한만 허용한다. 단순 작품 조회 권한은 수정 권한이 아니다.
- workId·revision과 추천/인기/신작 boolean 3개만 받는다. 출처·본문 크기·필드·변경 사유를 검증하고 DB에서도 권한을 재검사한다.
- `database/launch/006_work_curation.sql`: 기존 조회 RPC에 편집을 추가하며, 별도 버전/감사 테이블과 업데이트 트리거로 이전 경로의 수정까지 감지한다. 작품 행 잠금과 버전 비교로 동시 변경을 거절한다.
- 같은 설정 저장은 성공하되 데이터/버전을 변경하지 않는다. 실제 변경 시에만 이전/이후 값과 담당자·사유를 기록한다. 감사 기록은 수정·삭제할 수 없다.
- 저장 성공한 행만 최신 값으로 갱신하므로 다른 작품의 미저장 선택을 지우지 않는다. 저장 실패를 성공으로 표시하지 않는다.
- 기존 공개 목록에 이미 있는 작품의 표시 캐시만 갱신한다. 비공개 CMS 작품을 독자 목록에 추가하지 않는다.
- 인기·신작 지정 작품이 없을 때 임의 작품으로 채우던 자동 대체를 제거했다.

## 검증·운영 적용

- 적용 전 비공개 백업: `scratch/launch/backups/2026-09-26T05-35-27-916Z/`, 83개 테이블.
- `node scripts/prepare_admin_console.mjs <백업 디렉터리> --curation`: 실제 백업을 격리 PGlite에 복원하여 저장·충돌 거절·롤백·public 행 보존을 검증한다. `--apply` 추가 시 검증 후 운영 SQL을 적용한다.
- `scripts/verify_admin_console.test.mjs`: 권한/필드/Origin/버전, 원고 보존, 감사 불변성, 이전 경로 변경 감지, 저장·되돌리기·실패·충돌 UI, 홈 플래그 반영 검증.
- 브라우저/localhost 인수는 실행하지 않는다. 로컬 격리 DB·UI VM과 실제 운영 HTTP/DB 검증을 구분한다.
- 실행 결과: `artifacts/admin-curation-rollout.json`. 배포 및 실제 HTTP 확인은 후속 운영 기록에 남긴다.

운영 SQL 적용 후 실제 DB 트랜잭션에서 설정 변경·영속 값·감사 기록과 이전 버전의 409 충돌을 확인하고 롤백했다. 적용 전 백업과 public 42개 테이블의 전체 행을 대조해 원본이 보존되었음을 확인했다. 영구적인 홈 노출 설정 변경은 운영자가 저장할 때 이루어진다.
