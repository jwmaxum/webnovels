PC 상세는 표지·정보를 나란히 배치하고 모바일은 작은 표지 옆에 제목·상태를 표시한다. 소개와 읽기 행동은 그 아래에 둔다.
기본 소설 본문은 컨테이너 760px 안에서 여백을 두며, 독자가 설정한 좌우 여백에 따라 실제 폭이 달라진다.
웹툰은 최대 800px과 화면 폭 안에서 비율을 유지하고 본문 컷을 표지처럼 잘라내지 않는다.

## 수정한 동작 문제

1. 기존 고정 뷰어는 자체 스크롤을 사용했으나 읽기 위치 측정·복원은 `window`를 기준으로 했다. 뷰어를 문서 흐름에 연결해 스크롤 기준을 통일했다.
   [MDN overflow](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overflow)의 별도 스크롤 컨테이너 동작을 참고했으며 실제 기기 인수는 아래 한계에 구분한다.
2. 관심 작품만 20개 이상이면 더 보기 버튼이 이어읽기 탭에만 나타났다. 각 목록에서 추가 항목을 불러올 수 있게 했다.
3. 구독 작가 수의 DOM ID가 맞지 않던 부분을 실제 `statAuthorCount`와 기존 호환 ID에 함께 연결했다.
4. 한 작품의 일시적인 조회 실패가 서재 전체를 지우던 처리를 목록별로 분리했다. 조회 실패를 빈 목록으로 간주하지 않는다.
5. 이전 `/library/creators` 같은 URL을 복원할 때 탭 클릭이 새 방문 기록을 만들던 문제를 막고, 화면을 떠난 뒤 늦은 탭 선택도 차단했다.
6. 처음 회차를 열 때 본문 요청이 실패하면 재시도 버튼이 숨겨진 뷰어 안에 남던 부분을 고쳤다. 새 회차 로딩 중 이전 제목·추천·읽기 행동이 남지 않게 했다.
7. 짧은 웹툰 컷에서 오류 문구와 재시도 버튼이 겹치지 않도록 오류는 접근성 알림으로 전달하고 재시도 버튼을 표시한다. 긴 컷의 로딩·재시도 위치는 초기 화면 안에 들어오도록 상한을 뒀다.

## 보존 계약

- 공개 Catalog·회차 본문·서재 API와 인증·소유권·기능 플래그·실제 DB 자료를 유지한다. 새 패키지·외부 실행 스크립트·마이그레이션은 추가하지 않는다.
- 회차 번호가 2→5→9처럼 떨어져 있어도 서버가 반환한 실제 이전·다음 회차를 사용한다. 비공개·삭제 회차를 추정하지 않는다.
- Word 문단·강조·기울임·정렬을 처리하는 `ReaderContent`와 `ManuscriptDocument`는 변경하지 않았다.
- `ReaderSession`·`ReaderPosition`, 계정·공개 버전별 위치 저장, `ReaderPreferencesStore`의 서체·크기·행간·여백·문단 간격·4개 테마 구현은 그대로 유지한다.
- 웹툰의 최대 동시 요청 3개·상주 이미지 5개, WebP 디코딩 실패 시 PNG 대체, 이미지별 명시적 재시도·이탈 시 취소/Blob 해제를 유지한다.
- 작품명·회차명·구독 작가명·추천 정보는 DOM/textContent로 표시한다. 추천에 근거 없는 ‘함께 많이 본’·가짜 조회수를 붙이지 않는다.
- 기본 프로필의 가짜 이름·이메일을 중립적인 로딩 표시로 바꾸고, 실제 값이 없는 이메일을 임의 생성해 표시하지 않는다.
- 작가·관리자 화면과 R3 홈·탐색 DOM, `/creator`·Author/Creator 호환·원고·최초 발행·공개 후 변경 검토 계약을 유지한다.

## 검증

`search-first`로 기존 렌더러·API·라우터·세션·테스트를 조사했다. Codebase Memory 연결 종료로 소스 읽기·검색을 사용했다.
기존 DOM API와 설치된 parse5/esbuild/Node 테스트를 재사용했고 신규 의존성이 없어 npm/PyPI 패키지 검색·설치는 수행하지 않았다.
`security-review`와 `verification-loop`를 변경 범위에 맞춰 적용했다.

| 검증 | 결과 |
| --- | --- |
| UI-R4 신규 테스트 | 30개: 상세 6·서재 8·웹툰 7·읽기/화면/설정/라우팅 9 |
| 기존 관련 회귀 | 탐색·읽기·회차 간격·계정 전환·이미지·Word·인증·명칭·R2/R3 검증 |
| 전체 릴리스·빌드 | 전 42개 릴리스 명령·Prisma 생성·TypeScript 빌드 통과. [검증 기록](../../artifacts/ui-r4-verification-2026-10-31.json) |
| 보안·변경 비교 | 보존 대상 DOM·세션/위치/설정·서버/원고 구현·비밀 패턴·기존 사용자 작업 확인 |

`test:ui-r4`를 전체 릴리스에 연결했다. 독립 lint 명령이 없어 JS 구문·CSS 파싱·diff 검사를 사용하며 커버리지 비율은 측정하지 않았다.
첫 전체 실행은 기존 13단계 보호 콘텐츠 테스트에서 로딩 화면 진입이 비활성 유료·성인 거절보다 앞서는 문제로 중단됐다. 화면 진입 순서를 수정하고 기존 테스트를 그대로 통과시켰다.
수정 후 관련 28개 테스트를 재검증하고, 13단계부터 남은 릴리스와 빌드를 이어 실행했다. 앞서 통과한 단계와 재실행 결과를 합쳤으며 실패 테스트를 생략하지 않았다.
정적 검사·VM·합성 DB 테스트와 실제 운영 DB/브라우저 인수를 구분한다. 운영 DB·계정·작품·원고·비밀·Cloudflare 설정은 변경하지 않았다.
저장소 규칙에 따라 브라우저·localhost를 실행하지 않았다. 문서 스크롤의 실제 위치 복원, 좁은 컷의 재시도 조작, 모바일 키보드·확대·스크린리더는 명시 요청 후 실제 기기에서 확인할 항목이다.
push 이후 CI·자동 배포·공개 정적 파일의 결과는 별도로 보고한다.

## 다음 단계 — UI-R5 작가 작품·원고·웹툰 업로드

1. 내 작품에서 원고 작성·불러오기 → 저장 → 미리보기 → 지금/예약 발행으로 이어지는 핵심 행동을 단순화한다.
2. 표지·소개 변경은 작품 설정에 모으고 신규/예약/공개본의 상태에 따라 실제 가능한 행동만 표시한다.
3. 신규 발행은 작가가 직접 수행하며, 공개본 수정·삭제와 공개된 표지 변경은 기존 관리자 검토 절차를 유지한다.
4. Word 붙여넣기·자동 저장·revision·기기 사본·복구를 유지하면서 모바일 편집 면과 저장/실패/충돌 표시를 정리한다.
5. 웹툰 선택 순서·번호·썸네일·파일별 진행·위/아래 이동·실패한 파일 재시도·화면 폭 미리보기를 통일한다.
6. 작가/독자/관리자 권한·예약 시각·소설/웹툰 동시 등록·파일/원고 보존 회귀를 통과한 뒤 독립 커밋·push한다.

[37단계 운영 인수](../../improve37.md)의 SMTP·복원·PASS/결제 계약과 외부 베타 인수는 별도로 관리한다.
