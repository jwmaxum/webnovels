# OP-02 작가·독자 관리

작성일: 2026-11-01 (Asia/Seoul)

[관리자 CMS 계획](admin-cms-minimal-ux-plan-2026-11-01.md) OP-02를 구현한다. 사용자의 추가 요청에 따라 **작가 탭과 독자 탭의 목록·검색·필터·페이지·상세를 각각 분리**한다. 서로의 회원 목록을 합치거나 필명·실명·이메일을 근거로 계정을 병합하지 않는다.

## 화면

| 구분 | 목록과 검색 | 상세 관리 |
| --- | --- | --- |
| 작가 | 필명·작가 ID, 허용된 정확 이메일 검색, 상태·연결·가입 기간·최근 활동·작품 유무·정산 준비·조회 가능한 미처리 요청 | 기본 정보, 관련 작품·회차 수·최근 발행, 정산 준비 상태, 요청·공개 정보 변경 이력 |
| 독자 | 닉네임·독자 ID, 허용된 정확 이메일 검색, 상태·연결·가입 기간·최근 활동·조회 가능한 미처리 요청 | 계정 정보, 결제·포인트의 집계 상태, 열람권 연결 상태, 요청·공개 정보 변경 이력 |

서버에서 검색·필터링하고 50건 단위로 페이지를 넘긴다. 각 탭의 검색어·필터·페이지 위치는 로그인 계정의 메모리에 별도로 유지한다. 로그아웃·계정 전환에는 폐기한다. 검색어·이메일은 URL이나 localStorage에 기록하지 않는다. 상세는 `/admin/members?kind=author|reader&accountId=프로필ID`로 연결한다. 대문자 UUID는 정규화하고, 기존 정수 독자 ID도 보존한다. Auth UUID는 프로필 ID로 대체하지 않는다.

표·폼에는 기본 HTML 레이블과 제목, 키보드 포커스, 최소 조작 크기와 밝은 테마를 적용한다. 데이터 미연결·권한 없음·0건·조회 실패를 구분한다. 확장 회원 RPC가 아직 설치되지 않았거나 일시적으로 사용할 수 없으면 동일 종류의 기존 회원 조회로 연결한다. 접근 거부나 입력 오류를 이 전환의 근거로 사용하지 않는다. 상세의 ‘계정 지원 도구’는 기존 종류별 회원 목록과 연결·복구 상태, 설정된 Workflow의 권한별 계정 조치를 열고, 검색 조건을 보존한 복귀 링크를 제공한다. 새 화면이 기존 지원·정지/해제 도구의 진입점을 없애지 않도록 한다.

## 데이터와 권한

- `/api/v2/admin/members?action=list|detail|update-profile`은 계정 서비스가 확인한 사용자와 최신 관리자 매핑을 이용한다. 검색을 포함해 같은 출처의 JSON POST만 받는다. 목록 검색에 P0·Workflow·유료 결제 플래그를 켜지 않는다.
- 읽기는 `ACCOUNTS_READ` 또는 작가 `CREATOR_MGMT` / 독자 `USER_MGMT` 범위다. 공개 정보 변경은 최고 관리자만 수행한다. 읽기·계정 정지 권한을 프로필 수정 권한으로 확대하지 않는다.
- 변경 가능한 값은 작가 필명·공개 소개, 독자 닉네임뿐이다. Auth 연결, 이메일, 계정 상태, 비밀번호, 실명, 신분증, 계좌, 잔액을 이 화면에서 변경하지 않는다.
- 변경 사유·예상 revision·요청 UUID를 필수로 받는다. 공개 프로필의 실제 변경 때 증가하는 비공개 revision과 현재 상태/연결 지문을 비교한다. 본인의 기존 프로필 편집, 변경 후 원복, 프로필 ID 재사용도 감지한다.
- 동일 요청은 같은 결과를 반환하고, 같은 요청 ID에 다른 내용을 보내면 거부한다. 오류로 결과가 불명확할 때 화면은 같은 내용·요청 ID를 유지한다. 충돌 시 작성 내용을 보존하고 최신 정보를 명시적으로 다시 읽는다. 감사에는 허용된 공개 필드와 사유만 남긴다.
- 문의 자료는 `CASE_READ`, 공개본 변경 요청은 `CONTENT_REVIEW`로 구분한다. 운영 현황 권한만으로 개별 요청이나 그 집계를 읽지 못한다. 정산 상태는 해당 정산 읽기 권한, 변경 이력은 감사 읽기 권한을 확인한다.
- 새 비공개 revision·receipt 테이블은 RLS와 명시적 직접 접근 금지를 적용한다. 고정 `search_path`의 `admin_member_directory` RPC만 `service_role`에 실행을 허용한다. 브라우저·서비스 역할의 private 테이블/helper 직접 접근을 열지 않는다.

## 현재 자료의 의미

현재 `commerce.orders`는 TEST 자료다. TEST PAID와 기존 포인트 숫자를 실제 유료 독자·순결제·유상/보너스 잔액으로 표시하지 않는다. 결제·잔액·주문 검색은 미연결 상태를 안내하고 실제 금융 원장 연결 전에는 필터를 제공하지 않는다. 무료 열람권의 현재 계약과 이미 가진 권리를 변경하지 않는다.

정산 준비는 계좌 등록 여부와 서류의 수동 검토 상태만 표시한다. 서류 승인은 PASS·은행 예금주 확인·지급 완료를 뜻하지 않는다. 신분증 원문·계좌 소유자/번호·암호화 envelope는 회원 DTO에 포함하지 않는다. 국외 보관 고지와 R13의 개인정보 접수 보류는 유지한다.

활동은 연결된 인증 계정의 최근 로그인, 작가 최근 발행, 독자 최근 읽기의 확인 가능한 최종 시각이다. 소스가 없으면 미집계다. 가입 기간은 한국 시간의 날짜로 판정한다. 작가의 연재·휴재·완결은 개별 작품 상태이며 작가 계정 상태와 합치지 않는다.

## 적용·검증 기록

`build:compile`, 독립 타입 검사, 신규 OP-02와 기존 OP-01·인증·명칭·P0·운영 준비·17/35/36단계·관리자 운영·UI-R5/R6/R7/R13·Cloudflare 번들 등 **17개 검증 명령이 통과**했다. 기존 계정 도구의 진입·복귀 연결을 추가한 뒤 빌드·OP-02/OP-01·인증·운영 준비·UI-R5/R6/R7 **8개 명령을 다시 검증**했다. 최종 OP-02 신규 테스트 **62개**, OP-01 회귀 **35개**가 통과했다. 별도 백업 회귀 **4개**와 오프라인 원본·카탈로그 가드 합성 검사도 통과했다. 결과는 [검증 기록](../../artifacts/op02-verification-2026-11-01.json)에 남긴다. lint 명령은 없고 VM 소스의 수치 커버리지는 측정하지 않는다.

사용자가 이 PC의 `scratch/launch/backups/` 아래 로컬 복구 백업 생성을 명시적으로 승인한 뒤 새 논리·네이티브 백업을 생성했다. 원본 168개 테이블의 자료와 카탈로그·권한을 재구성해 보존·재실행·역할별 허용/거절과 drift 차단을 검증했다. 백업 생성기의 bigint 시퀀스 메타데이터는 SQL에서 문자열로 보존하도록 수정해 JavaScript JSON 반올림을 막는다. 새 검사에서도 실제 원본 비교 조건을 완화하지 않았다.

**2026-11-01 16:24 KST**, 검증한 [017 마이그레이션](../../database/launch/017_admin_members.sql)을 단일 보호 트랜잭션으로 실제 DB에 적용했다. 비공개 테이블 2개·함수 3개·공개 필드 변경 감지 트리거 2개와 마이그레이션 표식만 추가했다. 기존 회원·인증 연결·작품·원고·정산 자료와 ACL·기존 함수·제약 조건은 보존했고, 기능 플래그를 변경하지 않았다.

운영 Supabase REST에서 기존 활성 최고 관리자 매핑으로 작가 목록·상세를 읽어 확인했다. 독자 목록은 현재 0건으로 확인했으며, 운영 독자 상세·수정 자료를 만들지 않았다. 익명 REST RPC 거절, 일반 회원 실행 권한 없음, 서비스 전용 실행 권한, 비공개 테이블 직접 읽기 거절과 트리거 활성 상태를 확인했다. 운영 프로필을 수정하거나 신분증·은행·결제 자료를 생성하지 않았다. 실제 관리자 로그인·브라우저·휴대폰 인수는 실행하지 않았으며, 독자 상세·수정과 충돌·재시도는 합성 DB/VM 검증이다. push 이후 최종 CI와 자산 배포 상태는 별도로 확인한다.

다음 단계는 **OP-03 관리자 직접 선정 추천·전시 CMS**다. 관리자가 실제 작품을 검색해 선정하고, 순서·게시 기간·홈/추천 노출·미리보기를 같은 관리 원천에서 운영하도록 연결한다. 실제 결제·포인트는 OP-04/05, 작가 정산 지급은 OP-07의 별도 원장·세무·개인정보 인수 조건을 따른다.
