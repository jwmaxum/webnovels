# 13단계 수익화·성인 기능 출시 계약

상태: **미활성 / 별도 출시 대기** (2026-09-25). 현재 첫 공개 오픈의 기준 범위는 무료 웹소설 작성·연재다. 이 문서는 기존 권리·거래를 삭제하거나 무료로 바꾸는 승인서가 아니다.

## 현재 코드 경계

2026-09-26 후속: [최소 작가 대시보드](author-dashboard-rollout.md)에서 본인 이전 수익 기록 조회와 프로필·정산 계좌 등록을 추가했다. 이전 금액은 검증 대기로 표시하며 실제 예상수익은 집계 전이다. 아래 거래·지급 비활성 계약은 유지한다.

- `/api/v2/(payments|ads|adult-verification|points|support|settlements)`는 `PROVIDER_AND_LEDGER_NOT_READY`로 거절한다. `server/providers/toss.mjs`와 `portone-identity.mjs`는 제공업체 응답 검증의 일부이며 주문·인증 시도·원장 완료 경로가 아니다.
- 브라우저의 광고 이벤트 작성, 광고 해금, 후원, 정산 신청 함수는 비활성 결과로 종료한다. 작가 수익 조회는 검증된 본인 소유의 이전 기록만 제공하고 실제 지급액을 추정하지 않는다. 독자 카탈로그 화면은 성인 작품과 무료로 확인되지 않은 회차를 제외한다. 이 화면 필터는 서버 권한의 대체가 아니다.
- 구형 페이지의 광고/결제/성인 모달과 관리자 설정 화면은 코드에 남아 있다. 버튼 비표시와 서버 503만으로 실제 Supabase 공개 권한을 제한했다고 판단하지 않는다. [10단계 전환 감사](stage10-cutover-audit.md)의 실 DB 감사가 우선이다.
- 기존 유료 권한, 정산 신청, 수익 기록, 계약, 성인 작품은 보존하고 실 데이터 출처와 소유자를 확인하기 전 집계·마이그레이션·지급·무료 전환하지 않는다.

## 거래와 원장 선행 결정

운영·재무 담당자가 화폐와 포인트의 단위, 환산/소멸, 광고 매출 인식, 수수료·작가 배분·반올림, 확정/마감 주기, 최소 출금액·세금·지급일, 취소/환불·차지백·미확정 처리와 보관기간을 서명된 버전으로 확정한다. UI에 남은 `62.5%`, `100P` 등의 수치는 정책 근거가 아니다.

1. 실제 `revenue_events`, `author_earnings`, `earning_ledger`, `author_settlements`, `creator_supports`, 해금·포인트 테이블의 DDL/RLS와 데이터를 읽기 전용으로 감사한다. Auth UUID, `author_id`, 외부 거래 ID를 대조하고 운영/시험 기록을 구분한다.
2. 단일 불변 거래 원장을 정의한다. 외부 제공업체 ID와 거래 종류별 고유 제약, 상태 전이, 원거래를 참조하는 상쇄 분개, 금액·통화 일치, 잔액 불변식을 DB 트랜잭션 안에서 강제한다. 기존 기록은 삭제나 임의 합산 없이 대조표를 남긴다.
3. 광고 완료는 서버 검증 콜백 또는 제공업체 재조회와 재전송 방지 후 원장 및 회차 해금을 원자적으로 기록한다. 브라우저 타이머·성공 플래그는 근거가 아니다.
4. 결제는 서버가 예약한 주문과 Auth 사용자, 금액, 통화, 상점·환경을 확인한다. 확인 응답만으로 곧바로 확정하지 않고 미확정 상태, 재조회, 중복 확인, 취소·환불·차지백 및 원장 역분개를 다룬다. 토스 API의 확인/조회/취소와 멱등키 요구는 [공식 API](https://docs.tosspayments.com/reference) 및 [인증·멱등성 문서](https://docs.tosspayments.com/reference/using-api/authorization)와 운영 계약을 대조한다.
5. 본인확인은 서버가 생성·소유·만료 관리하는 인증 시도를 제공업체에 재조회한다. [PortOne V2 본인인증 조회 API](https://developers.portone.io/api/rest-v2/identityVerification)의 검증 결과에서 필요한 최소 속성만 저장하고, 나이 판정 시점·재확인·탈퇴 시 삭제 정책을 확정한다.
6. 작가 출금은 확정 잔액에서 예약액을 원자적으로 차감하고, 계좌 변경 확인·관리자 분리 승인·실제 송금 결과와 대조한다. 지급 확인 전 `PAID` 금지, 중복 지급 방지, 실패/보류/취소와 감사 기록이 필수다.

## 출시 순서와 증거

- 무료 오픈: 유료·성인·광고·후원·포인트·출금은 계속 비활성. 실제 DB 정책으로 직접 테이블·RPC·Storage 접근을 막고, 목록·검색·미리보기·본문·직접 URL에서 범위 밖 작품 노출을 시험한다. 기존 권리 처리 방침을 고객 지원과 함께 확정한다.
- 개별 유료 출시: 실제 업체의 테스트/운영 환경 분리, 서명/재조회·재전송·동시 요청·중복 마감·초과 출금·환불·장애 복구 시험, 원장 대조, 작가 A/B 격리, 운영 지급 리허설, 약관/문의/화면 일치를 각각 기록한다. 기능별 플래그와 중단 절차를 마련한 뒤 별도 출시 판정한다.
- 웹툰·AI·커머스 등은 [13단계 계획](../../improve13.md)의 후속 목록이며 위 기능의 출시로 자동 포함되지 않는다.

운영 DDL이나 실제 거래는 실행하지 않았다. 현재 Supabase 관리 스키마 요청이 HTTP 401이므로 원장의 실제 상태와 기존 RLS를 검증할 수 없다.
