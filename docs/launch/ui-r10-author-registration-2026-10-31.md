# UI-R10 — 작가 작품 등록·발행 흐름 개선

2026-10-31. 구현·영향 범위 검증 완료. 작가가 적은 입력과 명확한 다음 행동으로 연재를 시작하도록 기존 스튜디오를 개선했다.

## 검토 결과와 반영

| 기존 불편 | 개선 |
| --- | --- |
| 작품 생성 뒤 설정 저장에서 다음 행동이 끊김 | `작품 등록 → 작품 정보 → 원고 작성·발행` 안내와 미발행 작품의 **저장하고 원고 작성** 버튼 제공 |
| 발행 필수 정보와 많은 선택 입력이 함께 노출됨 | 소개·장르·이용등급·AI 표기를 먼저 배치하고 태그는 선택 펼침으로 분리. 일부만 입력한 상태도 기존 설정 저장으로 보관 가능 |
| 설정을 편집하다 다른 메뉴로 이동하면 입력을 잃기 쉬움 | 설정 입력의 현재 값과 기준 값을 비교하여 이동 전 확인. 장르 버튼으로 바뀐 값도 감지. 저장 중에는 설정 입력을 잠금 |
| 발행 화면에서 부족한 작품 정보를 고치러 갈 경로가 없음 | **작품 정보 보완 (원고 저장 후 이동)** 버튼 추가. 서버 원고 저장과 동일 계정·작품·원고·편집 순서를 확인한 뒤 설정으로 이동 |
| 발행 요약에 `ALL`, `GENERATED`와 기술 정보가 우선 노출됨 | 이용등급·AI 표기를 한국어로 표시. 저장 버전은 기존 준비 체크리스트에서 확인 |
| ‘크레딧’의 역할이 모호하고 빈 항목도 공개됨 | **참여 작가 (선택)** 아래 글 작가·그림 작가·원작 작가로 설명. 같은 사람의 겸임·원작 없는 경우를 안내하고 입력한 항목만 표시 |
| 이미지 일부 실패·건너뜀 뒤 마지막 성공 메시지가 앞선 문제를 가림 | 완료·실패·건너뜀·처리 대기·취소를 묶어 안내하고 파일별 원인과 재시도 흐름 유지 |

필수 정보와 선택 단계를 구분하는 방향은 [WAI 단계별 폼 안내](https://www.w3.org/WAI/tutorials/forms/multi-page/), 명확한 설명과 오류 복구 행동은 [WAI 입력 안내](https://www.w3.org/WAI/tutorials/forms/instructions/)와 [오류 알림 안내](https://www.w3.org/WAI/tutorials/forms/notifications/)를 참고했다. 기존 `CreatorReadiness`, 네이티브 폼·submitter·`details`를 확장했으며 새 UI 프레임워크나 의존성을 도입하지 않았다. 패키지 도입이 필요하지 않아 npm/PyPI·GitHub 패키지 검색은 생략했다.

## 유지하는 서비스 계약

- 작품 생성은 기존 제목·작품 유형 API를 사용한다. 같은 작가가 웹소설과 웹툰을 각각 등록할 수 있다.
- 새 회차는 작가가 즉시·예약 발행한다. 공개본 수정·삭제는 관리자 승인 후 반영한다.
- 저장 실패·충돌·새 편집·계정 또는 원고 변경 때는 저장 후 이동을 완료한 것으로 표시하지 않는다. 공개 후 검토 접수 응답도 직접 원고 작성 성공으로 처리하지 않는다.
- AI 사용·이용등급은 작가가 직접 선택한다. 참여 작가 표시는 신원·권리 인증의 근거가 아니며 기존 `writer/artist/original` 키와 입력값을 보존한다.
- `/creator`, Author 신원, 정확한 작품 bigint ID, 원고 revision·멱등 재시도 계약을 유지한다. 운영 데이터 변경이나 DB 마이그레이션은 없다.

## 검증 범위

검증 결과는 `artifacts/ui-r10-verification-2026-10-31.json`에 기록한다. 코드·구문·타입·빌드와 VM 기반 상호작용 및 기존 작가·독자 회귀 검사를 실행한다. 실제 종료 코드로 결과를 판단하며 별도 lint 명령과 전체 커버리지는 구성되지 않았다.

신규 테스트는 작품 등록·설정 14개, 참여 작가·이미지 업로드 9개, 발행 정보 보완·요약 12개로 **35개**다. 로컬 빌드·타입을 포함한 영향 범위 15개 명령이 통과했다. 마지막 권한 방어 보강 이후 신규 35개와 기존 작품 UI 17개도 추가로 실행해 **52/52** 통과했다. 독립 보안 검토에서 차단할 문제는 발견하지 못했다.

이번 요청은 작가 등록 UI/UX 개발을 중심으로 수행했다. 프로젝트의 브라우저 검사 제한에 따라 실제 브라우저·localhost·실기기 검사를 새로 실행하지 않았다. 이전 R9의 휴대폰·PC 붙여넣기 사용자 확인을 이번 신규 화면 인수 결과로 확대하지 않는다. 200% 확대·음성 스크린리더·Word 개별 서식 저장/복원·반복 LCP/CLS는 미확인이다. 스타일의 반응형 규칙과 접근성 속성 검사는 실기기 인수를 대신하지 않는다.

Graph 조회는 연결 종료 또는 사용 가능한 인덱스 없음으로 소스 fallback을 사용했다. 운영 DB·계정·기존 원고를 시험 변경하지 않았으며 `.env.local`·토큰·실제 데이터 백업은 커밋하지 않는다.

## Git·배포

단계 검증을 마친 뒤 변경 파일만 커밋하고 `main`에 일반 push한다. 최종 커밋·GitHub CI·Cloudflare 배포와 공개 자산 비교 결과는 완료 보고에 기록한다. Vercel은 사용하지 않는다.
