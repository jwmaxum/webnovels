# OP-03 관리자 직접 선정 추천·전시 CMS

작성일: 2026-11-01 (Asia/Seoul) · 상태: **코드·운영 DB 적용 및 서비스 RPC 검증 완료 / 브라우저 화면 인수 미실행**

[관리자 최소 메뉴 계획](admin-cms-minimal-ux-plan-2026-11-01.md)의 OP-03을 구현한다. 관리자가 작품을 직접 검색·선정하고, 같은 전시 문서에서 추천 목록·홈·메뉴·공지를 관리한다. 웹소설과 웹툰을 함께 지원하며, 추천 선정에 조회수·매출·개인화 기반 자동 편입을 사용하지 않는다.

## 관리자의 작업 흐름

`콘텐츠·전시 → 추천·홈 구성`에서 제목·필명·작품 ID로 검색한다. 공개 가능한 작품을 선택한 뒤 목록 순서, 홈 노출 위치, 노출 기간, 안내 문구를 정한다. 검색은 유형별 필터와 50건 페이지를 제공한다.

| 관리 항목 | 구현 범위 |
| --- | --- |
| 추천 선정 | 최대 200개 작품, 작품 중복 금지, 관리자가 저장한 순서 유지 |
| 홈 위치 | 대표 추천은 같은 시각에 1개, 사용 설정된 기획 추천은 최대 8개 |
| 기간 | 한국 시간으로 입력·안내하고 서버에는 UTC 전달. 시작 포함·종료 제외 |
| 홈 블록 | 대표 추천·추천 목록·최신 연재·인기 랭킹·공지의 제목·표시 여부·순서 |
| 공개 메뉴 | 홈·웹소설·웹툰·추천·랭킹 5개 경로의 표시명·순서·표시 여부. 홈은 유지 |
| 공지 | 최대 10개, 제목·일반 본문·허용된 내부 링크·기간·표시 여부 |
| 푸터 | 회사정보·정책·고객지원의 필수 링크 유지, 추가 안내는 일반 텍스트 최대 300자 |

주요 동선은 **초안 저장 → 저장본 미리보기 → 지금 발행 또는 예약 발행**이다. 미저장 변경은 미리보기·발행의 기준으로 사용하지 않는다. 미리보기는 저장한 revision과 확인 시각을 기준으로 서버가 생성하며, 독자 공개 응답과 같은 전시 판정기를 사용한다. 실제 브라우저에서 두 화면의 시각적 일치를 인수한 상태는 아니다.

발행 이력에서 활성 게시를 중단하거나 미래 예약을 취소할 수 있다. 이전 발행본의 복구는 **초안으로 복원**하며, 복원 자체가 재게시를 뜻하지 않는다. 다시 저장본을 확인하고 발행해야 한다. 최신 게시가 중단·만료됐을 때 이전 게시를 조용히 되살리지 않는다. 변경 사유와 담당자·시각·revision을 기록한다.

## 독자 화면

`/recommendations`에 전체·웹소설·웹툰 필터와 24개 단위 페이지를 제공한다. 순서와 선정 대상은 관리자가 발행한 문서에 따른다. 홈의 대표·기획 추천도 같은 선정 ID를 사용하며, 추천 페이지를 홈 8개 위치 제한에 묶지 않는다.

선정했더라도 미발행·비공개·공개 제한·기간 종료 등 현재 공개 조건을 만족하지 못하는 작품은 서버가 제외한다. 관리자 미리보기에는 제외 이유를 전달하고 일반 독자 DTO에는 내부 제외 자료를 넣지 않는다. 작품명·필명·표지 등 공개 카드 정보는 현재 작품 상태에서 읽는다.

선정 목록이 비었거나 모두 제외되면 추천의 빈 상태를 표시한다. 다른 인기작이나 구형 추천 플래그로 자동 대체하지 않는다. **최신 연재·인기 랭킹은 추천과 별도 목록**으로 유지한다. 연결 미준비·조회 실패·선정 없음도 구분한다. 이 단계는 회차 무료 범위·가격·본문 권리·결제·광고를 바꾸지 않는다.

## 권한·동시 편집·보존

- 최고 관리자 또는 `CURATION_WRITE` 권한을 서버에서 확인한다. 브라우저 버튼 숨김만으로 권한을 판정하지 않는다.
- 관리자 API는 인증된 동일 출처 JSON POST를 사용한다. API와 DB에서 문서 구조·길이·작품 ID·UTC 시각·허용된 링크를 검사한다. 임의 HTML·스크립트·외부 CSS를 저장하는 페이지 빌더가 아니다.
- 전역 revision으로 동시 편집을 비교한다. 충돌 시 작성 내용을 보존하고 최신 상태를 명시적으로 불러온다. 응답이 유실됐을 때 같은 내용과 요청 ID로 재시도하며, 같은 키의 다른 내용은 거부한다.
- 저장·발행·중단·복원은 사유와 요청 ID를 기록한다. 발행본·중단 기록·요청 영수증·감사는 수정·삭제를 막는 별도 기록으로 보존한다.
- [018 마이그레이션](../../database/launch/018_site_display.sql)은 비공개 테이블 5개, 함수 9개, 트리거 6개를 추가하도록 준비했다. 기존 추천 배치 테이블이 없는 호환 환경에서는 해당 테이블의 트리거 1개를 생략한다. 새 시퀀스는 없다.
- 새 테이블은 RLS와 명시적 직접 접근 금지를 적용한다. 공개·관리자 투영 RPC만 서비스 역할 실행을 허용하고, 브라우저 역할과 서비스 역할의 비공개 테이블·보조 함수 직접 접근은 열지 않는다.
- 기존 추천 플래그·배치 자료는 **이관 검토용 읽기 목록**으로 보존한다. 자동으로 새 선정 목록에 복사하지 않는다. 018 적용 시 두 구형 쓰기 원천을 차단하여 이중 편집을 방지한다. 기존 함수·회원·작품·원고·공개본·계정 연결·정산 자료는 교체하지 않는다.

주요 구현은 [관리자 화면](../../public/js/admin/admin-display.js), [독자 화면](../../public/js/reader/reader-display.js), [API](../../server/site-display-api.mjs), [준비 상태 판정](../../server/site-display-readiness.mjs), [018 SQL](../../database/launch/018_site_display.sql)에 있다. 기존 `/creator` 및 Author/Creator 식별·권한 계약은 유지한다.

초기 자동 승인 검토에서 운영 스키마 쓰기의 명시적 승인 근거를 요구해 적용을 보류했다. 이후 사용자가 **운영 DB 적용 허용**을 명시했으며, 새 네이티브·논리 백업과 보존 리허설 후 검토한 018 단일 보호 트랜잭션을 적용했다. 새 기본 전시 초안 1행과 마이그레이션 표식 외 기존 행은 그대로 유지했다. 기존 함수·소유자·ACL·트리거 모드와 카탈로그를 전후 검사했고, 서비스 역할 RPC 허용과 브라우저 역할·비공개 테이블/보조 함수 직접 접근 거절을 실제 DB에서 확인했다.

추천 선정·발행·중단 시험 자료는 운영 DB에 만들지 않았다. 현재 공개 추천은 0개이고 기본 초안 revision은 0이다. 관리자가 직접 작품을 선정하고 저장본 미리보기 후 게시해야 노출된다. 공개 검색/미리보기 판정은 웹소설·웹툰을 모두 확인했다. 결제·PASS·정산·개인정보 접수·기능 플래그는 변경하지 않았다. 세부 검증은 [OP-03 검증 집계](../../artifacts/op03-verification-2026-11-01.json)에 기록한다. 제품 커밋 `b7587f7`의 [GitHub CI](https://github.com/jwmaxum/webnovels/actions/runs/41295320117)와 Cloudflare Pages 배포가 모두 성공했다. `webnovels-db4.pages.dev`·`webnovels.uk`에서 추천 직접 URL과 익명 공개 API가 정상이며, 변경된 JS·CSS 10개씩 총 20개가 로컬과 일치한다. Pages 메인 HTML도 일치한다. `webnovels.uk` 메인 HTML의 원문 차이 2곳은 공개 푸터 이메일과 복원 스크립트에 적용된 [Cloudflare 이메일 보호](https://developers.cloudflare.com/waf/tools/scrape-shield/email-address-obfuscation/)임을 diff로 확인했다. 원문 해시 불일치를 일치로 바꾸어 보고하지 않는다. 화면을 실행하는 브라우저·실기기 인수는 수행하지 않았다. 후속 기록 커밋은 문서·집계만 포함한다.

## 다음 개발 단계

다음 기능 단계는 **OP-04 가격·열람권**이다. 가입 독자 1~2회차 무료, 이후 회차 기본 100P와 관리자 가격 정책, 안정적인 회차별 재열람 권리, 중복 구매 1회 차감, 웹소설·웹툰 본문/이미지 접근 보호를 같은 서버 판정으로 구현한다. 충전상품의 원화 가격과 지급 포인트·회차 소비 가격은 구분한다.

기존 지갑·원장·권리 자료를 먼저 감사하고 **실제 결제 없는 TEST**로 검증한다. PG 계약·설정·고지·결제/취소/대사 인수 전에는 LIVE 결제를 열지 않는다. OP-03의 브라우저·실기기 화면 인수, R13 개인정보 접수 보류, SMTP·독립 복원 인수는 별도 잔여 과제로 유지한다.
