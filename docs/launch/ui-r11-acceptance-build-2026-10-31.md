# UI-R11 — 휴대폰 확인 반영과 빌드

2026-10-31. 사용자 회신 **“휴대폰 잘 작동합니다. 그냥 빌드하세요”**에 따라 추가 인수 시도를 중단하고 현재 코드 빌드와 기록 정리를 수행한다.

## 확인 범위

| 항목 | 결과 |
| --- | --- |
| 휴대폰 신규 화면 | 사용자 보고 정상. 앞선 맥락은 갤럭시 S26 Chrome이며 이번 회신에는 OS·Chrome 버전과 항목별 결과가 없다. 전반적인 정상 확인으로 기록 |
| 현재 코드 빌드 | `npm run build:compile`로 Prisma Client 생성과 TypeScript 컴파일. 독립 `tsc --noEmit`도 실행하며 실제 결과는 검증 JSON에 기록 |
| 기존 전체 릴리스 | 변경 전 제품 커밋 `e194da7ac3e3bc7b0b99dc55da076b8fa955a5cc`의 [R10 CI](https://github.com/jwmaxum/webnovels/actions/runs/41179805737)는 성공. 이번 로컬 빌드와 구분 |
| PC Word 개별 서식 저장·복원 | 상세 인수 미완료. 과거 PC 붙여넣기 사용자 확인을 이번 저장·재로딩 검증으로 확대하지 않음 |
| 200% 확대·키보드·음성 스크린리더 | 이번 실제 인수 미완료 |
| 실제 LCP·CLS 반복 측정 | 미수집. 합성 테스트나 과거 값을 새 실측으로 표시하지 않음 |

브라우저 도구 문서 초기화가 시간 초과됐으며 실제 화면 탐색·로그인·원고 변경 전이었다. 이후 사용자가 빌드 진행을 요청하여 브라우저 복구·추가 실기기·성능 수집을 이어가지 않았다. 새 시험 작품이나 원고를 만들지 않았고 기존 작품·계정·DB·기능 플래그를 변경하지 않았다.

## 후속 인수 시 주의

- `원고 다운로드`는 `contentDocument`가 포함된 JSON 백업이다. 파일 메뉴의 `현재 원고` TXT 내보내기는 서식 보존 검증을 대신하지 않는다.
- 실제 버전 복원은 `서식·버전 도구 → 버전 비교·복구 → 서버 버전 선택 → 선택한 버전으로 복구`의 저장 결과까지 확인해야 한다. 소스 경로 확인을 실제 복원 성공으로 기록하지 않는다.
- 성능 수집은 지원 도구와 가시성 이력을 확인한 뒤 제한된 반복 표본으로 수행한다. 현장 Core Web Vitals·CrUX 백분위와 구분한다.

이번 단계는 제품 코드 변경 없이 인수 회신·빌드 결과·개발 계획만 기록한다. 결과는 `artifacts/ui-r11-verification-2026-10-31.json`을 따른다. 커밋과 일반 push 결과는 완료 보고에 기록하며 환경 파일·비밀값·백업은 제외한다.
