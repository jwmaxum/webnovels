# 작가 대시보드 운영 적용

2026-09-26. 기존 `/creator` 작가 스튜디오와 검증된 Auth UUID 연결을 확장한다.

## 네 가지 메뉴

| 메뉴 | 제공 기능 |
| --- | --- |
| 대시보드 | 본인 작품·등록 회차·작성 중 원고 수, 최근 작품, 수익·계좌 상태 |
| 내 작품 | 작품 등록·정보 수정, 비공개 원고 작성·저장·복구 |
| 수익 내역 | 기간별 이전 수익 기록 조회, 50건 단위 페이지 이동 |
| 내 정보·정산 계좌 | 로그인 이메일 확인, 필명·소개 수정, 실명(예금주)·은행·계좌번호 등록 및 변경 |

이전 광고수익·판매수익·정산신청·독자통계 등은 주 메뉴에서 제거했다. 기존 원고 편집 경로와 Author/Creator 별칭은 유지한다. 계좌 화면은 로그아웃·계정 변경·화면 이동 시 지운다. 계좌번호·비밀번호를 localStorage에 저장하지 않는다.

## 수익 표시

- `author_earnings` 90건은 외부 매출 증빙과 지급 원장이 연결되지 않은 이전 자료다. 본인 작가 ID에 속한 기록과 연결 작품 소유자까지 대조하여 조회한다.
- `earning_ledger` 11건은 조사 시 모두 seed/demo/test 계열 출처였다. 두 자료를 더하거나 지급 가능액으로 전환하지 않는다.
- 실제 예상수익은 API에서 `null / NOT_CONNECTED`, 화면에서 **집계 전**으로 표시한다. 이전 금액과 기록상 상태는 **검증 대기**로 구분한다.
- 실제 수익 산정·지급에는 광고/결제 업체, 검증된 거래 원장, 배분·마감·취소 정책 연결이 필요하다. [수익화 계약](monetization-contract.md), [13단계](../../improve13.md)를 따른다.

## 개인정보와 저장

- `/api/v2/creator/dashboard`는 서버 Supabase Auth와 `launch_account_actor`의 APPROVED 작가만 받는다. 작가 프로필 없는 독자/관리자는 403. 요청에서 작가 ID를 받지 않는다.
- 필명·소개만 공개 프로필에 저장한다. 로그인 이메일·UUID·작품 소유권·계정 상태는 이 메뉴에서 변경하지 않는다.
- 프로필 버전에는 관리자 관리 버전과 현재 프로필 값이 포함된다. 작가 수정도 관리자 버전을 증가시켜 오래된 화면의 덮어쓰기를 막는다.
- 정산 실명은 예금주로 저장한다. 실명 인증 완료를 뜻하지 않는다. 주민등록번호·주소·세금 정보를 추가 수집하지 않는다.
- 계좌 변경은 서버가 확인한 로그인 이메일과 현재 비밀번호를 Supabase Auth에 다시 검증한다. 확인용 세션만 `scope=local`로 종료한다. 작가별 15분에 5회 제한. MFA 사용자는 MFA 재인증 연동 전까지 이 변경 경로에서 거절한다.
- 새 계좌는 비공개 `launch_recovery.author_payout_details`에 저장한다. 기존 `author_settlement_accounts` 10건은 보존하며 자동 이관/신뢰하지 않는다. 기존 계좌만 있으면 재등록 안내를 표시한다.
- 계좌번호는 AES-256-GCM 암호화, 일반 조회/응답은 끝 4자리만 반환한다. 매번 새 nonce를 만들고 Auth UUID + 작가 ID를 키 파생 및 AAD에 결합한다. 은행·예금주는 제한된 비공개 테이블에 저장한다.
- 상태는 항상 `PENDING`. 계좌 검증·송금을 실행하지 않는다. 감사에는 작업자·작가·작업·버전·시각만 기록한다. 비밀번호·계좌번호·소개 본문은 감사에 복사하지 않는다.
- 동시 수정은 409. 응답 유실 시 새로고침으로 저장 여부를 확인한다. 입력 오류는 비밀번호 확인 후 전체 계좌를 교체하여 수정한다.

## 암호화 키와 후속 지급 연동

1. 서버 전용 `AUTHOR_BANK_ENCRYPTION_KEY`가 있으면 사용한다. 미설정이면 현재 서버 Supabase secret/service-role 키를 사용하므로 이번 배포에 추가 Cloudflare 설정은 필요 없다.
2. **Supabase 키 교체 또는 별도 암호화 키 설정 전** 기존 암호화 키를 비밀 저장소에 보존한다. 키는 DB/로그/Git에 기록하지 않는다. envelope에는 식별용 SHA-256 앞 16자리만 저장한다.
3. 서버 키를 교체하려면 기존 암호화에 사용한 값을 `AUTHOR_BANK_ENCRYPTION_KEY`로 먼저 고정하거나 별도 검증된 재암호화를 수행한다. 새 키를 설정하는 것만으로 기존 계좌가 재암호화되지는 않는다. 키를 잃으면 작가가 재등록해야 한다.
4. 향후 지급은 이 신규 비공개 계좌를 명시적으로 연결하고 제한된 지급 작업에서만 복호화해야 한다. 은행 확인·변경 이력·지급 증빙을 구현하기 전에는 이전 `bank_info`/seed 계좌를 지급에 사용하지 않는다.
5. 현재 전체 계좌번호 조회/복호화 API는 제공하지 않는다.

## 화면 인수 절차

1. 배포 후 강력 새로고침하고 작가로 로그인하여 `/creator`에 진입한다. 대시보드·내 작품·수익 내역·내 정보·정산 계좌의 네 메뉴를 확인한다.
2. 대시보드의 작품 수와 내 작품 목록을 대조하고, 작품 버튼으로 기존 원고 편집에 진입한다.
3. 수익 내역에서 전체 기간 및 기록이 있는 월을 조회한다. 이전 자료의 검증 대기 표시와 실제 예상수익의 집계 전 표시를 확인한다.
4. 본인의 필명/소개를 저장하고 새로고침해 유지되는지 확인한다. 두 창에서 동시에 수정하면 나중의 오래된 저장은 충돌로 거절되어야 한다.
5. 실제로 사용할 본인 명의 계좌를 입력하고 현재 비밀번호로 저장한다. 저장 후 전체 번호 대신 끝 4자리와 확인 대기가 표시되어야 한다. 검증용 가짜 계좌를 운영에 등록하지 않는다.
6. 독자 또는 작가 프로필 없는 관리자로 계정을 바꾸면 이전 작가 정보가 지워지고 작가 전용 조회/수정이 거절되어야 한다.
