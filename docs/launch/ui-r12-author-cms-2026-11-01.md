# UI-R12 — 작품별 회차 관리와 간결한 발행

2026-11-01. 대시보드에서 작품을 선택한 뒤 회차 현황과 발행본을 확인하고, 원고 작성·발행으로 이어지는 흐름을 웹소설과 웹툰에 동일하게 적용한다.

## 작품과 회차

- 대시보드의 최근 작품과 내 작품의 제목에서 해당 작품의 회차 관리로 이동한다. 바로 원고를 쓰는 버튼도 유지한다.
- 회차별 제목·최종 발행일·회원 열람수·공개/예약 상태·관리 버튼을 제공한다. 검색과 상태 필터를 적용한다.
- 회차 제목은 현재 발행본을 읽기 전용으로 연다. 비공개 원고나 예약본을 발행본처럼 표시하지 않으며, 열람에 새 수정 원고 생성이나 독서 이력 기록을 동반하지 않는다.
- 공개 회차의 수정은 별도 원고를 작성해 관리자 검토를 요청한다. 승인 전에는 기존 공개본을 유지한다. 비공개 원고의 작성·수정·신규 즉시/예약 발행은 기존 작가 권한으로 수행한다.
- 웹소설의 안전한 서식 렌더러와 웹툰의 패널 렌더러·인증된 이미지 조회를 재사용한다. 웹툰 패널 순서와 반응형 크기를 유지한다.

## 열람수의 의미

기존 `episodes.view_count`는 현재 독자 뷰어의 열람 기록과 연결되어 갱신되지 않는다. 이번 화면은 실제 `authoring.reader_events_v2`의 `OPEN`/`COMPLETE` 기록을 작품·회차별로 집계한다. 동일 회원·동일 시간 버킷의 중복 이벤트를 한 번으로 세고 작가 본인의 기록은 제외한다.

화면 이름은 **회원 열람수**다. 로그인하지 않은 독자의 열람이나 전체 기간 고유 독자 수를 뜻하지 않는다. 원시 회원 식별자·열람 이력은 브라우저에 반환하지 않는다. 기존 고유 독자 통계의 소수 표본 보호 규칙도 변경하지 않는다.

## 발행과 작성본

즉시 발행·예약 발행·공개본 수정 요청 화면에서 PC/모바일 폭 선택과 본문 미리보기를 제거했다. 작품·회차 요약, 준비 상태, 권리 확인, 공개 방식만 확인하고 제출한다. 작성 화면의 별도 **미리보기**는 유지하며, 발행창을 열 때 불필요한 웹툰 이미지 렌더링을 시작하지 않는다. 기존 DOM 호환 ID는 숨긴 상태로 보존한다.

불러오기에는 현재 원고의 최종 작성 내용을 한 번 표시한다. 기기 사본·서버 원고·이전 편집기 자료는 접힌 복구 목록으로 옮긴다. 실제 원고·버전·사본은 삭제하지 않는다. 기기의 마지막 작성 원고 포인터와 원고 저장을 같은 IndexedDB 트랜잭션으로 보존한다. 서버에서는 실제 원고 revision 생성 시각을 기준으로 최근 작성본을 선택한다. 작성 중인 원고와 미동기화 사본을 새 원고로 조용히 덮어쓰지 않으며, 충돌은 기존 복구 흐름으로 처리한다.

## DB와 검증

- `030_creator_episode_workspace.sql`: 검증된 작품 소유자에게 회차 목록과 현재 발행 head의 내용을 제공하는 서버 전용 읽기 RPC. 새 테이블이나 브라우저 직접 접근 권한을 추가하지 않는다.
- `031_creator_draft_list_summary.sql`: 기존 서버 원고 목록에 실제 revision 작성 시각을 추가한다. 소유권·revision·공개본 검토 계약을 유지한다.
- 운영 DB 적용 전 읽기 전용 백업을 보관하고, 현재 백업을 로컬 PostgreSQL 엔진에 복원하여 원본 행·함수·ACL·제약 보존과 반복 적용을 확인한다. 실제 `SET ROLE`로 브라우저 역할 거부와 서비스 역할의 소유권 검사를 검증한다.
- 검증 결과는 [R12 검증 기록](../../artifacts/ui-r12-verification-2026-11-01.json)에 기록한다. 로컬 합성 DB/VM 테스트, 운영 DB 적용, 배포 결과는 구분한다. 환경 파일·비밀·원본 백업은 커밋하지 않는다.

프로젝트 규칙에 따라 새 브라우저/localhost 인수는 수행하지 않는다. 이번 변경을 실제 Word·휴대폰·스크린리더·현장 성능 측정 완료로 표시하지 않는다.
