# 운영자 요청 작가·작품 등록

2026-10-22. 사용자가 이메일 사용 권한을 확인하고 실제 운영 DB의 작가 계정과 작품 발행을 명시적으로 요청했다.
기존 테스트 자료를 복원하거나 조회수·구독자·경력을 만들어 넣는 작업이 아니다.

## 대상과 등록 근거

- 필명 **비즈피어**, 작품 **조선 로맨스**, 웹소설 10화 완결.
- 조선에서 이루어지지 못한 성몽룡·이춘향의 사랑이 2026년 스무 살 대학생의 만남으로 이어지는 창작 소설이다.
- 원고 10화와 표지는 AI를 활용해 제작했다. 작품의 `ai_usage_type=GENERATED`와 소개문에 이를 표시한다.
- 사용자가 지정한 로그인 정보로 Supabase Auth Admin API에서 실제 계정을 생성했다. 비밀번호·이메일·Auth UUID는 이 문서와 Git에 저장하지 않는다.
- 이메일 소유권은 사용자의 확인과 운영자 등록 요청에 근거한다. Auth의 관리자 확인 처리를 메일 수신 성공이나 PASS 실명 인증으로 해석하지 않는다.
- 운영자가 위임받아 등록한 기록은 Auth 앱 메타데이터와 비공개 실행 기록에 남긴다. 작품의 권리 근거는 `LICENSED`이며, 본인이 직접 집필했다는 `OWN` 확약으로 기록하지 않는다.
- 실명·계좌·PASS CI/DI·인증 거래번호를 임의로 생성하지 않는다. 무료 작품 발행에는 이 정보가 필요하지 않다.

## 적용 방법

운영 DB의 164개 테이블에 대한 새 논리 백업을 확보했다. 기존 관리자 프로필은 값 해시를 전후 대조한다.
등록은 `free_beta_enrollment`, `creator_works`, 원고 저장·발행은 `creator_drafts`와
`creator_publications_v18`을 사용한다. 작품·회차 직접 INSERT로 소유권, 원고 revision, 공개 head 계약을 우회하지 않는다.

작가 등록 시 일반 가입 DB 게이트는 잠긴 한 트랜잭션 안에서만 열고 닫는다. 외부 연결에는 활성 상태가 노출되지 않는다.
표지는 작가 로그인 세션으로 기존 파일 API를 호출해 Cloudflare 이미지 처리 Worker와 private Supabase Storage를 거친다.
원본은 비공개로 보존하고 600×900 JPEG만 공개 표지 경로로 제공한다.

공개 연재 DB 게이트는 표지 API의 선행 조건이므로, 요청 작품만 비공개 초안이고 공개 회차가 없음을 확인한 뒤 전환한다.
10화 발행은 하나의 트랜잭션으로 처리한다. 최초 공개는 작가 권한이며,
발행 이후 수정·삭제 검토 계약을 유지한다. 실제 수신한 공개 본문을 준비한 원고와 대조한다.

## 활성화 범위

이번 명시 요청을 이행하기 위해 기존 작가 작업·파일·최초 발행·무료 독자 탐색/열람과 공개 후 변경 검토 플래그를 활성화한다.
현재 공개 대상은 이 작품이다. 게이트 자체를 작품별 허용 목록으로 해석하면 안 되며, 이후 적격 신규 작품에도 적용된다.
일반 가입 `AUTH_ONBOARDING_ENABLED`와 `free_beta_settings.enabled`는 비활성 상태를 유지한다.
PASS, 결제, 성장 측정, 관리자 역할 변경은 켜지 않는다. 예약 발행 Worker의 발행 플래그도 변경하지 않는다.
Cloudflare의 기존 비밀값·다른 설정·미리보기 설정과 Worker 바인딩을 보존한다. Vercel은 사용하지 않는다.

이번 운영자 요청 발행은 37단계 외부 베타 전체 인수 완료를 의미하지 않는다.
실제 확인 결과는 [검증 기록](../../artifacts/requested-author-publication.json)에 기록한다.

2026-10-22 완료: [실제 작품 페이지](https://webnovels-db4.pages.dev/works/32), 홈 완결 목록,
작품 상세·회차 목록, 비로그인 독자의 10화 본문과 공개 표지, 작가 비밀번호 로그인을 확인했다.
총 본문 23,580자이며 원고·공개 버전·발행 동의 연결이 각각 10개다. 공개 본문은 준비한 원고와 모두 일치한다.
기존 관리자 프로필 4개의 값 해시도 유지됐다. 브라우저 인수와 별도 hosted 복원 검증은 수행하지 않았다.

## 다음 개발·인수

1. SMTP 준비 후 외부 회원의 가입 확인과 비밀번호 복구 메일을 실제 수신하고, 일반 가입을 별도로 활성화한다.
2. 사용자 요청 시 실제 모바일·데스크톱 브라우저에서 작가 로그인, 원고 불러오기, 발행 후 수정 검토, 독자 열람을 인수한다.
3. 별도 Supabase 프로젝트에서 Auth·DB·private Storage 복원과 계정/작품 연결을 확인한다.
4. 실제 자료가 제공되면 작가 본인 정보·정산 계좌를 등록하고, PASS·Toss 계약 후 실제 제공자 검증을 진행한다.
5. 이 작품과 계정은 사용자 요청으로 만든 운영 자료다. 과거 테스트 자료 초기화 명령의 재실행 대상으로 삼지 않는다.

자세한 후속 범위는 [37단계 계획](../../improve37.md)을 유지한다.
