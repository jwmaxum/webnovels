# 관리자 CMS 메뉴 복구 — 2026-09-25

2026-09-26 후속: [작품 CMS 홈 노출 설정 편집·저장](admin-home-curation.md). 아래 초기 조회 범위를 확장하여 추천·인기·신작을 작품별로 변경하고 감사 기록에 남긴다.

## 요청과 원인

사용자가 `/admin/`에 CMS, 작가 정산, 서브관리자 권한 등 필요한 운영 메뉴를 다시 표시하도록 요청했다. 계정 전용 활성화 상태에서 `adminOperationsEnabled=false`이면 가상 계정을 제외한 모든 메뉴를 숨기고 기본 화면까지 가상 계정으로 이동하던 조건을 수정했다.

전체 콘텐츠 SQL 전환을 기다리지 않고 관리자에게 필요한 목록을 조회할 수 있도록 계정 서비스의 검증된 Auth/프로필 확인 경로에 제한된 `/api/v2/admin/console`을 추가했다. 일반 이용자의 콘텐츠·게시·정산 지급 기능은 활성화하지 않는다.

## 메뉴와 실행 범위

| 메뉴 | 이번 연결 |
|---|---|
| 운영 대시보드 | 실제 작품·회차·작가·독자 수, 검수·신고 대기 건수, 원본 본문 확인 필요 건수 |
| 작품 CMS | 작품 검색, 소유 작가 ID, 등록 상태, 회차 수, 본문 확인 필요 건수, 기존 큐레이션 설정 조회 |
| 회차 CMS | 작품·회차 검색, 상태·무료 설정·원본 본문 존재 여부. 원고 전문은 반환하지 않음 |
| 작가·독자 관리 | 역할별 목록·검색·인증 연결 여부. 가상 계정 관리로 이동 |
| 신고·콘텐츠 검수 | 기존 검수·신고 접수 기록 조회. 조치·반려는 기존 전체 운영 전환 후 제공 |
| 이의제기 | 전체 운영 미활성 시 필요한 선행 조건 안내. 활성 시 기존 처리 화면 |
| 가상 계정 관리 | 기존 수정·정지·삭제·복구 기능 유지 |
| 작가 정산 | 기존 정산 신청 기록 조회. 시험/실거래 미대조임을 표시. 지급 가능액 집계·승인·송금·상태 변경 없음 |
| 서브관리자·권한 | 최고 관리자가 기존 SUB_ADMIN의 지정 업무 권한 저장. 현재 비밀번호 재확인·동시 수정 방지·감사 기록 |
| 감사·처리 기록 | 계정 및 새 권한 변경 이력. 전체 운영 활성 시 기존 사건 기록 화면 |
| 서비스 운영 설정 | 기능 설정 상태와 가입·콘텐츠·운영·정산 준비 항목 |

`/admin/subadmins`, `/admin/settlements`, `/admin/revenue`, `/admin/episodes`, `/admin/authors` 등 기존 링크를 유지한다. 화면은 사이드바와 작업 영역으로 구성하고 좁은 화면에서는 메뉴가 상단에 배치된다. 제한 관리자는 보유 권한에 맞는 메뉴만 볼 수 있다.

## 권한 변경과 보존

- 새 `005_admin_console.sql` RPC는 service_role만 실행할 수 있다. DB에서 매 요청마다 현재 Auth 상태와 계정 연결, 관리자 권한을 다시 확인한다.
- 권한 변경은 같은 출처 JSON POST만 허용한다. 서버가 확인한 현재 관리자 이메일로 Supabase 비밀번호 인증을 다시 수행하고, 검증용 세션만 종료한 뒤 저장한다. 이메일 발송·비밀번호 변경은 하지 않는다.
- 비밀번호는 RPC·DB·감사 기록에 전달하지 않으며, 화면 입력도 제출 직후 지운다. 요청 본문을 로그에 남기지 않는다.
- 자기 자신, 최고 관리자, SUB_ADMIN 외 역할은 변경할 수 없다. 역할·Auth UUID·계정 연결·활성 상태 변경도 받지 않는다.
- 11개 기존 운영 권한과 새 `SETTLEMENTS_READ`만 편집한다. 이전 계약의 다른 권한은 보존하며 화면에 표시한다. 기존 권한으로도 가능한 접근은 새 체크박스를 해제해도 유지된다고 안내한다.
- 미연결 서브관리자는 권한 설정과 별도로 Auth 연결이 필요하다. 이메일만으로 다른 계정을 추정 연결하거나 Auth 사용자를 자동 생성하지 않는다.
- 콘텐츠·본문·거래·정산 행은 변경하지 않는다. 정산 조회에 계좌번호·은행 정보는 반환하지 않는다.

이번 사용자 요청에 따른 제한된 권한 관리 경로이며, 기존 `ADMIN_ROLE_CHANGES_ENABLED`와 stage9의 재인증 없는 권한 API를 켜지 않는다. 전체 콘텐츠 운영의 기존 인수 조건은 유지한다.

- `node scripts/prepare_admin_console.mjs <백업 디렉터리>`: 실제 백업을 PGlite에 복원하고 새 SQL·모든 조회·권한 저장 롤백·public 전체 행 보존을 검증한다.
