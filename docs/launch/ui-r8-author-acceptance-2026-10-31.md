# UI-R8 — 작가 직접 발행·예약 수정·독서 성능

2026-10-31. 웹소설과 웹툰에 같은 발행 원칙을 적용한다.

## 작가가 직접 처리하는 범위

| 내용 | 처리 방법 |
| --- | --- |
| 새 작품·미공개 원고 | 작가가 작성·수정·저장·불러오기 |
| 새 회차 즉시 발행 | 작가가 저장본을 확인하고 직접 무료 발행. 관리자 사전 검수 없음 |
| 새 회차 예약 발행 | 작가가 날짜·시간대를 선택하고 직접 예약 |
| 아직 공개되지 않은 예약 원고 수정 | **예약 원고 수정** → 기존 예약 취소 확인 → 같은 원고·회차 번호로 이어쓰기 → 즉시 또는 예약 발행 선택 |
| 이미 공개한 회차 수정·철회 | 수정 초안으로 검토 요청. 관리자 승인 전까지 기존 공개본 유지 |
| 공개 이력이 있는 작품의 설정·표지 변경 | 기존 공개 후 변경 검토 계약 유지 |

작품의 다른 회차가 공개되어 있어도 새 회차의 첫 발행에는 관리자 승인이 필요하지 않다.
한 번 공개한 뒤 비공개로 전환한 회차는 공개 이력을 잃지 않는다.
원고를 수정하려고 예약을 취소해도 자동으로 재예약하지 않는다. 작가가 새 발행 시각을 선택한다.
이미 실행 중이거나 다른 기기에서 변경한 예약은 generation 검증으로 충돌을 표시한다.

## 변경 내용과 보존

- `authoring.draft_json`과 `publication_json`은 해당 **회차의 실제 공개 이력**을 `hasPublicationHistory`로 전달한다. 원고의 episode ID만으로 공개 여부를 추측하지 않는다.
- 필드가 없는 이전 서버와 연결하면 공개본 보호를 위해 기존 회차를 보수적으로 검토 대상으로 표시한다. 실제 발행 권한은 서버에서 다시 검증한다.
- 예약 목록 조회에서 PL/pgSQL 변수와 테이블 별칭이 충돌하던 오류를 제한된 별칭 교체로 고쳤다. 예상하지 못한 함수 정의에는 마이그레이션을 중단한다.
- 예약 수정·취소의 중복 클릭, 계정 변경, 늦은 응답을 차단하고 취소 성공 후 원고 불러오기 실패를 구분한다. 다른 작성 중 원고와 기기 사본을 보존한다.
- 같은 작가 계정으로 웹소설과 웹툰을 각각 등록한다. 본인 확인·저작권·업로드·공개본 변경 검토 정책을 우회하지 않는다.

[028 마이그레이션](../../database/authoring/028_publication_history_contract.sql)은 새 테이블이나 브라우저 권한을 추가하지 않는다.
비공개 헬퍼의 직접 EXECUTE 금지, 서비스 전용 소유자 RPC, 기존 공개본 검토·불변 버전·RLS를 보존한다.
기존 계정·원고·공개본·작품을 초기화하지 않는다.

## 성능

홈에서는 독서용 Google Fonts 스타일시트를 비활성으로 두고, 실제 뷰어 진입 때 기존 URL을 한 번 활성화한다.
Noto Sans/Serif 선택과 로컬 SUIT, 기본 독서 설정을 유지한다.
소설 본문은 스타일시트와 현재 사용 서체의 배치를 최대 3초 기다린 뒤 저장 위치를 복원한다.
그동안 작가/독자가 화면을 이동하거나 직접 스크롤하면 늦은 위치 복원을 중단한다.
실패·시간 초과에도 본문을 표시하며 준비 완료라고 보고하지 않는다. 웹툰은 텍스트 서체 대기를 생략한다.
정적 배포 감사는 비활성 스타일시트를 차단 자원으로 계산하지 않으며, 실제 네트워크 요청은 브라우저 측정과 구분한다.

## 검증·운영 적용 기록

릴리스 명령 전체 범위를 실행했다. 첫 빌드는 R5의 이전 안내문·캐시 버전 기대값 2개에서 중단됐고,
수정 후 R5~R8 및 `build:compile`을 다시 실행해 종료 코드 0을 확인했다.
최종 스케줄러 형식 보완 후 해당 모의 검증 12개도 별도로 통과했다.
독립 TypeScript 검사와 변경 JS 16개의 구문 검사를 통과했다. 별도 lint 명령과 전체 커버리지는 구성·측정하지 않았다.

신규 R8 검증은 회차/소유권 SQL 9개, 실제 작가 UI 모듈 9개, 글꼴/읽기 위치 12개,
Cloudflare 설정 보존 12개로 42개다. 기존 배포 감사에는 비활성 스타일시트 회귀 1개를 추가했다.
일반 작가에게 관리자 프로필이 없어도 소설·웹툰 첫/후속 회차를 직접 발행·예약하고,
미공개 예약을 취소한 뒤 같은 회차로 수정할 수 있음을 합성 DB에서 검증했다.
이미 공개한 버전 교체는 승인 전까지 공개 head가 바뀌지 않는다.

운영 DB의 028은 **2026-10-31 12:10:53 KST**에 적용했다. 최신 논리 백업 164개 테이블·330개 행을
격리 복원하고 두 번 적용해 원본 보존을 확인했다. 실제 적용은 함수 3개 외 정의·행·ACL을 보존하는
트랜잭션으로 실행했다. 매분 갱신되는 `beta_operation_maintenance` 한 테이블은 잠금 직후의 현재 해시와
적용 후 해시를 비교하며, 나머지 163개 테이블은 백업 해시를 그대로 대조했다.
네이티브 pg_dump 아카이브도 검증했다. 외부 Storage 바이트·원격 독립 복원·외부 백업 보관 인수는 포함하지 않는다.
공유 복원 도구가 로컬에서 과거 기본 함수 ACL 2개를 좁혀 표현하는 한계는 기록했고,
실제 적용 전후에는 운영 원본 ACL을 정확히 대조했다.

운영 Worker는 **2026-10-31 12:21:40 KST**에 기존 `AUTHOR_PUBLISH_ENABLED` 하나만 활성화했다.
당시 PENDING/RUNNING은 0건이었다. 원본 코드 바이트·진입점·모든 비밀/다른 바인딩·Cron·비공개 라우팅·Pages 설정을
전후 대조했다. 소스와 기존 Noto/권한 설정을 다시 작성하지 않았다.
`node scripts/configure_ui_r8_scheduler.mjs`는 기본 조회 전용이며 `--apply`는 DB028·빈 대기열·동일 대상·원본 보존을 요구한다.
로컬 `scheduler/wrangler.toml`의 안전한 기본 비활성 값은 운영 설정과 구분한다.

허용된 실제 작가 계정으로 별도 비공개 인수 작품을 만들고 대표 Word HTML의 문단·줄바꿈·강조·정렬을
붙여넣어 저장·재로그인·새로고침 복원을 확인했다. 실제 Microsoft Word 프로그램 클립보드 인수와는 구분한다.
관리자 승인 없이 먼 미래의 예약 접수와 취소가 확정됐고 원고는 편집 가능한 상태로 보존됐다.
기존 조선 로맨스 10화의 공개·완결·공개 head 보존과 인수 작품의 미공개, 실제 헬퍼/RPC 권한을 읽기 확인했다.
새 UI 배포 후 예약 원고 수정·웹툰 업로드·반응형·글꼴 네트워크 결과는 후속 배포 인수 기록으로 추가한다.

Codebase Memory의 프로젝트·인덱스 조회가 `Transport closed`로 실패해 범위를 제한한 소스·기존 계약·공식 API 자료를 사용했다.
기존 구현과 Node·PGlite 테스트를 확장했고 새 제품 의존성은 추가하지 않았다.
