상태를 색상만으로 전달하지 않고 실제 상태명·안내·행동을 함께 표시한다. 역할별 색상과 SUIT는 R1·R2 토큰을 재사용한다.
신규 스타일은 관리자·계정·지원함 범위로 제한하고 독자 본문이나 작가 원고 서식을 전역으로 덮어쓰지 않는다.
관리자 메뉴는 상단 헤더와 겹치지 않도록 문서 흐름에 둔다.

## 보존한 서비스 계약

- 관리자 업무는 기존 서버 검증 `actor.admin`과 권한 문자열을 사용한다. `CREATOR_MGMT`·기존 URL 별칭과 클래식 모듈 로드 순서를 유지한다.
- 작가·독자·Auth UUID·작품 ID·원고 UUID를 새로 연결하거나 추정하지 않는다. 계정 소유권·원고 엔진·공개 head·revision 계약은 변경하지 않는다.
- 신규 회차의 최초 발행은 작가 권한이며, 이 화면은 공개 후 변경을 검토한다. 수정·삭제·표지의 기존 승인·반려·기준 변경 검사를 유지한다.
- 지원함의 상태·revision·requestId·소유권·쓰기 한도·탈퇴 검토 계약은 유지한다. 비밀·전체 원고·민감 개인정보를 자동 첨부하지 않는다.
- 결제·PASS의 설정 저장과 실제 서비스 승인·인수는 구분한다. 미계약 서비스나 운영 플래그를 임의로 활성화하지 않는다.
- 회사정보, 전자상거래 고지, 환불조건을 이번 UI 단계에서 새로 해석하거나 변경하지 않는다. 기존 법적 본문과 링크의 고정 fingerprint를 신규 테스트로 확인한다.
- DB·서버·CSP·비밀 설정·운영 데이터에 대한 변경은 없다. 비즈피어 계정과 실제 연재 자료를 보존한다.

## 조사·보안 검토

`search-first → 구현 → security-review → verification-loop` 흐름을 적용했다.
기존 관리자·Auth·지원함·정책 모듈과 관련 테스트를 확장했으며 외부 패키지를 추가하지 않았다.
Codebase Memory 프로젝트·범위 확인은 transport 오류로 사용할 수 없어 `rg`·소스 읽기를 사용했다.
패키지 레지스트리·GitHub 구현 검색은 이번 기존 UI 개선 범위에서는 수행하지 않았다.

인증 탭은 [W3C APG Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)를 참고해 좌우 이동·Home/End·선택 상태·탭 순서를 기존 클릭 흐름에 연결했다.
표는 [MDN table](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/table)의 열 제목·데이터 구조를 유지하며 스크롤 영역을 표시한다.

보안 검토는 사용자 입력의 안전한 텍스트 렌더링, 실제 권한, 늦은 비동기 응답, 처리 중 잠금, 변경 검토의 제한된 표시 항목, 비밀값 미포함에 집중했다.
미리보기·계정 상태 배지는 서버 권한·본인확인·배포 인수의 증거로 사용하지 않는다.

## 검증과 한계

자동 검증 결과는 [R6 검증 기록](../../artifacts/ui-r6-verification-2026-10-31.json)에 기록한다.
신규 테스트는 관리자 8개, 지원함 8개, 계정·정책 12개, 탭·메뉴·HTML/CSS·자산 7개로 총 35개다.
기존 테스트의 메뉴 문구·공통 로더 버전 기대값은 실제 R6 표시에 맞췄으며 권한·경로·요청 내용·데이터 보존 검사는 유지했다.

| 검증 | 결과 |
| --- | --- |
| `npm run build` | PASS — 릴리스 44개 명령, Prisma 생성·TypeScript 컴파일 전체 종료 코드 0 |
| `tsc --noEmit` | PASS — 설치된 TypeScript CLI로 실행, 종료 코드 0 |
| 신규 R6 회귀 | 35/35 PASS, 실패·건너뜀 없음 |
| 구문·HTML/CSS | JS 구문 18개, HTML 중복 ID·폼·대화상자·레이블·정책 링크, 두 CSS 파싱 검사 통과 |
| 보안 | 두 차례의 독립 소스 검토, 변경 대상 24개 파일 비밀값 패턴 0건, 서버·DB·Auth 원천·기능 플래그 보존 |
| 변경·사용자 작업 | diff 검사 통과, 기존 `gemini.md` 해시와 미추적 스킬 폴더 보존 |

새 작업 화면 CSS는 14,263바이트(gzip 2,768바이트), 개편한 정책 CSS 전체는 7,456바이트(gzip 1,671바이트)다.
실제 네트워크·실기기 성능 개선율로 해석하지 않는다.

프로젝트 규칙에 따라 명시 요청이 없는 localhost·브라우저 검증은 수행하지 않는다.
실제 모바일·확대·스크린리더 인수, 운영 DB의 실제 문의·승인 처리, PASS·결제·메일 계약 인수는 VM·합성 DB 검증과 구분한다.
전용 lint 명령과 커버리지 임계값 검증은 저장소에 없어 성공으로 표시하지 않는다.

## 다음 단계 — UI-R7

**UI-R7: 회귀·접근성·성능·배포 점검**을 진행한다.

1. 사용자 명시 요청 후 독자·작가·관리자 실제 브라우저 흐름을 모바일·PC에서 인수한다.
2. 320·375·390·768·1024·1440px, 200% 확대, 키보드 탭·대화상자·표 스크롤·스크린리더, 모바일 키보드와 저장 상태를 확인한다.
3. 실제 공개본 변경 검토, 문의 작성→관리자 답변→재개, 계정 전환·권한 회수 중 늦은 응답을 인수한다.
4. 동일 조건에서 CSS·폰트·이미지 전송, 화면 진입·레이아웃 이동을 측정하고 발견한 문제를 수정한다.
5. 커밋별 GitHub CI·Cloudflare Pages 결과를 대조하고 배포된 자산·서비스 상태를 확인한다.

SMTP·외부 베타·독립 복원·지원 기록 보존·외부 인증/결제 계약은 기존 37단계의 별도 운영 과제로 유지한다.
