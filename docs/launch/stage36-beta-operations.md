# 36단계 — 베타 문의와 운영 관측

2026-10-22. 35단계의 GitHub·Cloudflare 배포 성공을 확인한 뒤 기존 서비스에 문의 지원함과 기술 관측을 추가했다.
SMTP는 사용자의 추후 준비 결정을 유지한다. 새 의존성이나 별도 플랫폼으로 이전하지 않는다.

## 이용 방법

- 회원: 상단/모바일 더보기·독자 서재·작가 메뉴의 **문의·피드백**에서 문의, 오류, 개선 제안, 저작권 분쟁,
  탈퇴 검토 요청을 접수한다. 내 문의에서 답변·처리 사유·이력을 확인하고 재검토를 요청한다.
- 관리자: **서비스 운영 → 베타 운영**에서 문의를 조회·답변하고 처리 상태와 사유를 기록한다.
  문의 조회는 `CASE_READ`, 처리는 추가 `CASE_RESOLVE`, 기술 관측은 `OPERATIONS_READ` 권한을 사용한다.
- 최초 공개는 기존 작가 권한이다. 이 지원함의 상태 변경은 공개본 변경, 콘텐츠 제재, 탈퇴 삭제를 자동 실행하지 않는다.

지원 기록은 서버 세션과 DB의 현재 계정 상태·권한을 모두 확인한다. 본인 문의 격리, 동일 요청 재시도,
revision 충돌, 기록 불변성, 입력 크기·횟수 제한, 로그아웃/탭 변경 시 비공개 화면 삭제를 적용했다.
문의는 일반 텍스트로 표시하며 원고·파일·개인정보를 자동 첨부하지 않는다. [API·상태 계약](stage36-support-contract.md).

## 기술 관측

대상은 활성화된 원고 저장·파일/웹툰 업로드·발행·가입의 쓰기 응답과 예약 발행 작업이다.
성공 응답, 409 충돌, 5xx 실패만 집계하며 401/403 등 인증 거절과 일반 조회는 제외한다.
전체 방문자·가입 수·사이트 실패율을 뜻하지 않는다. 수집 실패 시 원래 저장 결과를 변경하거나 재시도하지 않는다.

원고 본문·이미지·사용자 ID·IP·요청 경로·토큰을 관측 테이블에 저장하지 않는다. 오류는 HTTP 상태에 따른
`CONFLICT`/`SERVICE_UNAVAILABLE`와 서버 요청 UUID로 일반화한다. 분야별 분당 최대 100개 오류 표본 중
최근 24시간의 50개를 표시하고, 실제 관측 건수·평균시간·현재 예약/이미지 실패 개수를 함께 표시한다.
관측은 best-effort이며 성공 집계를 정확히 한 번 전달하는 원장으로 취급하지 않는다.

분 집계와 세부 오류는 7일 경과 후 정리 대상이다. 정리 지연과 배치 한도가 있어 정확한 삭제 시각을 보장하지 않는다.
Cron의 **운영 점검 신호**는 정리 RPC가 DB에 도달했다는 뜻이며 예약 회차 발행 성공 증거가 아니다.
이 기간은 기술 관측에만 적용하며 문의·원고·신원·법정 보존기간과 무관하다.

## 운영 적용과 검증

`026_beta_support.sql`, `027_beta_operations.sql`은 비공개 RLS 테이블 7개와 service_role 전용 RPC를 추가한다.
같은 마이그레이션에서 직접 테이블 권한을 회수하고 RPC EXECUTE만 명시한다. 기존 DB나 Auth를 초기화하지 않는다.
`prepare_stage36.mjs`는 현재 snapshot의 리허설·원본 행/설정 보존·ACL 검증과 fresh native 백업 확인을 통과해야
`--apply`할 수 있다. `configure_stage36_cloudflare.mjs`는 적용된 DB를 재확인한 뒤 관측 플래그와 scheduler 소스만
변경하고 기존 Pages/Worker 바인딩·비밀·Cron·비공개 접근·공개 기능 플래그를 보존한다.

실행 결과는 `artifacts/stage36-*.json`에 비밀값 없는 요약으로 남긴다. 운영 DB 적용과 배포 확인은 외부 가입/발행 인수와 구분한다.
브라우저/localhost 테스트와 외부 메일 발송은 수행하지 않는다. 실제 PostgreSQL의 다중 연결 경쟁 인수도 별도다.

## 남은 운영 조건과 다음 개발

SMTP와 운영에서 분리된 Supabase 복원 대상이 없어 실제 가입 메일 수신과 격리 DB/Storage 복원은 미완료다.
공개 베타·연재 게이트, PASS·PG는 계속 비활성이다. [운영 실행서](stage36-operations-runbook.md)에 장애 대응,
탈퇴·보존·키 교체의 현 구현 범위와 필요한 후속 절차를 기록했다.
[37단계 계획](../../improve37.md)은 외부 베타 인수, 격리 복원, 승인된 보존·키 회전 구현을 우선한다.
