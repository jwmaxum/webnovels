# UI-R5 — 작가 작품·원고·웹툰 업로드 화면 개편

작성일: 2026-10-31 · 상태: **구현·로컬 검증 완료** · 기준: [UI 개편 계획](ui-redesign-plan-2026-10-30.md), [R1 명세](../design/ui-r1/README.md), [작가 호환 계약](author-creator-contract.md)

## 적용한 작성 흐름

**내 작품 → 원고 작성·불러오기 → 저장 → 미리보기 → 지금 발행 또는 예약 발행** 순서로 사용한다.
새 작품은 웹소설·웹툰을 각각 등록하며 기존 작품의 발행 이력으로 다른 종류의 작품 등록을 제한하지 않는다.
실제 서비스 연결·작가 권한에 따른 기존 기능 제한은 그대로 적용된다.

| 영역 | 변경 결과 |
| --- | --- |
| 내 작품 | 실제 작품의 유형·공개/비공개·연재 상태·회차 수, 2:3 표지와 `원고 작성`·`작품 설정` 행동을 구분 |
| 작품 관리 | 작성·설정·썸네일 변경을 먼저 표시하고 회차·예약·반응·파일·삭제 관리는 접어서 제공 |
| 원고 상단 | 선택한 실제 작품명·종류, 비공개 원고/공개본 수정/보관 상태와 기기·서버 저장 상태 표시 |
| 편집 행동 | 새 원고·불러오기·저장·미리보기와 발행 옵션을 구분. 썸네일·이미지는 선택한 작품 관리에 배치 |
| 저장한 원고 | 서버·기기·이전 편집기 사본을 보존하고 목록을 접어서 열기. 넓은 화면에서 펼친 목록은 본문 옆, 좁은 화면은 본문 위에 배치 |
| 소설 편집 | 흰 본문과 또렷한 글자, 충분한 여백. 서식·버전·파일·백업은 보조 도구로 구분 |
| 집중 편집 | 버튼과 Escape의 표시·눌림 상태를 함께 변경하고, 모바일 키보드 높이 변화 시 텍스트·서식 편집 초점 모두 확인 |
| 웹툰 업로드 | 순번·파일명·상태·실제 썸네일, 선택 순서/파일명 순서, 순차 처리, 위·아래/드래그 정렬, 실패한 파일별 재시도 |
| 미리보기 | 정확히 저장한 현재 원고 버전으로 확인. 별도 미리보기 행동은 공개·예약 목록 조회나 발행 요청을 보내지 않음 |
| 발행 상태 | 신규 회차는 작가가 발행. 공개본 수정 원고는 검토 요청으로 표시하며 예약 발행 차단. 보관·제한·충돌·한글 조합·이미지 처리 상태에 맞춰 행동 비활성화 |

일반 편집 도구는 문서 흐름에 놓아 상단 고정 헤더와 겹치지 않게 했다. 집중 편집 안에서만 도구를 고정한다.
색상은 R1·R2에서 확정한 토큰을 사용한다. 버튼·본문 글자에 대비가 높은 역할 색을 적용하며, 상태는 문구로 함께 표시한다.
새 CSS는 작가 화면과 기존 파일·발행 모달에 한정한다.

## 원고·업로드 보존과 오류 처리

- Word 붙여넣기는 기존 안전 변환의 문단·줄바꿈·강조·정렬을 유지한다. 표·그림·쪽 배치를 완전히 재현한다고 안내하지 않는다. TXT·DOCX·HWPX 파일 가져오기는 별도 변환 안내를 유지한다.
- 자동 저장·IndexedDB 기기 사본·서버 revision·충돌 비교·버전 복구·동일 요청 재시도·예약 발행의 기존 계약을 사용한다.
- 새 미리보기의 늦은 응답·오류가 다른 작품이나 계정의 현재 미리보기를 덮어쓰지 않게 했다.
- 웹툰은 업로드 묶음 처리와 개별 처리 중 새 선택·순서 변경·중복 재시도를 막는다. 취소와 원본 보존은 기존 경로를 사용한다.
- 동일한 대기 File 객체의 중복 선택을 막되, 파일명이 같다는 이유로 서로 다른 이미지를 버리지 않는다.
- 이전 작업의 완료 처리가 새 원고의 업로드 잠금을 풀지 않게 했고, 순서 변경·초기화 후 늦은 세로 미리보기 응답을 폐기한다.
- 서버 처리 상태·분할 위치가 진전되지 않으면 자동 반복을 멈추고 `이어서 처리`를 제공한다.
- 썸네일은 지연 로딩·비동기 디코딩을 사용하고 Object URL을 재사용하며 취소·초기화 시 해제한다. 서버 이미지 확인은 버튼으로 요청해 목록 전체를 자동 다운로드하지 않는다. 이미지 바이트는 원고 JSON·localStorage에 넣지 않는다.
- 기존 JPEG/PNG, 파일당 8 MiB, 변당 12,000px·1,200만 화소, 회차 100개·128 MiB 제한과 서버 검증을 유지한다.

썸네일 자원 해제는 [MDN Object URL 문서](https://developer.mozilla.org/en-US/docs/Web/API/URL/revokeObjectURL_static)를 확인했다.
접기 메뉴는 [HTML details](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/details)를 재사용한다.
펼친 원고 목록의 PC 배치는 [CSS :has()](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/:has)로 처리하며, 이를 지원하지 않는 환경에는 기본 한 열 배치가 남는다.

## 보안·호환 검토

인증 원천은 서버 검증을 거친 `WebNovelsAuth.getActor().author`이며 Auth UUID·작가 ID·작품 ID·원고 UUID의 구분을 유지한다.
`/creator`, `/api/v2/creator/*`, 기존 DOM ID와 클래식 스크립트 순서를 보존했다. 작품 제목·필명·파일명은 안전한 텍스트 또는 기존 이스케이프 함수를 사용한다.
미리보기는 서버 발행 권한 검증을 대체하지 않는다. 공개본 수정·삭제·썸네일 변경은 기존 변경 검토 경로를 사용한다.
DB 마이그레이션·권한·기능 플래그·결제·PASS·SMTP·운영 데이터는 이 단계의 변경 대상이 아니다.

조사에는 기존 소스·테스트·설치된 도구와 공식 웹 API 문서를 사용했다. Codebase Memory의 프로젝트/범위 확인은 transport 오류로 사용할 수 없어 `rg`와 소스 읽기로 대체했다.
이번 화면 개편은 기존 엔진·모듈을 확장해 외부 패키지를 추가하지 않았다. 패키지 레지스트리·GitHub 구현 검색은 수행하지 않았다.

## 검증과 실제 인수의 구분

자동 검증 결과는 [R5 검증 기록](../../artifacts/ui-r5-verification-2026-10-31.json)에 기록한다.
신규 회귀 테스트 30개는 작품 관리 8개, 편집·발행 9개, 웹툰 비동기 처리·자원 해제 7개, 실제 HTML/CSS 구조 6개로 구성한다.
기존 작가·모달 DOM ID 154개와 모듈 로드 순서를 확인한다.

| 검증 | 결과 |
| --- | --- |
| `npm run build` | PASS — 릴리스 43개 명령과 Prisma 생성·TypeScript 컴파일 전체 종료 코드 0 |
| `tsc --noEmit` | PASS — 설치된 TypeScript CLI로 실행, 종료 코드 0 |
| R5 신규 회귀 | 30/30 PASS, 실패·건너뜀 없음 |
| 구문·CSS·HTML | JS 구문 9개, esbuild CSS 파싱, HTML 중복 ID·중첩 form·파싱 오류 검사 통과 |
| 보안·변경 검토 | 대상 11개 파일의 비밀값 패턴 0건, 서버·DB·엔진·원고 변환 변경 없음, diff 검사 통과 |
| 사용자 작업 | 기존 `gemini.md` 해시와 미추적 스킬 폴더 보존 |

추가 CSS 전송 크기는 원문 13,909바이트, gzip 2,982바이트다. 실제 네트워크·실기기 성능 측정 결과와 구분한다.

프로젝트 규칙에 따라 사용자 명시 요청이 없는 localhost·브라우저 검증은 수행하지 않는다.
실제 모바일 키보드, 320~1440px 화면, 200% 확대, 스크린리더, 운영 DB의 업로드·예약·검토 인수는 자동 VM/합성 DB 테스트와 구분한다.
전용 lint 명령과 커버리지 임계값 검증은 저장소에 없어 통과로 표시하지 않는다. 구문·타입·CSS 파싱·보안·diff 검사를 별도로 기록한다.

## 다음 개발 단계

**UI-R6: 관리자·계정·문의·정책 화면 개편**을 진행한다.

1. 관리자 메뉴를 작품·발행 변경 검토, 회원·작가, 베타 문의, 운영 연동으로 정리한다.
2. 공개본 수정·삭제·표지 변경의 현재 공개본/요청본 비교와 처리 상태를 명확히 표시한다.
3. 계정·문의·정책 폼과 표의 가독성, 오류·빈 목록·재시도, 키보드 조작을 R2 토큰에 맞춘다.
4. 결제·PASS 미계약 상태와 관리자 설정 입력 경로를 보존하고 실제 자격 증명이 없는 기능을 활성화하지 않는다.

이후 UI-R7에서 사용자 요청에 따른 실제 브라우저·모바일 인수와 Cloudflare 배포 결과를 확인한다.
기존 37단계의 SMTP·외부 베타·복원 인수는 별도 운영 과제로 남는다.
