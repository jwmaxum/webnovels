## 광고가 없을 때의 기본 흐름

광고 미연결·미충전·미확정·중단·만료 시 **포인트 구매**를 기본 대안으로 안내한다. 기본 충전상품은 사용자 요청대로 **10,000원 결제 → 10,000P**이며 회차 기본 가격은 100P다. 실제 회차별 차감액은 현재 서버 견적을 따른다. 광고가 없다는 이유로 무료권이나 포인트를 자동 지급하지 않는다.

독자는 `/reading-test`의 잠긴 회차에서 가격을 확인하고 포인트 구매 또는 보상 TEST 흐름을 선택한다. `/charging-test`에는 실제 서버가 판매 중인 상품 중 **10,000원·10,000P가 모두 일치하는 상품**을 명시적으로 선택하는 버튼을 추가했다. 다른 금액/보너스 상품을 기본 상품으로 간주하지 않는다. 해당 상품이 없으면 관리자 상품 등록 필요를 안내한다. 기존 관리자 충전상품 폼의 기본값은 10,000원·10,000P이며 최고 관리자가 저장해야 판매된다. 운영에 상품·주문·잔액을 자동 생성하지 않는다.

상품 선택은 결제나 적립이 아니다. 기존 OP-05의 버전 확인·명시적 주문·카드 서버 승인 또는 은행 거래 대조 후 한 번 적립하는 계약을 유지한다. 기본 상품의 10,000원/10,000P 조건과 다른 상품·소비의 원화 배분을 혼동하지 않으며, 기존 원장이나 실제 금액을 일괄 환산하지 않는다.

## 내부 TEST 증빙의 서버 검증

`OP06_INTERNAL_TEST_V1`은 별도 테스트 송신기를 위한 자체 프로토콜이다. Google SSV·실제 광고 완료나 확정 광고 매출이 아니다. 기본 제공자는 NONE이며 외부 업체 연결은 닫혀 있다.

서버 환경의 명시적 INTERNAL_TEST 채널·별도 256비트 키·키 ID·callback 게이트가 준비된 경우에만 테스트 증빙을 받는다. 공개 callback은 원본 UTF-8 본문(최대16KiB), Unix 시각(±300초), 키 ID와 HMAC-SHA256을 WebCrypto로 검증한다. 중복 JSON 키·이스케이프 별칭·다른 인코딩·변조된 바이트·잘못된 보상 수량/종류를 거절한다. 서명 검증 실패는 DB readiness 조회보다 먼저 끝낸다.

검증한 proof는 서버 내부 WeakSet 표식과 불변 객체로만 전달한다. 브라우저 로그인이나 `{verified:true}` 입력으로 callback을 대체할 수 없다. 서버에서만 provider binding과 본문 해시를 추가한 뒤 서비스 전용 RPC를 호출한다. 비밀·서명 원문은 응답·DB·Git·로그에 저장하지 않는다. 세션 조회에는 nonce·binding·증빙 원문·계정 ID가 없고, 관리자 목록에만 검증한 독자 Auth UUID를 제공한다. 시작 시 본인에게 전달하는 내부 challenge에는 서명할 수 있는 키가 없다.

DB는 세션 소유자·현재 활성 Auth/독자·nonce·채널/binding·완료 시각·보상 종류/수량을 다시 확인한다. provider+안정 channel+eventId를 전체 세션에서 한 번만 사용하고, 키 버전을 고유키 범위에 넣지 않는다. 같은 증빙은 결과만 재현하며 다른 세션/내용에 재사용하면 409다. request와 event의 지문은 SHA-256이다.

Google Ad Manager는 웹 SSV 지원을 명시하지만 이번 조사에서 웹 콜백의 서명·키·사용자/세션 매핑 계약을 확정하지 못했다. 모바일 AdMob의 ECDSA 규격을 웹에 대신 적용하지 않았다. GPT의 브라우저 보상 이벤트도 서버 증거로 사용하지 않는다. 실제 업체 계약 후 해당 채널의 공식 규격·샘플·도메인·키 회전을 인수해야 한다. [GAM 웹 보상형 광고](https://support.google.com/admanager/answer/9116812?hl=en), [GPT 공식 예제](https://developers.google.com/publisher-tag/samples/display-rewarded-ad), [모바일 SSV 구분](https://developers.google.com/admob/android/ssv)

## 세션과 권리의 정확성

세션은 시작 당시 정책·현재 공개본·안정 episode ID·제공자 조건을 고정한다. 광고 세션은 기본 5분, 증빙 유예10분, 보상은 **완료 증빙 시각부터24시간**이다. 관리자는 각각의 허용 범위 안에서 변경할 수 있고, 이미 시작한 세션의 조건은 유지된다. 참여는 사용자별 분당5건·한국시간 일일 기본20건으로 제한한다.

브라우저의 닫기/중단은 완료 여부를 증명하지 않는다. 닫기 이전 완료 증빙이 수신 유예 안에 도착하면 보상하고, 닫기 이후 완료는 거절한다. 세션 참여 기한이 지나도 증빙 유예 동안은 새 세션/nonce를 만들지 않는다. 이미 GRANTED인 세션은 늦은 NO_FILL/REJECTED·닫기·정확한 재전송으로 회귀하거나 유효기간이 늘어나지 않는다.

광고권과 캠페인권은 구매 entitlement와 별도 불변 기록이다. `AD_REWARD`·`CAMPAIGN_FREE`를 구분하고 grant ID·만료 시각을 표시한다. 현재 무료 범위·구매권·가격0 무료가 임시권보다 우선한다. 이미 열람 가능한 회차에 불필요한 광고를 시작하지 않는다.

기존 `op04_access`를 확장해 소설 본문·웹툰 패널·회차 목록·견적·구매가 같은 만료 판정을 사용한다. 임시권이 있으면 0P이며 구매 영구권을 만들지 않는다. 만료된 임시권의 옛 0P 구매 영수증만 다시 보내면 `REWARD_EXPIRED`로 거절한다. 새로운 정상 권리나 기존 구매권이 있으면 그 현재 권리는 유지한다.

공개 head가 승인 변경되어도 권리는 안정 episode ID를 유지하고 현재 공개본을 읽는다. 이후 비공개·제재·등급/소유권 제한은 기존 본문/패널의 현재 적격성 검사를 계속 적용한다. 증빙이 있다고 제한된 원고나 Storage 주소를 공개하지 않는다. 광고권·캠페인권은 지갑 CREDIT·유상 구매·작가 확정 수익이 아니며 기존 충전 lot·환불 예약·구매 권리를 수정하지 않는다.

## 스키마와 수명주기

`database/launch/021_ad_rewards_test.sql`은 **미적용 준비 SQL**이다. 019·020 원본 파일, 원래 private OP-04 RPC 본문/소유자/ACL, 기존 commerce 테이블의 행과 스키마 ACL을 보존한다. 공통 access 함수와 public wrapper의 OID를 유지하면서 필요한 의미만 확장한다. 원래 구매의 지갑→회차 잠금 순서와 환불 예약 보호를 유지한다.

새 비공개 config/policy/session/event/grant/receipt/audit는 명시 ACL·RLS를 적용한다. 서비스 역할도 직접 테이블/보조 함수에 접근하지 못하고 현재 계정·최고 관리자 권한을 재검증하는 RPC만 실행한다. 정책·증빙·권리·영수증·감사는 불변이며 임의 삭제/수정 API를 만들지 않는다. 새 시퀀스·가짜 회원·운영 광고·충전 상품은 seed하지 않는다. 초기 정책은 비활성 기본 설정뿐이다.

클라이언트는 사용자별·회차별 메모리에 원래 미확인 요청 ID/내용을 유지한다. 다른 회차를 다녀와도 같은 요청으로 확인하고 계정 변경·로그아웃은 전부 폐기한다. localStorage에 권리·증빙·잔액을 저장하지 않는다. 부모 화면 재렌더·이동 시 child 세대와 quote identity를 폐기해 늦은 응답/부모 알림을 막는다. 검증한 grant 뒤에도 포인트 구매를 호출하지 않고 현재 회차 메타데이터를 다시 조회한다.

기존 Author/Creator·원고 revision·공개본 승인·정산 개인정보 계약과 무료 서비스 상태는 유지한다. 실제 개인정보 접수·PASS/PG·SMTP·복원 인수는 이번 광고 TEST 성공으로 개방하지 않는다.

독립 리허설 `npm run verify:op06`은 새 합성 DB에서 광고 NONE의 10,000원·10,000P 충전/입금 대조와 100P 구매, 웹툰의 서버 증빙·재현·타 계정 차단, 임시권 만료·옛 0P 영수증 차단, 별도 캠페인, 닫기 전 완료와 지연 증빙을 대조한다. 운영 환경·네트워크·실제 제공자 없이 실행하며 보고서는 Git 제외 `scratch/op06-sandbox/report.json`에 남긴다.

새 의존성은 없다. 기존 소스·관련 스킬·공식 웹·공식 GitHub GPT/Tink 샘플을 조사했고, 광고 전용 MCP는 발견하지 못했다. npm 웹 패키지 페이지는403으로 직접 확인하지 못했으며 채택하지 않았다. 그래프 조회는 연결 실패/빈 인덱스로 관련 canonical 소스를 직접 검색했다. 검색하지 못한 범위를 완료한 것으로 보고하지 않는다.

실제 광고 송출/업체 SSV·실결제·은행 송금·운영 SQL/플래그·PostgreSQL 다중 연결·브라우저/실기기 인수는 실행하지 않는다. 없는 린트 명령이나 VM 소스 미계측 커버리지를 수치 통과로 보고하지 않는다. 합성 성공과 운영 개방은 구분한다.
