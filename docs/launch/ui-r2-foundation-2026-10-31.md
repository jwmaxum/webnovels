# UI-R2 — 공통 색상·서체·컴포넌트 적용

작성일: 2026-10-31 · 기준: [R1 확정 명세](../design/ui-r1/README.md)

R1에서 확정한 밝은 바탕과 선명한 글자 대비를 실제 서비스의 공통 스타일에 연결했다.
이번 단계는 공통 디자인 적용이며, 독자 상단 탐색·홈 재배치는 R3, 상세·뷰어는 R4, 작가 작업면 재배치는 R5에서 진행한다.

## 적용 내용

| 대상 | 적용 |
| --- | --- |
| `public/css/design-tokens.css` | R1의 47개 확정 토큰 보존, 버튼·링크·선택·입력 컨트롤의 역할 변수 추가 |
| `public/styles.css` | 기존 변수와 클래스의 호환 연결, UI 본문 16px·보조 14px, 제목 무게 정리, 주요 버튼 단색 적용 |
| 공통 상태 | 일반/hover/선택/focus/disabled/aria-invalid/aria-busy 표현, 탭 선택 밑줄과 상태 문구 유지 |
| 입력·알림 | 입력 경계와 포커스 구분, 성공·오류·안내 문구의 진한 색상, 임시저장 충돌 안내 |
| 작품 카드 | 표지 2:3, 두 줄 제목, 가독성 높은 제목·작가 정보, 카드 hover 발광·이동 제거 |
| 기능별 CSS | 무료 베타 안내·지원함·성장 화면·웹툰 업로드·정책 화면의 색상 역할 연결 |
| `public/fonts/suit-v2.0.5` | 공식 SUIT Variable WOFF2 자체 제공, 원본 라이선스·SHA-256 기록 |
| HTML 4종 | 공통 토큰을 기존 CSS보다 먼저 로드, 폰트 preload, 변경 자산 버전 갱신 |
| 독자 JS | 기존 배지·별명/비밀번호 안내의 색상만 토큰으로 연결, 판정 및 요청 동작은 유지 |

원본 Primary 500 `#F55DD6`은 브랜드 팔레트로 유지한다. 흰 글자 주요 버튼은 Primary 800 `#8F357C`를 사용한다.
흐린 보조 설명을 피하기 위해 일반 크기 설명은 `--text-secondary`를 사용하고, `--text-tertiary` 원본값은 보존한다.
성공 버튼의 배경 역할은 `--action-success`로 분리해 독자 다크 테마의 밝은 성공 문구 색이 버튼 배경을 바꾸지 않게 했다.

## 호환·보존

- `--bg-main`, `--bg-surface`, `--border-color`, `--cdg-pink`, 기존 브랜드 변수는 제거하지 않고 새 역할에 연결했다.
- `/creator`, `CreatorDraftEditor`, `creator-*` ID, API·Auth·소유권·원고 revision·발행·공개 후 검토 계약을 변경하지 않았다.
- 독자 명조/고딕 선택에 필요한 Noto Sans KR·Noto Serif KR 로드는 유지했다. UI용 Outfit 혼용을 제거했다.
- `--reader-font`·크기·행간·읽기 위치와 Word의 문단·굵기·기울임·정렬 렌더링을 유지한다. 전역 `*` 규칙으로 본문 글꼴이나 정렬을 강제하지 않는다.
- 다크/OLED/세피아 뷰어 안에서는 입력·선택·상태 색상을 별도 지정한다. 설정 모달의 테마 표본은 실제 테마 색을 유지한다.
- 숨김 모달·무료 베타 비활성 메뉴·역할별 접근 표시, 웹툰 본문 이미지 비율을 보존한다.
- DB·플래그·실제 계정·작품·원고와 서비스 비밀 설정은 변경하지 않았다. 새 패키지나 외부 실행 스크립트도 추가하지 않았다.

## 조사·검증

`search-first`로 기존 CSS·폰트·로더·검증 도구를 조사하고 기존 `parse5`와 `esbuild`를 재사용했다.
Codebase Memory는 등록 프로젝트가 없고 coverage 조회도 실패하여 지정 소스의 읽기·검색으로 대체했다.
새 의존성이 필요 없어 npm/PyPI 패키지 검색·설치를 수행하지 않았다.

색상 판단은 [W3C 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html),
폰트 로드는 [MDN font-display 문서](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@font-face/font-display)를 참고했다.

| 검증 | 결과 |
| --- | --- |
| `node --test scripts/verify_ui_r2.test.mjs` | 5개 통과: 원본 토큰·대비, 독자 테마·원고 서체, 정적 자산·폰트, CSS·숨김·이미지 계약, 동적 상태 표현 |
| 전체 릴리스·빌드 | 전 40개 릴리스 명령 통과. 26단계부터 권한 재실행 후 Prisma 생성·TypeScript 빌드 통과 |
| 타입 검사 | `build:compile`의 `tsc` 통과 |
| 보안·diff | HTML 4종 동작 속성·독자 처리 로직 보존, 비밀 패턴 검사·변경 범위 확인 통과 |

[검증 기록](../../artifacts/ui-r2-verification-2026-10-31.json)을 보관했다. Windows 샌드박스의 기존 정션 테스트 `EPERM`은 테스트를 바꾸지 않고 26단계부터 로컬 권한으로 재실행해 해소했다. 앞서 통과한 25단계까지의 결과와 나머지 전 단계 결과를 합쳤으며 실패 테스트를 생략하지 않았다.

R2 테스트를 `test:ui-r2`와 전체 `test:release`에 연결했다. CI에서도 새 폰트·토큰 계약을 확인한다.
첫 push의 원격 CI에서는 기존 20단계 감사로그 테스트가 동일 시각 이벤트의 UUID 정렬을 인과 순서로 가정해 실패했다.
운영 SQL·결제 처리를 변경하지 않고 생성 이벤트의 유일성을 확인하도록 테스트를 수정했다.
트랜잭션 시각을 고정해 같은 시각의 생성·승인요청·관측 이벤트가 모두 보존되는 회귀 테스트를 추가했고, 20단계 25개 테스트가 통과했다.
독립 lint/coverage 명령은 저장소에 없으며 이를 실행한 것으로 보고하지 않는다. CSS 문법은 esbuild로 점검한다.
저장소 규칙에 따라 localhost·브라우저를 실행하지 않았다. 정적 대비 검증을 실제 브라우저 접근성 인증으로 간주하지 않는다.
실제 폰트 로딩 시간·모바일 키보드·200% 확대·화면별 줄바꿈·서비스 배포 인수는 별도 확인 대상이다.

## 다음 단계 — UI-R3 독자 홈·작품 탐색

1. PC 독자 화면을 상단 탐색·검색 중심으로 전환한다. 작가·관리자의 업무 메뉴와 권한 경로는 유지한다.
2. 홈을 실제 공개 작품·이어서 읽기 중심으로 구성한다. 작품이 적으면 섹션을 줄이고 가짜 작품이나 통계를 추가하지 않는다.
3. 웹소설·웹툰을 같은 계층으로 배치하고 검색·장르·연재/완결·정렬을 동일한 방식으로 제공한다.
4. 검색 조건의 URL query, 뒤로가기·공유 링크, 빈 상태·불러오기 실패·재시도를 유지한다.
5. PC 최대 6열·모바일 2열을 기준으로 제목 가독성과 좁은 화면을 점검한다. 실제 브라우저 인수는 명시 요청 시 수행한다.
6. 탐색·읽기 진입·인증/권한·라우팅 회귀와 빌드를 통과한 뒤 독립 커밋·push한다.

큰 화면 구조가 바뀌는 R3에서는 남아 있는 레거시 홈의 인라인 색상·장식 규칙을 함께 정리한다.
기존 [37단계 운영 인수](../../improve37.md)의 SMTP·복원·PASS/결제 준비는 UI 단계와 구분해 관리한다.
