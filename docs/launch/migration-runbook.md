# 2단계 마이그레이션·백업·복원 실행 절차

작성일: 2026-09-23. 운영 미적용. 로컬 검증과 실제 Supabase 적용을 분리한다.

## 현재 판정

- 로컬 SQL·격리 PostgreSQL 실행 검증은 구현했다.
- 관리 API 재확인(2026-09-23): 읽기 전용 `node scripts/p0_schema_audit.cjs`가 HTTP 401로 중단됐다. 실DDL/정책·기존 Auth 매핑·백업을 확인할 수 없어 실제 Supabase 변경은 수행하지 않았다.
- 이 문서의 순서는 실행 매뉴얼이며 운영 실행 완료 기록이 아니다.

## A. 읽기 조사와 적용 전 조건

1. 유효한 SUPABASE_ACCESS_TOKEN 또는 안전한 DB 관리 접속을 준비한다. 비밀값을 채팅/문서/Git에 쓰지 않는다.
2. `node scripts/p0_schema_audit.cjs`로 DDL·제약·RLS·RPC·뷰·publication을 읽는다. 결과 scratch/p0 파일은 비공개로 관리한다.
3. [000_integrity_audit.sql](../../database/authoring/000_integrity_audit.sql)을 읽기 전용으로 실행한다. 실제 열/타입과 다르면 수정 후 다시 검증한다.
4. 계정 중복·Auth 연결·잘못된 FK·회차 중복/결번·원고 위치를 확인한다. 연결 안 된 계정이나 결번을 자동 삭제/수정하지 않는다.
5. authoring 스키마/인덱스/버킷 이름 충돌을 확인한다. CREATE IF NOT EXISTS는 기존 객체가 올바른 구조임을 증명하지 않는다.
6. SEC-R01의 공개 민감 열/RPC/Storage 권한을 우선 점검한다. 이 단계의 새 private 스키마만으로 기존 public 노출이 해결되었다고 판단하지 않는다.

## B. 실제 백업

- 승인된 유지보수/쓰기 제한 구간 또는 일관된 스냅샷 기준 시점을 확보한다. DB와 파일 목록의 기준 시각을 맞춘다.
- DB: 스키마·데이터·제약·함수·정책·필요한 역할/권한·Auth 연관 정보를 지원되는 백업 방식으로 확보한다. 복원 대상은 별도 격리 프로젝트다.
- Storage: DB 객체 메타데이터뿐 아니라 실제 파일 바이트도 백업한다. 버킷/객체 경로/크기/해시/버전·보관 위치를 매니페스트에 기록한다.
- 외부 키·메일 설정·도메인·예약 설정은 보안 저장소에서 별도로 보관한다. SQL 덤프에 비밀값이 포함될 수 있으므로 Git 업로드를 금지한다.
- [백업 매니페스트 양식](backup-manifest.example.json)은 빈 템플릿이다. checksum·개수·복원 시각을 실제 결과로 채우기 전 백업 완료로 표시하지 않는다.

## C. 격리 복원 검증

1. 운영에서 분리된 DB/Auth/Storage를 준비한다. 메일·외부 결제·광고·예약 발행은 비활성화한다.
2. DB를 복원하고 작품·회차·계정·신고·원장 수, 원고 해시, FK, 계정 연결, 정책을 대조한다.
3. 실제 파일을 복원하고 매니페스트의 객체 수·크기·해시를 대조한다. 새 URL을 통한 공개 접근도 점검한다.
4. 복원 소요 시간·실패·누락·재시도·담당자를 기록한다. 중간 실패 때 동일 기준선으로 재개 가능한지 확인한다.
5. 불일치가 있으면 운영 적용을 중단한다. 원본 DB를 테스트 대상으로 초기화하지 않는다.

## D. SQL 적용 순서

기존 세대별 database/*.sql 전체 실행은 금지한다. 이 절차는 별도 DB 관리 도구의 같은 세션에서 수행한다.

1. 실제 스키마와 대조한 기존 [P0 001 확장](../../database/p0/001_expand_identity_content.sql)을 적용한다. 누락 Auth 연결 열과 보호 본문 복제를 포함한다. 이미 적용된 경우 현재 버전/제약을 먼저 확인한다.
2. 적용/복원 검토가 끝난 뒤에만 세션에 `SET webnovels.authoring_apply_verified = 'true'`를 설정한다. 플래그는 검증을 대신하지 않는다.
3. [authoring 001](../../database/authoring/001_authoring_foundation.sql): 고정 초안 ID·불변 버전·공개본·예약·파일 참조·보관 정책 생성.
4. [authoring 002](../../database/authoring/002_private_storage.sql): 충돌 없는 두 private 버킷과 제한 정책 생성. 같은 이름의 public 버킷이 있으면 전체 중단하며 기존 버킷을 임의 변경하지 않는다.
5. [authoring 003](../../database/authoring/003_verified_identity_link.sql): 검증된 계정 연결 함수와 최소 service_role 컬럼 권한 생성.
6. 적용 기록, 기존 데이터/파일 해시, anon/authenticated 직접 접근 차단, 함수 권한, 재적용 가능성을 확인한다.
7. 세션 검토 플래그를 RESET한다. 서버에 영구 환경값으로 배포하지 않는다.

각 파일은 BEGIN/COMMIT 트랜잭션이다. 실패하면 ROLLBACK 후 원인을 해결하고 같은 파일을 재실행한다. 스키마는 추가되지만 원고/기존 계정 ID는 자동 변환하지 않는다.

## E. Auth 연결과 원고 이관

- 초기 최고 관리자는 기존 계정 소유 확인·Auth 복구·DB 운영자 검증 증거를 확보한 뒤 수동으로 최초 연결한다. 신원 확인 없이 기존 이메일만 매칭하지 않는다.
- 이후 `authoring.link_verified_identity`를 운영자가 매개변수 바인딩으로 호출한다. 입력값을 문자열 결합 SQL로 만들지 않는다.
- profile_id는 기존 ID의 정규화된 문자열이다. 함수는 기존 UUID/숫자 ID를 보존한다.
- 재시도는 동일 연결을 유지하며 다른 UUID와 충돌하면 중단한다. 충돌 건은 별도 조사한다.
- work_state와 초안/공개본/예약 이관은 [데이터 계약](data-contract.md)의 보존 순서를 따른다. 실제 데이터 매핑이 확정되기 전 자동 backfill을 실행하지 않는다.
- 프로필 상태를 자동 APPROVED로 바꾸거나 관리자 역할을 부여하지 않는다.

## F. P0 잠금 및 프론트 전환과의 관계

`database/p0/002_lockdown_after_cutover.sql`은 **이번 2단계에서 실행하지 않는다.** 모든 활성 프론트/API 전환과 권한 검증이 완료되는 10단계의 별도 작업이다.

- 기존 P0 public 잠금은 authoring 별도 스키마에 대한 grant를 넓히지 않는다.
- authoring 마이그레이션은 P0 expanded→locked 전환이나 P0_API_ENABLED 활성화를 수행하지 않는다.
- 3단계 서버가 새 스키마에 접근할 때는 명시적 인증/소유권 검증과 좁은 서버 전용 API를 추가한다. 새 스키마를 브라우저에 직접 공개하지 않는다.
- 공개본 서비스 전환은 기존 public 본문을 새 publication_heads와 비교한 뒤 수행해야 한다. 두 경로를 서로 다른 공개 내용으로 운영하지 않는다.

## G. 실패·되돌림

새 스키마 적용 실패는 트랜잭션 롤백 후 원본을 유지한다. 새 데이터가 들어오기 시작한 뒤에는 스키마 DROP으로 롤백하지 말고 쓰기를 제한하고 검증된 백업/이관 기준으로 전진 복구한다. immutable 트리거를 일반 앱 권한으로 끄지 않는다.

역할/RLS 오류를 해결하려고 민감 데이터를 PUBLIC/anon에 재공개하지 않는다. 실제 백업 복원이 필요하면 별도 프로젝트에서 데이터 무결성을 먼저 확인한다.

## H. 이번에 완료한 검증과 남은 조건

- 합성 레거시 스키마(integer ID / UUID reader·bigint 콘텐츠 변형)에 실제 SQL을 실행했다.
- 재적용, 중간 트랜잭션 실패 후 재시도, 이전 ID·본문 보존, 중복/교차 작품 거절, 충돌 저장, 불변 공개본, Storage restrictive 정책, 계정 연결 원자성을 검사했다.
- 임베디드 PostgreSQL datadir를 덤프한 뒤 다른 인스턴스에 복원하여 원고·버전·Storage 메타데이터를 대조했다.
- 실제 Supabase DDL 적용, 실제 Auth 이관, 실제 파일 바이트 백업/복원, 다중 연결 동시성, Storage HTTP/서명 URL·Realtime는 **미검증**이다.
- 로컬 복원은 운영 백업 검증을 대신하지 않는다. DEP-01/02/04/05/06/10 확인 후 실제 격리 환경 검증이 남아 있다.
