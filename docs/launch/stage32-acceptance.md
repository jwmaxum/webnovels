## 공개 운영의 남은 작업

현재 기존 본문 두 경로의 불일치는 78건이다. `database/p0/001_expand_identity_content.sql`은
어느 본문이 원본인지 임의로 고르지 않도록 중단한다. 설치된 작가 마이그레이션은
001/003/004/005/006이며, 파일·예약·웹툰·서식·발행 후 검토의 운영 DB 설치가 남아 있다.
따라서 메뉴에서 저장본 미리보기는 제공하지만 실제 발행·예약·업로드가 활성화됐다고 안내하지 않는다.

DB 제품이나 프로젝트를 교체할 필요는 없다. 기존 자료 전체 이관을 신규 연재의 전제에서
분리하려면 **동일 DB에서 신규 작품 공개 범위를 명시하는 전환 코드**가 먼저 필요하다.
과거 회차를 삭제하거나 기존 P0 검사만 제거하는 방식은 사용하지 않는다.

## 33단계 구현 계약 — 기존 DB 신규 연재

1. 검증 시점에 존재하는 작품·회차를 명시적 ID로 보존·격리하고, 검증된 작품 생성 경로에서
   새로 생성한 작품만 신규 공개 대상으로 등록한다. 날짜·ID 크기·클라이언트 상태로 추정하지 않는다.
2. P0 확장 대안을 별도 마이그레이션으로 작성한다. 과거 두 본문을 수정하지 않으며 신규 공개본의
   불변 버전·head만 독자에게 전달한다. 기존 원고 편집·백업은 유지하고 과거 공개본 편집에서
   미검토 내용을 신규 대상으로 승격시키는 우회를 차단한다.
3. 목록·검색·작품/회차 metadata RLS, 서비스 역할 API, 본문, 이미지, 표지, 공유 페이지와
   sitemap이 같은 공개 범위를 사용하도록 한다. 탐색 기능을 끄더라도 옛 본문 fallback으로
   돌아가지 않는다. 관리자/작가의 소유 원고 조회와 독자 공개 조회를 구분한다.
4. 무료 연재 의존성 002→007→008→009→010→011 및 012→013→014→015→021→022를
   검토·격리 적용하고 마지막에 공개 범위 정책을 적용한다. 유료화·실험·과거 복구의 별도
   의존성은 필요한 경우에만 추가한다. 마이그레이션 표식만 채워 넣지 않는다.
5. 같은 백업에서 원본 행·초안 6개·버전 21개·Auth 매핑을 대조하고, 재시도·계정 간 접근·
   첫 발행·공개 후 변경 검토·동시 편집·rollback을 검증한다. 실제 적용 직전 새 백업과
   원본 전체 행 비교로 중간 변경을 탐지한다.
6. Cloudflare Images, 비공개 `authoring-originals`/`authoring-covers`/`authoring-webtoons`
   Storage, 서명 URL과 예약 Worker Cron을 연결·인수한다. Pages push만으로 예약이
   실행된다고 판단하지 않는다.
7. 제한 계정 인수 뒤 관련 기능을 순서대로 켠다. 되돌리기는 공개·발행·Cron을 먼저 닫고,
   새로 저장된 원고·발행본·검토 기록을 보존한다. 오래된 백업으로 덮어쓰지 않는다.

기존 32단계의 별도 hosted 복원 요구는 운영 DB 교체 요구가 아니다. 실제 복구 능력·제공자
역할·Storage 검증을 위한 인수 항목이다. 별도 대상이 확보되지 않은 동안 실행 가능한
로컬 검증 결과와 실제 hosted 인수 미실행을 계속 구분한다.
