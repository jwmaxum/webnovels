# 웹소설 웹툰 후속 단계별 개발계획

기준일: 2026-10-08 KST. [서비스 점검](service-audit-2026-10-08.md)의 발견을 실행 순서와 완료 조건으로 정리한다. 기존 [1~13단계](../../improve.md)의 구현·운영 기록을 보존하며, 아래 14~21단계는 새 계획이다. 문서 작성 자체가 구현 완료·운영 적용·출시 승인을 뜻하지 않는다.

첫 목표는 작가가 작품을 직접 만들고 안전하게 연재하며 다른 독자가 읽는 흐름을 완성하는 것이다. 이후 웹툰 제작·열람을 확장하고, 실제 사용 검증을 거쳐 수익화한다. 모든 단계는 관련 계약과 실제 소스부터 읽고 구현한다.

## 1 개발 순서와 출시 묶음

| 19 | 실제 기기·운영 복원·제한 베타·출시 판정 | 출시 대상 유형의 14~18 및 기존 10~12 게이트 | 2주 | QA·운영·제품 | 품질 코드·로컬 검증 완료 / 실제 복원·기기·베타 대기 |

| 21 | 신인 발견·개인화·IP 확장 실험 | 검증된 이용 이벤트·콘텐츠 공급·운영 여력 | 최초 실험 2~4주, 이후 반복 | 제품·데이터·편집 | 미착수 |

기간은 개발자 2명, QA 0.5명, 제품/디자인·운영의 참여를 가정한 작업 규모 추정이다. 외부 계정·메일·업체 계약·정책 검토·데이터 원본 확인의 대기시간은 제외한다. 14~20단계를 직렬 수행하면 약 13~21주이며, 14단계에서 실제 잔여 범위를 확인한 후 다시 추정한다. 확정 일정이나 출시일로 사용하지 않는다.

출시 묶음은 다음과 같다.

- **무료 웹소설:** 14~17단계와 19단계의 소설 인수, 기존 10~12단계 조건을 통과하면 별도 출시 판정한다. 18단계를 기다릴 필요는 없다.
- **무료 웹툰:** 18단계 이후 16·17단계의 웹툰 영향 범위와 19단계를 다시 인수한다. 기존 소설의 회귀도 포함한다.
- **수익화·성인:** 20단계에서 기능별 별도 출시를 판정한다. 성인 콘텐츠는 선택한 경우에만 본인확인·등급·본문/이미지 접근 조건을 추가한다.

소설·웹툰 동시 오픈이 사업상 필수라면 첫 출시의 19단계에서 두 유형을 모두 통과해야 한다. 기존 유료 권리·성인 데이터·수익 이력을 임의 무료화하거나 삭제하지 않는다.

## 2 14단계 최신 상태·공개 전환 준비·작가 연재 편의

상세 실행 문서: [improve14.md](../../improve14.md). 기존 2~12단계의 남은 작업을 이 단계에서 재분류하며, 과거 완료 근거를 다시 실행한 것처럼 기록하지 않는다.

2026-10-08 작가 편의 제안을 반영했다. 기존 Cloudflare/JS/Supabase와 DraftEngine을 유지하고 비독점 연재·외부 링크·권리 확인 진술을 첫 스프린트에서 추가한다. [추가 설정 계약](creator-distribution-contract.md)은 기존 bigint 작품/작가 ID와 Auth UUID를 구분하고, 독점 상담 희망을 실제 계약·오리지널 인증과 구분한다. 스택 전면 이전·원고 형식 교체·작품 테이블 재생성은 이 단계의 범위에 넣지 않는다.

작가 편의의 4개 스프린트는 **인증/등록 기반 재사용과 비독점 설정 → 첫 연재/자동 저장 보완 → 독자 UI와 신뢰 가능한 지표 → 작가 통계·성장 후보 검증**이다. 각 1~2주 규모의 개발 가정이며 전체 소설/웹툰 운영 오픈·자동 승격·후원의 4주 완료를 보장하지 않는다. 공개 전환·백업·실환경 인수의 차단 조건은 별도로 유지한다. 첫 로컬 구현의 운영 적용은 아직 대기다.

작업은 최신 커밋·배포 ID·적용 SQL·Auth 연결·기능별 준비 상태를 하나의 근거 표로 맞추는 것으로 시작한다. 보류 본문 78건과 그중 웹툰 이미지 회차의 원본을 검토하고, 확인된 공개본만 전환하는 정책을 확정한다. 최신 백업과 격리 Supabase/Storage 복원, 구 직접 DB/RPC 폐쇄, Auth·메일·callback·Images·Cron 설정을 이어 검증한다.

**완료 조건:** 준비된 기능과 미준비 기능을 서버·화면·문서에서 동일하게 구분하고, 다른 작가 원고/파일 접근이 거절되며 원본·계정·권리·감사 데이터가 보존된다. 공개 전환의 실제 증거가 없으면 다음 단계의 로컬 개발만 진행하고 운영 활성화는 보류한다.

검증: 관련 `test:p0`, `test:auth`, `test:naming`, `test:authoring-schema`, `test:launch`, 전체 출시 회귀·타입 검사. 실제 DB/RLS/Storage·복원·호스팅 검증은 별도 환경과 결과로 기록한다.

## 3 15단계 작가 첫 연재 완성

2026-10-09 상태: [실행 기록](../../improve15.md)과 [첫 연재 계약](creator-first-serial-contract.md)에 따라 최대 대기 자동 저장·공개 준비 체크리스트·선택 입력·게시 재확인·보관 사본 복사를 구현하고 로컬 회귀를 통과했다. 아래 실환경 완료 조건은 별도 인수 대기다.

대상은 `creator-works.js`, `creator-editor.js`, `creator-files.js`, `creator-publications.js`, 관련 서버 API·증분 SQL이다. [작품](creator-works-contract.md), [원고](creator-drafts-contract.md), [파일](creator-files-contract.md), [게시](creator-publication-contract.md) 계약을 확장한다.

- 제목만으로 비공개 생성하는 현재 흐름을 유지하고 작성 재개·공개 준비 체크리스트를 제공한다. 이 단계의 실제 제공 유형은 웹소설이며 웹툰은 18단계 완료 전 준비 중으로 구분한다.
- 14단계의 비독점 설정과 외부 링크를 공개 준비 흐름에 연결한다. 플랫폼 이용/유통 약관의 버전·명시적 동의·권리 범위는 별도 검토하며 단순 권리 확인 진술을 전자 계약으로 전환하지 않는다.
- 기존 글자 수·집중 모드·IndexedDB 및 2.5초 debounce 저장을 활용한다. 연속 입력에는 최대 30초 대기를 보완하되 한글 조합·seq·revision·멱등키·실행 중 sync·충돌을 존중한다. 저장할 변경이 없으면 서버 저장을 반복하지 않는다.
- 장르·태그를 선택 UI와 canonical 코드로 정리한다. 공개 전 소개·등급·권리·AI 표기·첫 회차를 확인하며 저장과 공개를 구분한다.
- TXT/DOCX 다중 가져오기·표지·내보내기를 같은 소유 작품과 초안 revision으로 연결한다. 변환 검토, 원본 보존, 파일별 재시도·취소를 유지한다.
- 미리보기·즉시 공개·예약·철회·공개본 수정에서 같은 버전이 사용된다. 발행 후 독자 링크와 다음 원고를 제공한다.
- 브라우저 종료·연결 실패·서버 충돌·다른 기기 수정·로그아웃에서 원고를 보존한다. 준비 중 문구는 실제 가능한 다음 작업으로 연결한다.

**완료 조건:** 신규 작가 A의 `작품 생성 → 첫 원고 → 표지/정보 → 미리보기 → 공개 → 독자 B 열람 → 다음 원고 → 기기 재접속 복구`가 실환경에서 통과한다. 작가 C·일반 관리자는 A의 비공개 원고에 접근할 수 없다. 재전송·동시 저장으로 중복 작품/회차나 원고 손실이 발생하지 않는다.

검증: `test:naming`, `test:auth`, `test:creator-works`, `test:drafts`, `test:files`, `test:publication`, 타입 검사. 실제 기기 인수는 별도 명시 요청에 따라 수행한다.

## 4 16단계 독자 탐색과 읽기 개선

대상은 `reader.js`, `reader-hub.js`, `continue-reading.js`, `router.js`, HTML/CSS, `stage8-api.mjs`, 카탈로그/활동 SQL이다. [독자 연결 계약](creator-reader-operations-contract.md)을 따른다.

2026-10-09: [실행 명세](../../improve16.md)와 [독자 탐색 계약](reader-discovery-contract.md)에 따라 로컬 구현·검증을 완료했다. 서버 카탈로그 페이지, 실제 공개 회차 이동, 공개본별 문단 위치, 계정/응답 경합 보호, 공개 비독점 링크를 추가했다. [검증 기록](../../artifacts/stage16-reader-discovery-verification.json)을 참조한다. 신규 013 SQL의 운영 적용과 기본 false인 발견 플래그 활성화·실기기 인수는 별도다.

- 웹소설/웹툰 탐색, 랭킹·신작·완결을 목록 URL로 제공한다. 필터·정렬·페이지·뒤로가기 상태를 복원한다.
- 서버 검색·cursor 페이징을 제공하고 홈 요약·작품 상세·회차 목록을 분리한다. 총 작품/회차 일괄 응답에 의존하지 않는다.
- 편집 추천과 실제 인기 순위를 분리한다. 인기에는 대상 기간·집계 시각·고유 이용자/중복 제외 기준을 붙인다. 표본이 작으면 랭킹을 과장하지 않는다.
- ‘최신 등록’, ‘처음 공개’, ‘최근 연재’를 분리하고 실제 공개 회차를 기준으로 첫 화·이전·다음 화를 결정한다.
- 위치 정보는 소설 문단 ID+상대 위치, 웹툰 패널 ID+상대 위치를 후보로 설계한다. 공개본 버전 변경 시 안전한 대체 위치를 제공한다. 열 때 기존 진행률을 0으로 덮어쓰지 않는다.
- 본문 영역의 진행률과 완독 기준을 사용한다. 회차 요청의 늦은 결과·화면 이동·계정 전환을 취소/무시한다.
- 공개 작품의 비독점 외부 연재 배지는 전용 공개 응답으로 표시한다. 작가 설정·비공개 작품을 공개 데이터로 우회하지 않고 정확한 플랫폼 링크·등급·제재 정책을 따른다.
- 조회/구매 전환/완독은 정의·분모·표본·집계 시각을 함께 표시한다. 전체 페이지 scroll depth를 완독률로 사용하지 않는다. 고유 독자·중복/봇 제외·동의/보존 기간을 정의하고 결제 지표는 검증된 거래 원장이 준비된 뒤 제공한다.
- 링크·버튼·아이콘 이름·키보드 포커스, 상태 안내·동작 감소, 카드 정보·공유 메타데이터를 개선한다.

**완료 조건:** 검색/링크 → 상세 → 첫 공개 회차 → 다음 공개 회차 → 다른 기기의 위치 복원이 통과한다. 회차 번호가 불연속이어도 이동하고, 댓글/추천 추가로 완독률이 변하지 않는다. 비공개·제재·등급 제한이 탐색·직접 링크·본문에서 일치한다. 빈 결과와 장애를 구분한다.

검증: `test:operations`, `test:publication`, `test:stage11`, 관련 URL/페이지·요청 경쟁·위치 복원 회귀. 성능 목표는 실제 기기별 p75 LCP ≤2.5초·INP ≤200ms·CLS ≤0.1이며 실험실 검사와 이용자 측정을 구분한다. [측정 기준](https://web.dev/articles/vitals).

## 5 17단계 관리자 운영 업무 완성

2026-10-09 상태: [실행 기록](../../improve17.md)과 [관리자 업무 계약](admin-workflow-contract.md)에 따라 사건 근거·담당·기한·중복 참조, 원조치와 별도 이의제기 후속 조치, 계정 지원, 기간별 편집 추천, 통합 감사와 제한된 초안 열람을 구현했다. 새 플래그는 비활성이며 아래 실환경 완료 조건은 인수 대기다.

대상은 `admin-console.js`, `admin-operations.js`, `admin-console-api.mjs`, `stage9-api.mjs`, `stage9-appeal-api.mjs`, 관련 SQL이다. [관리자 계약](admin-operations-contract.md)과 [후속 메뉴 복구](admin-console-rollout.md)를 함께 따른다.

- 작품/회차는 콘텐츠 탭으로, 신고/검수/이의제기는 사건 처리 탭으로 연결한다. 기존 URL·권한·각 사건 종류는 보존한다.
- 담당자·우선순위·처리 기한·근거·사유·통지·재검토를 연결한다. 중복 신고 병합은 원본 사건을 보존하는 참조 방식으로 설계한다.
- 계정 지원의 실제 복구 절차와 권한 회수·다른 기기 반영을 검증한다. 가상 계정 도구는 최고 관리자 시험 업무로 표시한다.
- 큐레이션의 기간·위치·순서·미리보기·이력을 제공하고 편집 추천을 실제 랭킹과 분리한다.
- 감사 조회에서 계정·권한·큐레이션·콘텐츠 사건을 연결한다. 비공개 초안 예외 열람은 별도 사유·최소 권한·감사를 요구한다.
- 수익·정산 메뉴의 현재 조회 범위를 유지하며 미검증 지급 동작은 제공하지 않는다.

**완료 조건:** 신고 접수 → 제한 관리자 검토 → 권한 있는 조치 → 작가 통지 → 이의제기 → 별도 해제/유지 조치 → 감사 추적이 통과한다. 읽기 권한으로 조치·본문 수정·지급이 실행되지 않고 권한 회수 후 기존 세션 요청도 거절된다.

검증: `test:admin-operations`, `test:launch`, `test:auth`, `test:operations`, 권한별 직접 요청·감사·중복 처리·동시 조치 회귀 및 실제 운영 인수.

## 9 21단계 발견과 성장 실험

신인 작품의 노출·첫 열람·관심 등록·연재 지속률과 독자 D7/D28 재방문을 측정한다. 충분한 데이터가 생기기 전에는 편집·장르·신인 노출 규칙을 사용하고 복잡한 개인화·AI 추천은 뒤로 둔다.

- 루키→챌린지 성장 배지는 검증된 공개 회차·소설 글자 수/웹툰 분모·최근 14일 유효 열람·관심·최소 완독 표본을 기준으로 후보 dry-run부터 수행한다. 제안 수치 10화/45,000자/3,000뷰/100관심/65%는 가설이며 실제 분포·부정 트래픽·편향 검증 뒤 확정한다. 플러스/유료화·독점·권한은 별도 심사/계약으로 진행한다.
- KST 집계일·정책 버전·평가 근거·이전 등급 CAS·고유 평가 키·알림 outbox로 재실행을 안전하게 만든다. 기존 Cloudflare 실행 기반을 우선 사용하고 Inngest/QStash는 실제 운영 필요와 비용을 확인한 뒤 추가한다. IP/Cookie만으로 유효 독자나 개인정보 보호를 보장한다고 가정하지 않는다.
- 작품별 페이지 제목·공유 이미지·sitemap과 외부 유입 → 첫 열람을 측정한다. 비공개·등급 제한 콘텐츠의 검색 노출을 보호한다.
- 신규 작품 편집 캠페인과 작가 지원·콘텐츠 공급을 검증한다. 공모전은 심사·권리·부정 행위 대응·담당이 준비된 뒤 운영한다.
- 소설 원작의 웹툰화·작가/그림 작가 협업·계약 제안은 권리자와 참여 권한·크레딧·배분을 먼저 설계한다.
- HWP/HWPX·회차 분리·맞춤법/AI 보조·팬미팅·굿즈는 실제 수요·운영 비용을 확인해 독립 계획을 만든다.

**완료 조건:** 실험별 가설·표본·기간·대조 기준·이용 지표·운영 비용을 기록하고 유지/수정/종료를 결정한다. 조회 증가만으로 성공을 판단하지 않으며 콘텐츠 공급과 재방문이 함께 개선되는지 확인한다.

## 10 공통 보존과 검증 규칙

`Author`는 신원과 데이터 도메인, `Creator`는 기존 스튜디오 이름이다. `WebNovelsAuth.getActor().author`, `/creator`, `/api/v2/creator/*`, `CreatorWorks`, `CreatorDraftEditor`와 기존 DOM/저장소/별칭을 유지한다. Auth UUID·작가 ID·작품 ID·초안 UUID를 구분한다. `CREATOR_MGMT` 등 영속 권한을 검증 없이 변경하지 않는다.

기존 초안·공개본·계정 매핑·원장·신고·감사 기록을 보존한다. 스키마는 추가 → 검증 → 전환 → 폐기 순서로 이관하고 운영 재시드·초기화·광범위 RLS 재개방을 하지 않는다. 새 데이터 보존과 신규 쓰기 제한을 복구 기본으로 삼는다.

개발 검증은 범위별 회귀와 타입 검사를 먼저 실행한다. 실제 DB·Storage·업체·호스팅·브라우저 인수는 환경과 근거를 구분한다. 문서에 브라우저 시험이 적혀 있다는 이유로 실행 권한이 생기지 않으며, [프로젝트 규칙](../../.agents/rules/testing_rules.md)의 명시 요청 조건을 따른다. 비밀·원고 전문·계좌 원문은 로그·산출물·Git에 넣지 않는다.

각 단계의 상태는 계획 수립/미착수 → 구현 → 로컬 검증 → 실환경 인수 → 완료로 관리한다. 완료에는 변경 파일·커밋·명령·결과·적용 SQL·배포/환경·미해결 이슈가 필요하다. 담당 역할은 제안이며 실제 담당자와 기한은 14단계 시작 때 배정한다.

15~21단계의 구현에 착수할 때는 해당 명세를 `improveN.md`와 필요한 계약 문서로 구체화하고 먼저 읽는다. 현재 14~16단계 실행 기록은 `improve14.md`, `improve15.md`, `improve16.md`에 있으며 다음 17단계도 별도 명세와 검증 기록을 먼저 준비한다.

## 11 바로 다음 개발 묶음

첫 묶음인 [14단계](../../improve14.md)에서 비독점 연재 설정·외부 링크·권리 확인·이력을 추가했고, [15단계](../../improve15.md)의 최대 대기 자동 저장·첫 공개 체크리스트·게시 결과 재확인과 [16단계](../../improve16.md)의 독자 탐색·이어보기·공개 회차 이동도 로컬 검증을 마쳤다. 실제 DB/배포/활성화는 별도 대기다. 공개 전환의 최신 증거 상태표·보류 원본·복원/권한 잔여 목록도 계속 준비한다. 다음 코드 묶음은 17단계 관리자 사건 처리·계정 지원·편집 큐레이션과 감사 흐름이다.

이 네 개선은 실제 독서의 신뢰와 재방문에 직접 영향을 준다. 이후 작가 첫 발행과 운영 처리의 실환경 인수를 마치고 웹툰 업로드·뷰어를 확장한다.
