# UI-R3 — 독자 홈·작품 탐색 개편

작성일: 2026-10-31 · 상태: **구현·로컬 검증 완료** · 기준: [UI 개편 계획](ui-redesign-plan-2026-10-30.md), [R1 확정 명세](../design/ui-r1/README.md), [R2 공통 기반](ui-r2-foundation-2026-10-31.md)

## 적용 내용

독자 화면을 상단 검색과 작품 탐색 중심으로 재구성했다. 기존 좌측 독자 메뉴의 기능은 상단 주요 메뉴·서재와 모바일 메뉴로 연결한다.
작가와 관리자 업무 화면은 기존 내부 메뉴를 유지하며, 화면 구성은 계정 역할이 아니라 실제로 진입한 화면을 기준으로 결정한다.

| 영역 | 결과 |
| --- | --- |
| PC 공통 | 최대 1280px, 로고·실제 검색 입력·내 서재, 홈/웹소설/웹툰/랭킹/신작/완결 탐색 |
| 모바일 | 상단 검색, 같은 작품 종류 메뉴, 홈/탐색/내 서재/내 정보 하단 메뉴, safe-area 여백 |
| 홈 | 실제 이어읽기 → 선정 작품이 있으면 편집 추천 → 최근 공개 웹소설·웹툰 → 중복되지 않는 선택 섹션 |
| 적은 작품 | 같은 작품을 여러 진열에 반복하지 않고, 빈 편집 추천·인기·신작·완결 섹션은 생략 |
| 탐색 | 종류 탭·작품/작가 검색·장르, 조건별 해제, 접이식 상세 필터, 항상 보이는 결과 수·정렬 |
| 카드 | 표지 2:3, 제목·작가·종류·연재/휴재/완결·이용등급·공개 회차, PC 최대 6열/모바일 2열 |
| 연결 수정 | 서재의 ‘새 작품 찾기’, 탐색의 검색창 초점, 장르 버튼의 중복 이벤트 호출 정리 |

홈의 최신 웹소설은 기존 공개 목록 API에 `type=NOVEL&sort=latest&limit=6`으로 조회한다.
기존 홈의 `new` 응답은 첫 공개 시각순이므로 ‘새로 시작한 연재’에만 사용한다. 웹툰은 기존 홈 응답의 최근 공개 목록을 재사용한다.
홈 요약과 최신 소설은 독립적으로 처리해 한 요청의 실패가 성공한 목록을 지우지 않게 했다.
선정·최신 목록에 같은 작품이 있으면 앞선 진열에만 표시하며, 공개 작품이나 조회·독자·추천 수를 생성하지 않는다.
인기 집계가 있는 경우에만 기존 최소 표본·기간·집계 의미를 표시한다.

홈 목록에는 실제 첫 공개 회차 번호가 없으므로 작품 상세로 연결한다. 1화를 추정하거나 존재하지 않는 읽기 링크를 만들지 않는다.
이어서 읽기는 기존 계정별 이력과 실제 공개 회차 검증을 그대로 사용한다.
공개 탐색 기능이 꺼진 기존 모드에서도 실제 공개 회차가 있는 작품만 두 기본 진열에 표시한다.

## URL·접근성·보안 계약

- `q`, `type`, `genre`, `status`, `rating`, `epRange`, 반복 `tag`, `sort`, 불투명 `cursor`와 뒤로가기 계약을 유지한다.
- 탐색 중 헤더 검색·작품 종류 전환·조건 해제는 다른 조건을 보존하고 페이지 cursor만 초기화한다. 전체 초기화도 웹소설/웹툰 종류를 유지한다.
- 실제 링크를 사용하며 Ctrl/Cmd·수정키·새 탭 동작을 유지한다. 현재 메뉴는 밑줄·`aria-current`, 종류와 조건은 기존 선택 속성으로 식별한다.
- 검색 입력에 label·100자 제한을 제공하며, 본문 이동 링크와 공개 목록의 로딩·실패·재시도 문구를 제공한다.
- 상세 필터는 [HTML details/summary](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/details)를 재사용한다. 내부 정렬·초기화는 접이식 영역 밖에 둔다.
- 작품명·작가명·검색어·태그는 DOM/textContent로 표시한다. 임의 HTML이나 외부 스크립트를 삽입하지 않는다.
- 작가 편집 화면과 독서 뷰어에는 독자 하단 메뉴가 겹치지 않도록 숨김과 하단 여백을 함께 조정한다.
- `/creator`, 기존 DOM ID·Author/Creator 계약·인증/소유권·원고·예약/발행·공개 후 변경 검토·서체와 읽기 위치 설정을 유지한다.
- 서버·API·DB·마이그레이션·공개 플래그·비밀·Cloudflare 설정은 변경하지 않았다.

## 조사와 검증

`search-first`로 기존 Catalog·라우터·계정 메뉴·CSS·테스트를 조사했다. Codebase Memory 연결이 종료되어 소스 검색·읽기로 대체했다.
기존 DOM API·URLSearchParams·HTML disclosure와 설치된 parse5/esbuild/Node 테스트를 재사용했다.
새 의존성이 필요하지 않아 npm/PyPI 패키지 조회·설치를 수행하지 않았다.

| 검증 | 결과 |
| --- | --- |
| 신규 UI-R3 테스트 | 21개: 실제 데이터·중복·빈 상태·부분 실패·늦은 응답·필터·내비게이션·DOM 경계·기존 모드 |
| 기존 R2 테스트 | 5개 통과: 색상·서체·본문 테마·CSS·정적 자산 |
| 기존 탐색·라우팅·인증 | 관련 회귀 검증 및 전체 릴리스에 포함 |
| 전체 릴리스·빌드 | 전 41개 릴리스 명령·Prisma 생성·TypeScript 빌드 통과. [검증 기록](../../artifacts/ui-r3-verification-2026-10-31.json) |
| 보안·변경 | 작가/관리자/뷰어/상세 DOM 보존·서버/원고 구현 보존·비밀 패턴·기존 사용자 작업 보존 확인 |

`test:ui-r3`를 전체 `test:release`에 연결했다. 독립 lint 명령은 없으므로 CSS 파싱·JS 구문·diff 검사를 사용한다.
코드 커버리지 비율은 측정하지 않았다. 정적 검증과 VM 대역 검증을 실제 브라우저·운영 DB 인수로 간주하지 않는다.
저장소 규칙에 따라 localhost와 브라우저를 실행하지 않았다. 실제 좁은 화면·200% 확대·모바일 키보드·보조기술 조작은 별도 인수 대상이다.
운영 데이터와 계정은 변경하지 않았다. push 뒤 CI·자동 배포와 공개 정적 자산 확인은 별도로 보고한다.

## 다음 단계 — UI-R4 상세·서재·소설/웹툰 뷰어

1. 작품 상세의 표지·제목·작가·소개·연재 상태·대표 읽기 행동을 R1 배치로 정리한다. 실제 첫 공개 회차와 회차 목록을 유지한다.
2. 서재의 이어읽기·관심작·구독 작가를 단순한 목록으로 구성하고 빈 상태·연결 실패를 구분한다.
3. 소설 뷰어의 조작부와 회차 이동을 정리하면서 Word 문단·굵기·기울임·정렬, 독자 서체·크기·행간·테마·읽기 위치를 유지한다.
4. 웹툰은 화면 폭과 원본 비율을 유지하고 이미지 로딩·실패·회차 이동의 상태 표현을 통일한다.
5. 계정 전환·비공개/삭제 회차·실제 회차 번호·늦은 응답·문의 진입 회귀를 검증한 뒤 독립 커밋·push한다.
