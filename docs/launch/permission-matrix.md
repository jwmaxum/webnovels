# 목표 권한과 현재 권한의 차이

기준일: 2026-09-23. 아래는 후속 구현을 위한 확정 기준이며 현재 코드가 이미 준수한다는 의미가 아니다.

## 역할별 권한

`자기`는 서버 검증된 Auth UUID에 연결된 소유자만 뜻한다. `위임`은 서버 권한+업무 사유가 있는 제한 관리자다. 최고 관리자도 원고 대필·정산 조작·비밀값 공개 권한을 자동으로 갖지 않는다.

## 보안상 고정할 규칙

1. 기본 거절. localStorage 역할·필명·요청 authorId를 권한 증거로 사용하지 않는다.
2. 계정 정지·탈퇴·권한 변경은 서버의 최신 상태로 반영한다.
3. 창작 내용 변경과 운영 제재를 다른 필드·API·권한으로 분리한다. 작가가 휴재/공개 상태를 바꿔도 운영자 제한은 유지된다.
4. 관리자 비공개 열람은 지원 요청/신고 사건 ID, 범위, 만료, 사유, 접근 기록을 남긴다. UI 숨김만으로 보호하지 않는다.
5. 독자 기능을 가진 작가라도 역할 혼합으로 타인 데이터 권한이 늘어나지 않는다.
6. 시스템 예약 실행자는 대상 작업에 한정된 서버 권한만 사용하며 일반 관리자/작가 토큰으로 임의 예약 실행을 허용하지 않는다.
7. 수익 확장 시 작가는 본인 조회·출금 요청만, 검증·마감·지급은 분리된 운영 권한으로 제공한다.

## 기존 권한 문자열 이관표

새 권한명 중 9단계 운영 조회·사건·제재·계정 조치·큐레이션·감사 범위는 [관리자 운영 계약](admin-operations-contract.md)의 서버 전용 RPC에 구현했다. 나머지는 설계 계약이다. 기존 배열을 그대로 새 권한으로 모두 확대하지 말고 계정별 실제 업무에 맞춰 최소 범위로 이관한다.

| 기존 이름/위치 | 목표 권한군 | 처리 |
|---|---|---|
| DASHBOARD | OPERATIONS_READ | 개인 정보 없는 운영 요약 |
| USER_MGMT / v2 USERS_READ | ACCOUNTS_READ, ACCOUNT_SUPPORT, ACCOUNT_MODERATE | 읽기·지원·제재 분리 |
| HTML AUTHOR_MGMT / 탭 CREATOR_MGMT | 위 계정 권한 + 작가 탭 범위 | 동일 기능의 이름 충돌 제거 |
| WORK_MGMT / EPISODE_MGMT / v2 CONTENT_WRITE | CONTENT_METADATA_READ, CONTENT_MODERATE, CURATION_WRITE, CONTENT_CASE_READ | 원고 쓰기 권한으로 일괄 변환 금지 |
| CONTENT_REVIEW / COMMENT_REPORT | CASE_READ, CASE_RESOLVE, CONTENT_CASE_READ | 검수/신고 처리와 원고 열람 범위 연결 |
| SYSTEM_MGMT / v2 CONFIG_READ | CONFIG_READ, CONFIG_WRITE, ADMIN_ROLE_MANAGE | 역할 부여는 최고 관리자 전용 |
| SECURITY_MGMT | AUDIT_READ | 감사 로그 임의 수정·삭제 불가 |
| AD_MGMT / AD_REVENUE / AUTHOR_SETTLEMENT | 13단계 AD_OPERATE, REVENUE_CLOSE, SETTLEMENT_PAY 등 별도 설계 | 초기 역할 부여/메뉴 활성 금지 |
| FAN_MEETING / GOODS_MGMT / EVENT_MGMT | 비활성 권한 기록 보존 | 초기 API 접근 허용하지 않음 |
| ANALYTICS | OPERATIONS_READ 또는 수익 확장 권한 | 지표와 개인정보 범위 분리 |

## 현재 구현의 차이와 담당 단계

| 확인 사항 | 근거 | 해결 |
|---|---|---|
| HTML 작가 메뉴는 AUTHOR_MGMT, switchAdminSubTab은 CREATOR_MGMT | index.html / admin.js | 3·9 |
| 구 requirePermission은 ADMIN/SUPER_ADMIN 자동 통과, v2는 SUPER_ADMIN 외 세부 권한 확인 | auth.middleware.ts / secure-api.mjs | 3·10, 관리자 계정 이관 시 영향 검사 |
| v2 CONTENT_WRITE가 본문 읽기·쓰기·운영 상태 변경을 결합 | authorizeContent, editor 판정 | 3·7·9 |
| v2 작가는 DRAFT만 본문 수정, 공개본 편집/재게시 미제공 | episodes PATCH | 7 |
| 클라이언트 관리자/작가 세션·필명 필터는 서버 소유권 대체 불가 | creator.js / router.js | 3·4·10 |
| 비밀번호 필드를 브라우저에서 직접 비교하는 경로 | supabase-admin.js readerLogin/authorLogin | 3·10 |
| 구 revenueRouter 인증 미들웨어 없음 | revenue.router.ts / app.ts | 10 이전 운영 재노출 금지, 수익 확장은 13 |

## 필수 권한 검증

[인수 시나리오](acceptance-scenarios.md)의 AUTH-03, SEC-01~04, MOD-01~03을 계정별 직접 API/DB/Storage 요청으로 수행한다. 관리자 화면에서 버튼이 사라졌다는 확인만으로 통과하지 않는다.
