# 8단계 작가 운영·독자 연결 계약

기록일: 2026-09-24. 로컬 구현과 합성 PostgreSQL 검증 기록이다. 실제 Supabase 적용·브라우저 인수·운영 활성화는 완료하지 않았다.

## 작가 운영

- 기존 `/creator`, `/creator/works/:id`, `/creator/works/:id/settings`, `/reactions` 주소를 유지한다. 새 플래그가 켜지면 홈·내 작품·설정/도움말을 먼저 보이고, 원고와 공개·예약 관리 진입은 작품 상세에 둔다. 옛 탭 주소는 호환 진입점으로 남긴다.
- 홈은 Auth UUID에 연결된 작가의 최근 ACTIVE 초안과 실패 예약을 보여준다. 회차 목록은 소유 작품의 메타데이터만 조회하고 번호/제목 검색·상태 필터를 제공한다.
- 공개본 수정·예약 변경/취소는 008 게시 API와 불변 버전 계약을 사용한다. 개별 공개 철회는 회차 상태를 DRAFT로 바꾸고 공개본 head·본문·댓글을 보존한다. 공개 복구는 head가 있는 회차에만 가능하다. 작품 전체 비공개·휴지통 복구는 기존 작품 API를 유지한다.
- 연재 상태 변경은 작품 version과 `KEEP`/`CANCEL` 예약 선택을 한 트랜잭션에서 검증한다. KEEP이면 휴재·완결 상태에서도 기존 예약이 시각에 실행된다. CANCEL이면 PENDING 예약을 감사 이벤트와 함께 취소한다. RUNNING 작업이 있으면 전체 변경을 중단한다.
- 댓글 정책, 금칙어, 최소 완독 회차, 작품별 독자 차단·해제, 댓글 숨김·해제·신고는 검증된 작품 소유자만 실행한다. 숨김은 영구 삭제가 아니며 본문과 action/report 이력을 보존한다. 플랫폼 전체 계정 정지나 타 작품 삭제 권한은 없다.
- 최근 30일 통계는 서버 기록의 고유 인증 독자만 집계한다. 작가 본인의 이벤트는 집계하지 않는다. 0건과 5명 미만을 구분하고, 표본이 적으면 회차별 수치를 숨긴다. 관심·댓글 수는 같은 30일 기간의 건수다. 통신/권한 오류는 집계 0으로 대체하지 않는다.
- 예약 실패 이벤트와 신고 검토 완료는 작가 알림으로 생성한다. 읽음 기록은 별도 보존한다. 문의 및 실제 관리자 신고 처리 화면은 아직 연결되지 않아 해당 알림의 운영 인수는 대기다.

## 독자 연결

- 공개 카탈로그는 서버 전용 `stage8_catalog`에서 실제 공개 작품/회차 메타데이터만 반환한다. 기존 발견·검색·장르·태그·최근 목록은 이 결과를 사용한다. 본문은 기존 `/api/v2/episodes/:id/content`의 공개·등급·권한 검사를 통과해야 한다.
- 새 독자 경로에서는 아직 서버 검증 경로가 없는 Golden Best·후원 명예의 전당·후원 결제를 표시하거나 호출하지 않는다. 후속 단계에서 별도 인수한다.
- 독서 기록·관심작·작가 구독·뷰어 설정은 검증된 Auth UUID를 키로 새 private 테이블에 저장한다. 필명·이메일·localStorage는 권한 근거가 아니다. 새 경로에서 계정 변경은 메모리 캐시를 비우고 지연 응답을 버린다. 예전 직접 DB/로컬 캐시 경로는 플래그가 꺼진 호환 경로이며 10단계 전환 목록에 남는다.
- 익명 독자는 공개 무료 본문과 공개 댓글을 읽을 수 있지만 활동 이벤트·댓글 쓰기는 인증 독자만 가능하다. 진행률은 0~100으로 제한하고 회차/작품 공개 상태를 서버에서 재검증한다. 이벤트는 사용자·회차·종류·시간 구간별로 중복을 제한한다.
- 문단 댓글은 공개본 버전 UUID, 문단 번호, 해당 문단 SHA-256, 서버가 가져온 최대 300자 문맥을 보존한다. 공개본이 바뀌거나 문단이 달라지면 새 문단 배지를 붙이지 않고 과거 문맥을 보여준다. 클라이언트가 보낸 필명이나 인용문은 저장 근거로 사용하지 않는다.
- 댓글 정책에 따른 쓰기 거절 등 업무상 403은 유효한 Auth 세션을 지우지 않는다. 만료·비활성 계정 응답만 세션을 정리한다.

## 적용 경계

009는 `authoring-008`과 실제 `public.comments` 구조 확인 및 복원 가능한 DB/Storage 백업 뒤 같은 검토 세션에서만 적용한다. 2~7단계 운영 스키마·Auth 매핑·권한·Cron 검증도 선행해야 한다. 기존 작품 댓글 정책은 새 private 정책에 보존 복사한다. 기존 `creator_comment_blocks.reader_id`가 검증된 Auth UUID인지 모르는 행이 있으면 적용을 중단하고 먼저 신원 매핑을 검토한다. 이번 작업은 합성 PGlite에서 001~009를 실행했으며 운영 DB에는 적용하지 않았다.

`P0_API_ENABLED`, `AUTHOR_PUBLISH_ENABLED`, `READER_SERVICE_ENABLED`, `AUTHOR_OPERATIONS_ENABLED`를 운영에서 일괄 활성화하지 않는다. 예제 플래그는 모두 false다. 먼저 별도 환경에서 다른 작가/독자 간 접근, 구형 공개 댓글/활동 이관, 직접 DB 권한 잠금, PC·모바일 및 새로고침/직접 링크, 대량 카탈로그, 예약 경쟁과 알림 전달을 인수한다.

롤백은 신규 플래그를 내리고 신규 쓰기를 닫는다. 새 독서기록·관심·댓글·정책·감사 기록을 삭제하지 않는다. 구형 public 댓글·관심·독서기록과 새 private 모델의 이관은 검증 전 자동 병합하지 않는다. 운영 SQL 실행 시 기존 원본과 중복 여부를 먼저 대조한다.
