# WebNovels 다국어 지원과 웹소설 번역 개발계획

2026-11-06 · 독자 화면과 작품 정보, 웹소설 시범 번역 범위 승인

현재 서비스는 Cloudflare Pages의 HTML·JavaScript 화면, Supabase 인증·데이터와 서버 API로 구성되어 있다. 기존 화면과 API를 단계별로 확장해 한국어 `ko`, 영어 `en`, 일본어 `ja`, 중국어 간체 `zh-Hans`를 지원한다. 번체 `zh-Hant`는 별도 선택 항목으로 추후 추가할 수 있다. 화면 표시 언어, 작품의 원문 언어, 독자가 선택한 번역 언어를 따로 관리한다.

| 범위 | 구현 가능한 수준 | 권장 출시 범위 |
|---|---|---|
| 독자 화면 | 홈·탐색·추천·검색 필터·작품 상세·서재·뷰어·가입/로그인·오류·접근성 문구 | 4개 언어. 한국어 기본, 명시적으로 선택한 언어 기억 |
| 작품 정보·검색 | 작가가 입력하거나 승인한 현지어 제목·소개·회차명·키워드로 검색하고 원문으로 대체 표시 | 시범 작품부터 적용. 일본어·중국어 검색 분절과 원문/현지어 결과 확인 |
| 웹소설 본문 | 발행한 원문을 기준으로 자동 번역 초안 생성, 작가가 편집·검수한 번역본 열람, 원문으로 전환 | 작가가 동의한 무료 웹소설 2종, 작품당 5화, 한국어 원문에서 영어·일본어·중국어 간체로 시범 번역 |
| 작가·관리자·지원 | 작가 화면과 관리자 문구 현지화, 문의 양식, 이메일 템플릿, 약관·정책의 검토 번역 | 시범 단계에 번역 작업·검수 UI를 추가하고, 전체 운영 화면과 메일·정책은 후속 단계에서 검증 |
| 웹툰·회원 게시물 | 웹툰 제목·소개·회차명 번역, 작가 제공 번역 이미지나 말풍선 레이어, 댓글의 선택적 번역 | 웹툰은 제목·소개·회차명부터 적용. 말풍선 이미지 OCR·재식자와 댓글 번역은 별도 승인 범위 |

## 승인 후 개발 순서

1. **ML-01 · 언어 설정과 독자 화면.** 기존 화면 문구를 키 기반 번역 사전으로 옮긴다. 첫 접속은 한국어를 기본으로 하고 사용자가 고른 언어를 브라우저에 저장한다. 문서 `lang`, 날짜·숫자 표기, 줄바꿈·서체, 키보드 초점과 스크린리더 안내를 함께 다룬다. 같은 작품·회차와 읽던 위치에서 언어를 바꿀 수 있게 한다. 완료 기준은 네 언어의 홈→탐색→상세→뷰어와 가입→확인→로그인 흐름이 이어지고, 필수 문구 누락과 모바일 잘림이 없는 것이다.
2. **ML-02 · 작품 정보와 현지어 탐색.** 기존 작품 ID와 원본을 기준으로 언어별 제목·소개·회차명을 연결한다. 게시된 번역 정보가 있으면 해당 언어 목록·검색에 반영하고, 준비 중이면 원문과 원문 언어를 표시한다. 고유명사, 원제, 띄어쓰기 없는 일본어·중국어, 한글/로마자 혼용으로 검색 품질을 평가한다. 번역 정보가 없거나 기존 작품을 열 때 원문과 링크가 유지되는 것이 인수 기준이다.
3. **ML-03 · 웹소설 자동번역 시범.** 작가가 번역 및 외부 처리 범위에 동의한 작품을 선택하고, 서버에서 공개된 회차의 확정 버전을 번역 대기열에 넣는다. 제목과 문단을 식별자로 맞춰 보내고 문단·대사·줄바꿈·허용 서식을 복원한다. 인물명, 호칭, 지명과 표기 예외는 작품별 용어집으로 관리한다. 언어별 초안은 작가 또는 지정 검수자가 원문과 나란히 비교·수정하고 승인한 뒤 공개한다. 승인 기준은 시범 10화의 번역본 30건 전수 확인, 문단 누락·순서 변경과 권한 우회 0건, 인물·존칭·줄거리의 의미를 바꾸는 오류 수정이다.
4. **ML-04 · 자동번역 운영 확대.** 발행 후 동의한 작품만 자동으로 초안을 만들고, 회차 원문 버전과 목표 언어·용어집 버전을 기준으로 작업을 구분한다. 같은 버전의 결과를 재사용하고, 예산·재시도 한도와 관리자의 중지·재실행 메뉴를 제공한다. 원문 수정 시 이전 번역본을 이력으로 두고, 새 버전 승인 전 독자에게는 현재 원문을 제공한다. 삭제·공개 중단·연령·열람권 검사도 원문의 서버 판정을 적용한다. 관리자 화면은 번역 건수·실패·비용·대기 현황을 표시한다.
5. **ML-05 · 서비스 운영 다국어와 검색 노출.** 작가·관리자 화면, 문의, 인증·안내 메일과 검토된 약관·환불 안내를 확장한다. 검색 노출이 필요하면 공개 번역 작품에 공유 가능한 언어별 주소를 제공하고, 해당 페이지의 `canonical`, `hreflang`, 사이트맵을 함께 검증한다. 회원·결제·정산의 현지 적용 범위는 서비스 운영 정책과 연동이 준비된 국가부터 확정한다. [Google Search Central의 언어별 페이지 안내](https://developers.google.com/search/docs/specialty/international/localized-versions)

## 자동번역 엔진과 비용

| 후보 | 비교 기준 |
|---|---|
| Google Cloud Translation Advanced | 한국어·영어·일본어·중국어 간체/번체의 언어 지원, 글자 수 과금, 용어집 지원을 기준으로 첫 시범 후보로 삼는다. [지원 언어](https://docs.cloud.google.com/translate/docs/languages) · [용어집](https://docs.cloud.google.com/translate/docs/advanced/glossary) |
| DeepL API | 같은 회차를 번역해 인물 호칭·말투·용어 일관성과 후편집 시간을 비교한다. API의 언어별 기능 응답에서 실제 계정의 목표 언어와 용어집 호환성을 확인한다. [번역 API](https://developers.deepl.com/api-reference/translate/request-translation) · [지원 기능 조회](https://developers.deepl.com/api-reference/languages/retrieve-supported-languages) |

Google Cloud NMT 공개 기본 요율은 월 50만 자 크레딧과 초과 사용량 100만 자당 미화 20달러다. 회차당 5,000자 × 10화 × 목표 언어 3개는 약 15만 자로, 기본 요율로 환산하면 크레딧 차감 전 번역 API 비용이 약 3달러다. 재번역, 별도 인프라와 사람의 검수 시간은 이 계산 밖에 있다. 실제 입력량과 해당 월의 남은 크레딧은 시범 운영에서 확인한다. [Google Cloud Translation 요금표](https://cloud.google.com/products/translate/pricing)

번역 결과는 원문·버전과 분리해 저장한다. 번역 제공자에는 해당 회차의 승인된 원문과 필요한 용어집만 전달한다. 계정·결제·비공개 원고는 작업 입력에서 제외한다. 작가 동의 범위와 제공자의 저장·처리 조건은 외부 전송 전에 확인한다. 작업이 중복 전달될 수 있으므로 같은 번역 요청의 결과가 중복 공개되거나 재과금되지 않도록 영속 작업 키와 결과 상태를 검사한다. 제공자 응답이 유실된 경우에는 자동 재요청 전에 상태를 대사한다. [Cloudflare Queues 전달 보장](https://developers.cloudflare.com/queues/reference/delivery-guarantees/)

## 단계별 반영 범위

사용자가 독자 화면·작품 정보부터 시작하고 웹소설 시범 번역까지 진행하는 범위를 승인했다. 각 단계를 검증한 뒤 개별적으로 Git에 반영한다.

- **1단계 · ML-01과 ML-02.** 헤더와 뷰어에서 4개 언어를 선택하고, 같은 경로에서 화면·작품 정보를 바꾼다. 한국어가 기본이며 선택은 기기에 저장한다. 원문과 번역본은 기존 작품 ID에 연결하고, 열람 중 언어를 바꿔도 본문과 읽기 위치를 유지한다. 탐색 언어가 바뀌면 검색어와 필터를 유지한 채 새 언어의 첫 결과 페이지를 불러온다.
- **작품 정보 적용.** 제목·소개·회차명·검색 키워드를 승인 근거와 원문 버전에 연결한다. 적용 조건과 원문 변경 시 처리 절차는 [작품 정보 번역 운영 문서](reader-metadata-approval.md)에 정리했다. 운영에서는 승인본 등록과 DB 적용 전까지 원문을 표시한다.
- **2단계 · ML-03.** 동의한 무료 작품 2종·10화를 확정하고 원문 버전별 초안, 용어집, 검수 화면과 예산 한도를 연결한다. 번역 제공자와 비용 한도는 실제 전송 전에 확정한다.

1단계에서 독자·인증·검색·카탈로그 회귀 검사 337개와 최종 화면 보완 후 관련 검사 18개가 통과했다. TypeScript 컴파일과 Cloudflare Pages Functions 번들 6개를 확인했다. 작품 승인, 다국어 검색, 공개 범위 검사는 합성 DB에서, 독서 위치 및 문구 전환은 가상 DOM에서 수행했다. 실제 독자 인수와 승인 번역 등록은 운영 적용 절차에 포함된다.

## ML-03 운영 절차

1. 운영 DB에 검증한 `authoring-033`을 추가한다. 기본값은 번역 중지와 예산 0이다. 번역 표의
   직접 API 권한은 부여하지 않으며 Cloudflare의 `NOVEL_TRANSLATION_PILOT_ENABLED`도 준비 후 설정한다.
2. 운영자가 한국어 원문인 무료 웹소설을 최대 2종 선정한다. `authoring.novel_translation_works`에
   현재 작가 ID와 작품 ID를 연결하고, 작가는 작품의 회차 관리에서 번역 권한과 외부 처리 범위를 확인한 뒤 동의한다.
   자동번역 대상은 현재 공개된 무료 회차의 앞 5화다. 작가의 말·계정·비공개 원고는 외부로 전송하지 않는다.
3. 인명·호칭 표기가 필요한 작품에는 같은 프로젝트·리전의 다국어 Google 용어집을 준비한다.
   `glossary_resource`와 `glossary_revision`을 함께 기록하고, 변경 시 새 리소스로 교체한다.
   새 버전의 원문·용어집·동의를 기준으로 새로 검수한 번역만 공개한다.
4. 제공자 조건과 비용 한도를 확인하고 운영 DB의 `character_limit`을 설정한다. 운영 Pages에
   `NOVEL_TRANSLATION_GOOGLE_PROJECT`, `NOVEL_TRANSLATION_GOOGLE_LOCATION` 및 최소 권한의 단기
   `NOVEL_TRANSLATION_GOOGLE_ACCESS_TOKEN`을 설정한다. 토큰은 서버 비밀로 저장하고 만료되면 교체한다.
   DB 설정의 `enabled`와 Pages 시범 플래그를 적용한 뒤 선정 작가에게 검수를 안내한다.
5. 작가가 회차·언어를 선택해 요청하면 DB에서 요청 ID와 글자 수를 먼저 예약하고 서버가 공개 원문을 보낸다.
   같은 원문 버전·언어·동의·용어집 조합은 한 번만 제출된다. 시범 총량은 30건이며 실패·응답 불명 작업도
   예약량에 포함된다. 처리 중 또는 실패로 남은 작업은 제공자 이력을 대조한 뒤 운영자가 판단한다.
6. 작가는 원문과 초안을 대조해 수정하고 공개를 승인한다. 독자는 현재 무료 원문과 승인 언어를 같은
   회차에서 전환한다. 원문 수정, 비공개 전환, 유료 전환, 동의 철회가 있으면 이전 번역은 표시되지 않는다.
   번역 전환 후 댓글 인용은 원문 문단에 연결된다.

번역 API에 보내는 단위는 제목과 기존 문서의 텍스트 구간이다. 문단·줄바꿈·굵게·기울임·밑줄·정렬은
기존 원고 구조에서 복원한다. 서식 경계를 넘는 문장과 인명·호칭은 공개 전 사람이 대조한다.
실제 외부 요청 전에 작품별 동의, Google 제공 조건, 사용할 예산을 확정해야 한다.
