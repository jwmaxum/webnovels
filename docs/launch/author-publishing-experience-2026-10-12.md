# 작가 직접 발행·Word 서식·웹툰 탐색

기준: 2026-10-12 사용자 요청. 32단계 hosted 인수에 앞서 구현하는 작가 경험 보완이다.
기존 Author/Creator 신원·경로·초안 revision·공개본 보존 계약을 유지한다.

## 발행 권한 계약

| 작업 | 웹소설·웹툰 공통 동작 |
|---|---|
| 작품 등록, 비공개 원고 작성·수정 | 본인 작품을 작가가 직접 관리 |
| 첫 회차, 다음 새 회차의 최초 발행 | 작가가 저장본·권리·등급을 확인하고 즉시 발행. 관리자 사전 검수 없음 |
| 아직 공개하지 않은 회차 예약 | 작가가 예약·변경·취소. 기존 서버 예약·멱등 계약 유지 |
| 발행된 회차 수정 | 공개본에서 별도 초안 작성 → 저장 revision으로 변경 검토 요청 → 관리자 승인 시 교체 |
| 발행 이력이 있는 작품 정보·표지·연재 형태·연재 상태 변경 | 변경 요청을 보관하고 승인 전까지 기존 설정 유지 |
| 발행된 작품 삭제·비공개·회차 철회·복구 | 관리자 검토 후 휴지통/노출 상태 변경. 원본·구매·댓글·이력은 영구 삭제하지 않음 |
| 신고에 따른 관리자 긴급 노출 제한 | 기존 운영 권한·사유·감사 계약으로 처리 |

기존 원본 누락 자료의 **복구 검토**와 새 원고의 **최초 발행**을 혼동하지 않는다.
기존 자료에 요구했던 관리자 권리·원본 검토를 새 회차의 사전 검수 절차로 확대하지 않는다.

## 이번 코드

- `/discover?type=NOVEL`, `/discover?type=WEBTOON`에 동등한 탐색 탭과 진입점을 제공한다.
  검색·필터 초기화에서도 작품 종류를 유지한다. 공개 가능한 목록만 사용하며 비공개 원고를
  탐색 데이터로 섞지 않는다. 공개 카탈로그 연결 전 기존 목록에서도 종류를 분리한다.
- 작성 화면에 `미리보기 후 발행` 버튼을 표시한다. 신규 회차는 `지금 발행`, 기존 회차는
  `수정 검토 요청`으로 구분한다. 기능 미연결 시 이유를 작성 화면에 표시하고 원고는 보존한다.
- Word 클립보드 HTML은 [parse5](https://github.com/inikulin/parse5)로 실행·네트워크 없는
  파싱 후 제한된 JSON으로 변환한다. 문단, 줄바꿈, 굵게, 기울임, 밑줄, 정렬, 기본 들여쓰기와
  목록 텍스트를 보존한다. 임의 HTML, URL, 폰트, 배경 CSS를 저장하거나 삽입하지 않는다.
- `contentDocument`와 순수 텍스트 `content`를 함께 검증한다. 기기 사본·충돌·버전 복구·
  서버 revision·불변 공개본·공개본 수정 초안·독자 뷰어에 같은 문서가 전달된다.
- 웹툰은 전체 선택 파일을 먼저 대기 목록에 표시하고 순차 처리한다. 선택 순서/파일명 자연순을
  선택하고 완료 후 드래그·위/아래 버튼으로 순서를 바꾼다. 실패 후 재시도도 같은 배치의
  원래 순서를 유지한다. 파일당 8 MiB, 회차당 100개/128 MiB 및 기존 이미지 검증은 유지한다.
- 웹툰 독자 화면은 화면 너비 안에서 비율을 유지한다. 기존 분할·WebP/PNG 처리와 메모리/동시
  요청 제한을 재사용한다. 모바일에서는 웹툰의 좌우 여백을 줄인다.
- 변경 검토는 기존 작가 RPC의 소유권·필드·revision 검증을 롤백되는 DB 하위 트랜잭션에서
  실행해 검증한다. 변경 후보와 기준 상태는 불변 테이블에 남기며, 본문을 오류 로그에 넣지 않는다.
  승인은 기준 상태·원고 revision 재확인, 실제 반영, 결정·감사 기록을 한 트랜잭션에서 처리한다.
- 관리자 검수 화면에서 전후 원고·웹툰·표지를 확인한다. 이미지마다 관리자 권한·요청에 고정된
  자산인지 검사한다. 작가 작품 화면에는 최근 20개 요청의 대기·승인·반려와 사유가 표시된다.
- 공개본 수정 예약은 현재 지원하지 않는다. 수정은 승인 시 반영하며, 기존 수정 예약도 승인
  없이 공개 head를 교체할 수 없다. **새 회차 최초 예약 발행은 유지**한다.

Word의 종이 쪽 배치, 표 구조, 이미지, 각주, 사용자 폰트와 정확한 글자 크기까지 재현하지 않는다.
독자의 화면 폭과 읽기 설정에 맞게 재배치하며, 제외된 요소는 붙여넣기 안내에 표시한다.
기존 DOCX/HWPX **파일 가져오기**는 별도의 텍스트 변환 계약을 유지한다. 서식 보존은 이번의
클립보드 붙여넣기 경로에 적용하며, 파일 변환까지 완료했다고 표시하지 않는다.

## 적용 순서와 운영 경계

1. 기존 별도 hosted 복원·마이그레이션/RLS/Storage 인수를 진행한다. 현재 비공개 작업공간의
   부분 설치를 전체 공개 서비스 준비 완료로 해석하지 않는다.
2. `015`를 포함한 기존 의존성을 확인하고 `021_manuscript_documents.sql`,
   `022_publication_change_review.sql`을 검토된 백업·격리 복원에서 적용·검증한다.
   직접 호출 가능한 옛 작가 변경 RPC는 권한 없는 내부 구현으로 이동하고 기존 공개 RPC는
   검토 분기를 갖는 동일 이름/서명으로 유지한다. 마이그레이션 재적용도 검증한다.
3. 최초 발행·재시도, 비공개 후에도 남는 발행 이력, 수정·삭제·철회·표지·연재 형태의 검토,
   관리자 권한 철회, 실제 다중 연결 충돌, 승인 도중 실패 rollback을 hosted에서 인수한다.
4. 공개 서비스의 기존 P0/무료 공개/Storage 조건 충족 후 `AUTHOR_PUBLICATION_REVIEW_ENABLED`,
   `AUTHOR_RICH_TEXT_ENABLED` 및 기존 기능 설정을 의도한 환경에 활성화한다. 검토 경로 없이
   공개 기능부터 켜지 않는다. 이번 코드 작업에서 운영 설정을 임의로 변경하지 않는다.
5. 기능 되돌리기는 공개/작성 기능을 먼저 잠그고 불변 문서와 검토 이력을 보존한다. `021/022`를
   되돌리기 위해 기존 DB 함수를 무검토 구현으로 덮어쓰거나 서식 컬럼을 삭제하지 않는다.
   서식 원고가 있는 환경에서 구형 편집기로 쓰기를 재개하는 것도 별도 인수 사항이다.

현재의 부분 비공개 작업공간은 검토가 연결되기 전에 공개/회차 이력이 있는 작품의 metadata·
휴지통·연재 형태 변경을 서버에서 보수적으로 차단한다. 순수 신규 비공개 작품과 수정 초안
저장은 계속 허용한다. 영속적인 발행 이력과 원자적 변경 검토는 `022`의 역할이다.

## 검증과 남은 인수

`test:author-publishing`은 안전한 Word 파싱, 문서 제한·일치 검증, API 권한/Origin,
합성 PostgreSQL의 최초 발행·검토 전 보존·승인 반영·기준 변경 거절·재시도·RPC 권한을 검증한다.
기존 초안·파일·발행·웹툰·탐색·계정 회귀와 빌드/타입/Functions 번들을 함께 실행한다.

이는 실제 DB 적용이나 브라우저 인수 결과가 아니다. 명시 요청 없는 localhost/브라우저 검증은
진행하지 않는다. 실제 Word 버전별 붙여넣기, 한글 IME·선택/실행 취소·모바일 키보드, 긴 웹툰
이미지 업로드·네트워크 끊김·관리자 전후 비교는 후속 실제 기기 인수에 포함한다.

추가 개선: 승인된 수정의 예약 반영, 변경 요청 취소·중복 병합·알림/페이지네이션,
DOCX/HWPX 파일의 동일 서식 모델 변환, 글쓰기 도구의 키보드·실행 취소 고도화.
