# 웹소설·웹툰 UI 디자인 개편 계획서

작성일: 2026-10-30 · 갱신: 2026-11-01 · 상태: **UI-R1~R13 기록 연결 / OP-03 구현·로컬 검증, 운영 적용 대기** · 범위: 색상, 서체, 정보 배치, 반응형 화면

최초 요청에서는 계획만 작성했고, 후속 R1 진행 요청에 따라 **글자 대비를 우선한 색상·SUIT 서체·주요 화면 10종을 확정**했다.
[R1 확정 명세](../design/ui-r1/README.md)와 [PC·모바일 시안 모음](../design/ui-r1/index.html)을 기준으로 후속 구현을 진행한다.
후속 R2에서 공통 색상·서체·컴포넌트를 서비스 코드에 연결했다. [R2 결과와 검증 범위](ui-r2-foundation-2026-10-31.md)를 함께 참조한다.
R3에서 독자 공통 탐색·홈·검색 레이아웃을 적용했다. [R3 결과와 다음 단계](ui-r3-reader-discovery-2026-10-31.md)를 참조한다. R4에서 상세·서재·뷰어를 개편했다. [R4 결과](ui-r4-reader-experience-2026-10-31.md)를 참조한다. 기존 37단계 운영 인수 계획과 별도로 UI-R1~R7 순서로 추진한다.

## 1. 제안 방향

**밝은 회색 바탕, 흰 콘텐츠 면, 선명한 작품 표지, 절제된 핑크가 중심인 독서 서비스**로 정리한다.
표지와 작품명을 먼저 보게 하고, 독자에게는 읽기, 작가에게는 쓰기·발행, 관리자에게는 처리할 업무를 우선한다.

| 영역 | 변경 방향 | 판단 기준 |
| --- | --- | --- |
| 색상 | 사용자 팔레트를 원본 토큰으로 보존하고 용도별 토큰으로 연결 | 같은 기능은 같은 색상·상태를 사용 |
| 서체 | UI는 SUIT 계열 1종, 소설 본문은 별도의 독서 서체·기존 사용자 설정 유지 | 한글·영문·숫자의 크기와 무게가 자연스럽게 이어짐 |
| 효과 | 단색 면과 얇은 구분선 중심, 그림자는 팝업·떠 있는 조작부에 제한 | 일반 카드에 발광·유리 효과·장식용 그라데이션을 반복하지 않음 |
| 정보 배치 | 독자는 상단 탐색과 책장, 작가는 편집 작업면, 관리자는 목록·상세 구조 | 서로 다른 역할의 화면을 하나의 대시보드 모양으로 통일하지 않음 |
| 글자 강조 | 제목 600~700, 본문 400, 버튼 600 중심 | 모든 제목·숫자를 800~900으로 강조하지 않음 |
| 콘텐츠 | 실제 공개 작품과 실제 상태만 표시 | 자료가 적으면 섹션을 줄이고 빈 공간을 허위 작품·통계로 채우지 않음 |

색상 사용 비중은 콘텐츠 면적 기준으로 중립색 약 90%, 핑크 약 8%, 보라 약 2%를 출발점으로 삼는다.
표지 자체의 색상은 이 비율에 포함하지 않는다. 수치는 디자인 검토용 가이드이며 구현의 강제 비율이 아니다.

## 2. 현재 소스에서 확인한 개선 대상

이번 점검은 로컬 소스와 기존 계약 문서 기준이다. 실제 브라우저 화면·웹폰트 로딩·모바일 인수를 수행하지 않았다.
Codebase Memory에 이 저장소의 인덱스가 없어 구조 조회와 coverage 확인은 사용할 수 없었고, 저장소 내부 파일을 직접 읽었다.

| 근거 파일 | 확인한 내용 | 계획에 반영할 사항 |
| --- | --- | --- |
| `public/styles.css` | 밝은 테마이나 청회색 배경, 기존 CDG 변수, 여러 그라데이션·발광·blur 규칙이 공존 | 실행 화면에서 사용하는 규칙부터 새 토큰으로 정리. 남아 있는 규칙이 모두 현재 노출된다고 단정하지 않음 |
| `public/styles.css`, `public/index.html` | Pretendard·Outfit·Noto 계열 지정 및 800~900 굵기, 인라인 스타일 혼재 | UI 서체와 굵기 체계를 통일하고 실제 적용 폰트·fallback을 별도 확인 |
| `public/index.html`, `UI_pc.md` | 독자 화면도 데스크톱 고정 사이드바를 전제로 구성 | 독자는 상단 탐색 중심으로 넓은 작품 목록 확보 |
| `public/js/reader/reader-discovery.js` | 목록·홈·상세가 JS에서 생성되며 URL 필터와 상태 연동 | HTML만 수정하지 않고 동적으로 생성하는 카드·빈 상태도 함께 설계 |
| `public/js/creator/creator-editor.js`, `creator-rich-editor.js`, `creator-webtoon.js` | 저장·복구·발행 및 문서·이미지 편집 기능이 이미 분리되어 있음 | 새 편집기 도입보다 기존 기능의 배치와 표현을 개선 |
| `public/css/free-beta.css`, `webtoon.css` 등 | 기능별 CSS와 서비스 활성 상태에 따른 노출 규칙 존재 | 공통 토큰을 공유하되 비활성 기능 숨김과 웹툰 비율 규칙 유지 |
| `design.md` | 과거 다크·CDG PLAY 방향과 최초 게시 심사 설명 포함 | 승인 후 현행 밝은 디자인·작가 최초 발행 계약에 맞춰 문서 정합성 정리 |

기술 선택은 현재 HTML/CSS/JavaScript SPA와 기존 모듈을 확장하는 안이다. 디자인 개편을 이유로 Next.js·Tailwind·새 UI 라이브러리로 이전하지 않는다.
이번 조사에서 패키지 설치·npm/PyPI 레지스트리 전수 검색은 하지 않았다. 기존 코드, 사용 가능한 MCP, 서체 공식 배포 문서와 W3C 기준을 확인했다.

### 3.2 용도와 대비 보완

색상 이름의 `primary`가 항상 버튼 배경 500을 의미하도록 만들지 않는다. 원본 팔레트와 실제 컴포넌트의 용도를 분리한다.

| 용도 | 배경 / 글자·선 | 적용 |
| --- | --- | --- |
| 페이지 / 콘텐츠 면 | Base / Elevated | 회색 배경 위 흰 작품 목록·편집 면 |
| 대표 행동 버튼 | Primary 800 / White | `첫 화 읽기`, `이어서 읽기`, `지금 발행`. hover는 900 |
| 밝은 브랜드 강조 | Primary 500 / Text Strong | 필요한 강조 배지·보조 행동. 흰 글자는 사용하지 않음 |
| 선택된 탭·필터 | Primary 50 또는 100 / Primary 800 | 밑줄·체크·선택 속성도 함께 표시 |
| 일반 버튼 | White / Text Primary | 중립색 외곽선, hover는 Neutral 100 |
| 키보드 포커스 | Secondary 500 외곽선 | 2px 이상 + offset, 주변 색과 구분되도록 흰 간격 포함 |
| 링크·필수 설명 | Primary 800 또는 Text Secondary | 링크는 밑줄 또는 명확한 문맥을 제공 |
| 입력란 경계 | 추가 용도 토큰 `--border-input: var(--color-neutral-500)` | 기본 연한 구분선과 구별. label을 placeholder로 대체하지 않음 |
| 비활성 상태 | Neutral 100 / Text Disabled | 실제 disabled 상태에만 사용, 사용 불가 사유는 Text Secondary |

원본 값으로 sRGB 상대휘도를 계산한 결과다. 아래 수치는 표시용 반올림이며 실제 통과 판정은 반올림 전 값으로 한다.

| 조합 | 대비 | 일반 크기 글자 판단 |
| --- | ---: | --- |
| White / Primary 500 | 2.83:1 | 사용하지 않음 |
| Text Strong / Primary 500 | 6.62:1 | 사용 가능 |
| White / Primary 800 | 7.07:1 | 사용 가능 |
| White / Secondary 500 | 4.87:1 | 사용 가능 |
| Text Tertiary / White | 3.30:1 | 작은 안내·필수 정보에는 사용하지 않음 |
| Text Secondary / Base | 5.46:1 | 사용 가능 |

제공된 Semantic fg/bg 조합도 일반 크기 글자에서는 각각 약 2.20, 2.56, 3.68, 3.87:1로 4.5:1에 미달한다.
원본 fg는 장식 색으로 보존하고, 상태 문구에는 다음 **R1 확정 추가 토큰**을 사용한다.

| 추가 토큰 | 확정값 | 해당 Semantic bg 위 대비 |
| --- | --- | ---: |
| `--text-success` | #137B29 | 4.77:1 |
| `--text-warning` | #A33A13 | 5.84:1 |
| `--text-error` | #B71F1F | 5.41:1 |
| `--text-info` | #174CB8 | 6.46:1 |

상태를 식별하는 유일한 아이콘·테두리에도 충분한 대비를 제공한다. 원본 밝은 fg만으로 성공·실패를 전달하지 않는다.
`--border-default`·`--border-strong`은 모든 입력 컨트롤의 식별선으로 일괄 사용하지 않는다. 예를 들어 Strong/White는 약 1.64:1이다.
일반 텍스트 4.5:1, 필요한 비텍스트 정보 3:1 기준은 [W3C 텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)와
[비텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)를 적용한다.

## 4. 서체·간격·컴포넌트

UI 서체는 **SUIT Variable v2.0.5**로 확정했다. 제목·메뉴·버튼·관리자 표를 같은 서체로 맞춘다.
한글 작품명·회차명, 영문 로고, 숫자·상태가 포함된 시안을 확인했다. 별도 사용자 서체 비교 실험을 수행한 것은 아니다.
[SUIT 공식 배포·라이선스](https://github.com/sun-typeface/SUIT). 확정 크기·상태·예외는 [R1 명세](../design/ui-r1/README.md)를 따른다.

| 요소 | PC / 모바일 제안 | 굵기·행간 |
| --- | --- | --- |
| 페이지 제목 | 28 / 24px | 700 · 1.35 |
| 섹션 제목 | 22 / 20px | 600~700 · 1.4 |
| 작품 제목 | 16 / 15px, 최대 2줄 | 600 · 1.45 |
| UI 본문·입력 | 16 / 16px | 400 · 1.6 |
| 버튼·탭 | 15 / 15px | 600 · 1.4 |
| 보조 정보 | 13~14 / 13~14px | 400~500 · 1.5, 충분한 대비 |
| 소설 본문 | 기존 기본 18px 유지, 독자 설정 우선 | 기존 명조/고딕 선택·크기·행간 조절 유지 |

서체는 확정 버전의 WOFF2를 자체 제공한다. R1 자료에는 624,536 bytes의 폰트와 라이선스를 함께 보관하고 `font-display: swap`을 사용했다.
한글 가변 폰트가 항상 가장 작은 파일이라는 전제를 두지 않고 실제 전송량을 비교한다. UI 폰트 하나를 우선 로드하고 독서 폰트는 해당 화면에서 로드한다.
Outfit의 제목·랭킹 숫자 혼용을 정리한다. 사용자가 선택한 독서 서체와 원고의 굵게·기울임·정렬을 전역 CSS로 덮어쓰지 않는다.

간격은 4·8·12·16·24·32·48px 체계를 사용한다. 버튼·입력 높이는 44~48px, 모서리는 기본 8px/패널 12px이다.
pill은 장르 필터·상태 배지에 제한한다. 아이콘은 기존 Lucide를 유지하고 대체로 18~20px, 클릭 영역은 44px 이상으로 설계한다.
44px은 이 서비스의 사용성 목표다. WCAG 2.2 AA 최소 대상 크기는 예외 조건을 포함한 24px 기준으로 별도 점검한다.
[W3C 대상 크기 기준](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

컴포넌트 명세에는 버튼·탭·카드·입력·드롭다운·모달·표·알림의 기본/hover/focus/선택/비활성/로딩/오류 상태를 포함한다.
로딩 중 레이아웃 높이를 확보하고 중복 저장·발행을 막는다. 오류는 사유와 재시도 행동을 함께 보여준다.

## 5. 독자 화면 재구성

### 5.1 홈·탐색

PC 독자 화면은 고정 좌측 사이드바를 정리하고, 상단 검색과 장르·유형 탐색으로 통합하는 안을 권장한다.
관리자와 작가의 업무용 사이드바까지 동시에 없애지 않는다.

```text
[로고]              [작품명·작가 검색________________]     [내 서재] [내 정보]
홈   웹소설   웹툰   랭킹   신작   완결
──────────────────────────────────────────────────────────────────────
이어서 읽기 — 실제 읽기 이력이 있을 때만 표시

선정 작품: 표지 + 제목 + 소개 2줄 + [첫 화 읽기]
──────────────────────────────────────────────────────────────────────
최근 공개한 웹소설                              [전체 보기]
[표지] [표지] [표지] [표지] [표지] [표지]

웹툰을 만나보세요                               [전체 보기]
[표지] [표지] [표지] [표지] [표지] [표지]

완결까지 읽는 작품 / 실제 집계가 있는 인기 목록
──────────────────────────────────────────────────────────────────────
회사정보 · 이용약관 · 개인정보처리방침 · 환불정책 · 문의
```

- 대형 광고형 히어로 대신 높이 약 280~320px 이내의 작품 소개 모듈을 검토한다. 자동 회전·반짝임 없이 표지와 설명을 읽게 한다.
- 선정 작품이 없으면 추천의 빈 상태를 표시하고 최근 공개 목록은 별도 제목의 영역으로 유지한다. 추천을 다른 목록으로 자동 대체하지 않는다. 데이터가 없는 섹션은 생략하거나 간결한 빈 상태를 사용한다.
- 작품이 적을 때 동일 작품을 모든 섹션에 중복해 풍성하게 보이게 하지 않는다. 실제 인기·편집 추천·최신 공개를 문구로 구별한다.
- 카드 외곽 박스를 줄이고 표지 2:3, 제목, 작가, 이용등급·완결 여부 순으로 정리한다. 없는 수치·가짜 리뷰·임의 추천 문구를 추가하지 않는다.
- 탐색의 웹소설/웹툰 탭은 같은 계층·같은 필터 구조를 사용한다. 검색·장르·상태·정렬은 기존 URL query를 유지해 뒤로가기·링크 공유가 가능하게 한다.
- 모바일은 `검색 → 웹소설/웹툰 → 장르 → 결과` 순서. 상세 필터는 접이식 패널에 모으고 선택 결과와 초기화를 결과 위에 표시한다.
- 목록은 PC 최대 6열, 태블릿 3~4열, 모바일 기본 2열로 설계한다. 가로 스크롤 진열은 일부 홈 섹션에만 사용한다.

### 5.2 작품 상세·서재·뷰어

| 화면 | 주요 배치 |
| --- | --- |
| 작품 상세 PC | 좌측 표지, 우측 작품명·작가·소개·등급·연재 상태, 대표 행동 아래 회차 목록 |
| 작품 상세 모바일 | 작은 표지와 제목을 나란히, 소개 접기, `이어서/첫 화 읽기`와 관심 등록을 구별 |
| 회차 목록 | 회차·제목·공개일·읽음 상태의 단정한 행. 실제 공개된 회차만 탐색 가능 |
| 내 서재 | 이어서 읽기 / 관심 작품 / 구독 작가. 로그인 전·기록 없음·불러오기 실패를 구분 |
| 웹소설 뷰어 | 본문 폭 약 680~720px, 화면에 따라 축소. 상단 작품/회차, 하단 이전·목록·다음, 설정은 보조 메뉴 |
| 웹툰 뷰어 | 화면 안에 비율 유지, 컷 사이 틈 없음, 모바일 좌우 여백 최소화. 긴 이미지에 `object-fit: cover`나 고정 높이 금지 |

사이트 기본은 밝은 모드다. 뷰어 안에서 독자가 선택한 기존 다크·세피아·명조/고딕·글자 크기는 보존한다.
본문에는 브랜드 핑크 배경을 사용하지 않는다. 폰트 변경으로 줄바꿈이 달라질 수 있으므로 읽기 위치 복원도 함께 인수한다.

## 6. 작가 스튜디오 재구성

진입 시 `내 작품`을 기본으로 하고, 각 작품에서 `원고 작성`으로 이어지게 한다. 웹소설과 웹툰을 같은 작가가 함께 등록할 수 있어야 한다.
프로필·정산·통계는 보조 메뉴에 두고 현재 계정·연동 상태에 맞게 노출한다.

```text
[내 작품으로]   작품명 / 웹소설 또는 웹툰    저장 상태       [저장] [미리보기] [발행 ▾]
───────────────────────────────────────────────────────────────────────────────────
원고 목록·불러오기      | 회차 제목
[새 원고]              | 서식 도구 또는 이미지 업로드
임시저장 원고          | 원고 본문 / 순서가 표시된 웹툰 컷
공개한 회차            |
───────────────────────┴───────────────────────────────────────────────────────────
작품 설정: 표지 변경 · 소개 · 장르     추가 도구: 파일 가져오기 · 버전·복구
```

- 주요 행동은 `원고 작성·불러오기`, `저장`, `발행`으로 묶는다. 저장 상태는 `저장 중/저장 완료/실패/충돌`을 구분해 상시 표시한다.
- 발행 버튼은 신규 회차에서 `지금 발행 / 예약 발행`을 제공한다. 시간대와 예약 일시를 확인한 후 기존 발행 경로를 사용한다.
- 이미 공개된 회차에서는 `수정 검토 요청`, 작품·회차 삭제에서는 `삭제 검토 요청`으로 정확하게 표시한다. 최초 발행에는 관리자 승인 단계를 넣지 않는다.
- 공개본 수정에는 예약 발행을 제공하지 않는다. 기존 공개본 변경 계약에 따라 검토 승인 후 반영한다.
- 표지 변경은 작품 설정의 명확한 한 위치에 둔다. 공개된 작품의 표지 변경도 기존 검토 대상임을 표시한다.
- 소설: Word 붙여넣기의 허용 문단·줄바꿈·강조·정렬·목록을 유지한다. 임의 HTML·스크립트·외부 CSS·폰트를 허용하는 방식으로 바꾸지 않는다.
- 웹툰: 파일 선택/드롭 → 번호와 썸네일이 있는 대기 목록 → 순차 처리 → 위/아래 이동 또는 드래그 → 스크롤 미리보기 순서로 정리한다.
- 파일별 처리·실패·재시도 상태를 표시한다. 키보드로 순서를 바꿀 수 있어야 하며, 재시도로 기존 업로드를 중복 발행하지 않는다.
- 모바일에서 목록은 접을 수 있게 하고 편집 면을 넓힌다. 발행 조작부와 가상 키보드, 사이트 하단 메뉴가 겹치지 않게 한다.
- 저장하지 않은 원고, IndexedDB 기기 사본, revision 충돌·버전 복원은 디자인 변경 중에도 보존한다.

## 7. 관리자·공통 화면

관리자는 232~240px 사이드바 + 검색·필터 + 데이터 목록 + 상세 패널 구조를 권장한다.
메뉴는 기존 권한·경로를 재사용하고 `회원·작가`, `작품·공개 후 변경 검토`, `문의·신고`, `서비스 설정` 등 업무로 묶는다.
미신청 결제·PASS 서비스는 설정 상태를 정확히 보여주며 색상 개편을 위해 기능을 켜지 않는다.

대형 KPI 카드보다 미처리 요청·실패 작업·최근 처리 목록을 먼저 보여준다. 표는 날짜·상태·담당·행동의 위치를 일관되게 한다.
변경 검토는 이전/변경 내용과 승인·반려 사유를 함께 제공한다. 단순 색상 배지를 승인·본인확인의 증거처럼 사용하지 않는다.
로그인·회원가입·문의·법적 고지 페이지도 같은 입력·버튼·본문 서체를 공유한다. 회사정보와 환불정책 링크는 유지한다.

## 8. 반응형 기준과 수용 조건

| 화면 폭 | 제안 |
| --- | --- |
| 320~767px | 단일 작업 열, 좌우 16px, 필요 시 12px까지 조정. 독자 하단 메뉴는 홈/탐색/서재/내 정보 |
| 768~1199px | 좌우 24px, 독자 목록 3~4열. 작가 보조 패널은 접기 가능 |

개발 검증 폭은 320·375·390·768·1024·1440px을 포함한다. 카드 수보다 제목 가독성과 최소 폭을 우선한다.
200% 확대, 긴 제목, 긴 작가명, 키보드 포커스, 모바일 safe-area, 오류·빈 상태를 수용 조건으로 삼는다.
전역 가로 스크롤은 없도록 하고, 관리자 대형 표처럼 필요한 내부 가로 스크롤은 명확히 표시한다.
모션은 짧은 상태 전환에 제한하고 `prefers-reduced-motion`을 존중한다. 상태 전달을 색상이나 hover에만 의존하지 않는다.

## 10. 코드 적용 범위와 보존 계약

| 대상 | 예정 변경 |
| --- | --- |
| `public/styles.css` | 토큰 연결·공통 서체·기존 효과·반응형 규칙 정리 |
| `public/index.html` | 헤더·메뉴·정적 화면 구조, 서체 로드, 인라인 표현 스타일의 클래스 이전 |
| `public/css/{webtoon,free-beta,beta-operations,growth,policies}.css` | 활성 화면의 개별 스타일을 공통 토큰과 연결 |

| `public/js/creator/{creator-works,creator-editor,creator-rich-editor,creator-files,creator-webtoon,creator-publications}.js` | 동적 폼·조작부·상태 표시. 기존 엔진·원고·발행 계약 유지 |

| `design.md`, `UI_pc.md`, `UI_mobile.md` | 방향 확정 후 최신 화면·현재 계약으로 정리 |

CSS가 계속 뒤에 덧붙는 구조를 피한다. 같은 선택자의 중복 규칙과 인라인 스타일을 먼저 목록화하고 사용 화면별로 이전한다.
기존 `--bg-main`·`--bg-surface`·`--border-color`는 새 Base·Elevated·Default의 호환 별칭으로 연결한다.
`--cdg-pink`처럼 배경과 글자에 혼용된 변수는 일괄 Primary 500 치환을 하지 않고 역할을 나눈다. 확인 전 별칭을 삭제하지 않는다.

`/creator`, `CreatorWorks`, `CreatorDraftEditor`, `creator-*` ID와 서버의 Author 식별 계약을 보존한다.
표시용 모달 재배치가 서버 소유권 검사·권한·세션 검증을 대신하지 않는다. 웹툰 업로드 검증과 Word 안전 변환도 유지한다.
스타일 변경에 DB 마이그레이션은 필요하지 않을 것으로 예상한다. 별도 데이터 요구가 생기면 별도 범위로 분리하고 Supabase 명시적 GRANT/RLS 계약을 적용한다.
비즈피어 작가·조선 로맨스·기존 계정·초안·공개 버전을 테스트 데이터로 초기화하지 않는다.

## 11. 검증 계획과 이번 확인 범위

구현 시 `search-first → 구현 → security-review → verification-loop`를 변경 범위에 맞게 적용한다.

- 구조·동작: `test:naming`, `test:auth`, `test:creator-works`, `test:drafts`, `test:files`, `test:publication` 중 영향 범위 실행.
- 화면 계약: 독자 탐색·웹툰·공개본 변경 검토·스튜디오·운영 지원함 관련 기존 테스트를 선택해 실행. 숨김 화면도 실제 활성 조건별로 확인.
- 타입·빌드: `npx tsc --noEmit`, `npm run build`, Cloudflare 번들 검증. 없는 lint/coverage 명령을 성공으로 보고하지 않음.
- 보안: 사용자 콘텐츠의 안전한 DOM 렌더링, 업로드 제한, 서버 권한, 미공개 원고 노출, 비밀값 미포함 확인. 서체용 외부 스크립트나 넓은 CSP 예외 추가 금지.
- 시각·접근성: 사용자 명시 요청 후 실제 브라우저에서 위 화면 폭·키보드·확대·색 대비·모바일 키보드·로딩/실패 상태 확인.
- 성능: 구현 전후 동일 조건에서 CSS/폰트 전송량, 이미지 레이아웃 이동, 화면 진입 시간 비교. 현재 측정되지 않은 개선율을 약속하지 않음.

최초 계획 시에는 소스·문서 조사와 대비 계산을 수행했다. 후속 R1에서는 정적 시안 10종, 색상·자산·파일 참조를 추가 확인했다.
R1 실제 확인 항목과 한계는 [확정 명세](../design/ui-r1/README.md)와 [검증 결과](../design/ui-r1/verification.json)에 기록한다.
R1에서는 제품 코드를 변경하지 않아 빌드·타입 검사·기능 테스트·커버리지·브라우저·DB·클라우드 검증을 수행하지 않았다.
R2의 코드 적용과 릴리스·빌드 검증 결과는 [R2 완료 문서](ui-r2-foundation-2026-10-31.md)를 따른다. R3는 [독자 홈·탐색 완료 문서](ui-r3-reader-discovery-2026-10-31.md)에 기록한다.
위 대비 계산은 디자인 후보에 대한 정적 결과이며 전체 서비스의 WCAG 적합성 인증이 아니다.

R5의 구현·검증 범위는 [작가 스튜디오 개편 문서](ui-r5-author-studio-2026-10-31.md)에 기록한다.
R6의 구현·검증 범위는 [관리자·계정·문의·정책 개편 문서](ui-r6-operations-account-2026-10-31.md)에 기록한다.
R7의 실제 인수·수정·검증 범위와 미실행 항목은 [회귀·접근성·성능·배포 점검](ui-r7-release-acceptance-2026-10-31.md)에 기록한다.
R8의 구현·운영 적용·비공개 인수 범위는 [작가 직접 발행·예약 수정·독서 성능](ui-r8-author-acceptance-2026-10-31.md)에 기록한다.
R9의 **구현·릴리스·운영 발행 왕복과 029 적용**은 [운영 왕복·휴대폰 인수 기록](ui-r9-acceptance-2026-10-31.md)에 기록한다. Galaxy S26 Chrome과 PC 붙여넣기 정상 동작은 사용자 보고이며, Word 개별 서식의 저장·복원·200% 확대·음성 스크린리더·실제 LCP/CLS 반복 계측은 미확인이다. R10에서는 최신 요청에 따라 [작가 등록·발행 UX](ui-r10-author-registration-2026-10-31.md)를 개선했다. 다음은 **UI-R11: 신규 등록 실기기 인수·Word 상세·접근성·관측 근거에 따른 성능 개선**이다.
기존 37단계의 SMTP·외부 베타·복원 인수는 이 디자인 계획과 구분해 계속 관리한다.

R11은 사용자 회신에 따라 **휴대폰 정상 확인을 기록하고 빌드**하는 범위로 진행했다. [R11 확인·빌드 기록](ui-r11-acceptance-build-2026-10-31.md)에 사용자 보고와 미완료 인수를 구분한다. 다음 서비스 단계는 SMTP 준비 후 외부 가입·복구 메일 수신 확인과 독립 복원 인수다.

R12는 [작품별 회차 관리·간결한 발행](ui-r12-author-cms-2026-11-01.md) 요청을 반영한다. 회차별 최종 발행일·회원 열람수·읽기 전용 발행본과 수정 요청, 발행창의 폭 선택/본문 미리보기 제거, 최종 작성본 1건 중심의 불러오기를 웹소설·웹툰에 함께 적용한다. 다음 UI-R13은 새 CMS의 실제 작가 인수와 열람 지표 정책 확정이며, SMTP·복원 준비는 별도로 계속 관리한다.

후속 요청으로 **UI-R13은 [정산 계좌 관리·수동 서류 확인](ui-r13-settlement-registration-2026-11-01.md)을 우선 구현**한다. 개인·개인사업자·법인을 구분하고, 국외 보관 조건을 먼저 확정한다는 사용자 회신에 따라 실제 개인정보 접수는 준비 상태로 둔다. 다음 UI-R14는 최종 고지·처리 조건 확정 후 접수 개방과 실제 왕복 인수다. R12의 CMS 실기기 인수는 별도 미완료 항목으로 보존한다.

2026-11-01 추가 기획: [관리자 최소 메뉴와 수익 운영 개발계획](admin-cms-minimal-ux-plan-2026-11-01.md)은 14개 관리자 항목을 6개 상위 메뉴로 통합하고, 가입 독자 1~2화 무료·포인트 충전·회차 기본 100P·광고 보상·작가 정산을 단계별로 준비한다. 추천은 관리자가 직접 선정한 작품만 게시한다. [OP-02 회원 관리](op02-member-management-2026-11-01.md)는 작가·독자 탭을 분리해 검색·필터·50건 페이지·통합 상세와 최고 관리자 공개 정보 수정에 연결한다. 검색어는 계정별 메모리에만 두고 로그아웃 시 폐기한다. 정산·문의·공개본 변경 이력은 기존의 각 읽기 권한을 유지한다.

[OP-03 관리자 직접 선정 추천·전시](op03-manual-display-cms-2026-11-01.md)는 최대 200개 선정·순서·기간과 홈 대표 1개·기획 8개, 웹소설/웹툰 공통 추천 24개 페이지, 정형 홈 블록·메뉴 5개·공지 10개를 구현한다. 저장본 미리보기에서 즉시/예약 발행·중단/취소·초안 복원으로 이어지며 최신·랭킹과 수동 추천을 구분한다. 미선정·비공개 작품을 자동 대체하지 않고 필수 회사·정책 링크를 유지한다. 사용자가 운영 DB 적용을 명시 허용한 뒤 최신 백업·보존 리허설로 018 적용을 완료했고, 실제 서비스 RPC와 권한을 검증했다. 추천은 기본 빈 초안으로 시작하며 관리자가 직접 선정·게시해야 노출된다. 브라우저·휴대폰 인수를 실행한 것으로 기록하지 않는다.

[OP-04 회원 무료·가격·열람권 TEST](op04-points-test-implementation-2026-11-02.md)는 기존 `설정 → 서비스 정책`에 최고 관리자 TEST 등록·가격·시험 지급을 연결하고, 독자는 별도 `/reading-test`에서 회원 1~2화 무료·이후 기본 100P·보유 회차 재열람을 시험한다. 가격 우선순위는 회차→작품→기본이며 KST/UTC·불변 버전·CAS·5분 견적·명시적 동의/구매를 사용한다. Word 안전 서식, 인증된 웹툰 Blob·PNG fallback, 계정/이동 경계·URL 폐기와 운영 독서 이력 분리를 포함한다. 신규 68개와 전체 릴리스 54개 명령·컴파일·타입·독립 5단계 리허설이 통과했다. main push와 CI·Cloudflare 배포를 완료하고 두 도메인의 TEST OFF를 확인했다. 019 SQL·운영 TEST 플래그는 적용하지 않고 실제 결제·기존 잔액/권리를 유지한다. 실제 PostgreSQL 병렬·브라우저·실기기 인수는 미실행이다. 다음 OP-05는 충전상품·수동 입금 대조·카드 승인/환불의 TEST 구현과 기존 원장 감사이며, PG 계약·고지·결제/취소/대사 인수 이후에만 LIVE 전환을 검토한다.

[OP-05 충전·입금·환불 TEST](op05-topups-implementation-2026-11-02.md)는 기존 금융의 3개 탭을 최고 관리자 상품·입금/환불 증빙·대사에 연결하고 독자 `/charging-test`를 추가한다. 사용 가능/총액/환불 예약 P, 원충전별 소비·환불액을 구분하고 카드 복귀 뒤 서버 확인을 요구한다. 기본 LOCAL은 외부 카드창·모의 승인을 실행하지 않는다. 미확인 요청의 같은 ID 재시도와 계정/경로 폐기를 유지한다. 019·020과 금융 운영 플래그는 미적용이며, 실제 업체 TEST·브라우저·다중 연결 인수는 별도다. 다음 OP-06에서 광고 보상의 서버 증거·열람권과 실패 안내를 연결한다.

[OP-06 광고 보상 TEST](op06-ad-rewards-implementation-2026-11-02.md)는 새 상위 메뉴 없이 회차 가격 확인 안에 서버 보상 세션과 포인트 대안을 연결하고 기존 서비스 정책에 광고/무료 캠페인 sibling 패널을 둔다. 광고 없음의 기본 대안은 포인트 구매, 기본 상품은10,000원→10,000P다. 실제 서버 판매 SKU를 확인한 뒤 독자가 선택하며 자동 충전/차감하지 않는다. 광고·캠페인 임시권과 구매권을 구분하고 정책 재동의·증빙 유예·미확인 요청 재시도·계정/회차별 폐기를 유지한다. 미계약이므로 실제 광고는 열지 않고 내부 TEST 증빙만 검증한다. 다음 OP-07은 작가 정산 요청·확정 수익·예약·지급 증빙이며 개인정보/실기기/실제 업체 인수는 별도다.
