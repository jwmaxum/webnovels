# UI-R1 확정 명세 — 선명한 글자와 밝은 독서 화면

확정일: 2026-10-30 · 상태: **R1 디자인 기준·시안 완료** · 다음 단계: **UI-R2 공통 디자인 적용**

사용자의 “글자 대비가 뚜렷한 방향으로 확정하여 진행” 요청에 따라 색상 역할, UI 서체, 주요 화면 구성을 확정했다.
이 단계의 산출물은 검토용 HTML과 정적 디자인 보드다. 서비스 HTML/CSS/JS, DB, 계정, 발행 기능에는 아직 적용하지 않았다.

## 2. 색상 역할 확정

원본 팔레트는 보존하고 사용 역할을 구분한다. 밝은 핑크를 모든 배경·글자·버튼에 공통 적용하지 않는다.

| 역할 | 배경 | 글자·선 | 대비 / 판단 |
| --- | --- | --- | --- |
| 본문 | #FFFFFF | #292B2B | 14.24:1 · 기본 본문 |
| 제목 | #FFFFFF | #121212 | 18.73:1 · 제목·중요 정보 |
| 보조 설명 | #F5F6F6 | #606567 | 5.46:1 · 작은 필수 설명에도 사용 |
| 주요 버튼 | #8F357C | #FFFFFF | 7.07:1 · 읽기·저장 후 발행 등 대표 행동 |
| 주요 버튼 hover | #4F1D45 | #FFFFFF | 13.17:1 · 기본보다 진하게 |
| 브랜드 강조 | #F55DD6 | #121212 | 6.62:1 · 강조 배지·필요한 보조 행동 |
| 선택된 탭 | #FEEEFA | #8F357C | 6.34:1 · 밑줄·선택 속성 병행 |
| 키보드 포커스 | 흰 간격 뒤 외곽선 | #6E52FF | 흰색과 4.87:1 · 최소 2px, 권장 3px + offset |
| 입력란 식별선 | #FFFFFF | #878F91 | 3.30:1 · 텍스트가 아닌 경계선 |

흰 글자 / 밝은 핑크 #F55DD6은 2.83:1이므로 버튼 문구에 사용하지 않는다.
`--text-tertiary` #878F91도 흰 배경에서 3.30:1이므로 일반 크기 필수 문구에는 사용하지 않는다.
`--border-default`, `--border-strong`은 장식 구분선으로 사용하며 입력란 식별선 역할은 `--border-input`으로 분리한다.
사용자가 비워 둔 `--border-focus`는 **#6E52FF**로 확정한다.

성공·주의·오류·정보의 원본 밝은 fg는 보존한다. 일반 크기 상태 문구에는 다음 추가 토큰을 쓴다.

| 상태 | 글자 토큰 | 값 | 기존 상태 배경 위 대비 |
| --- | --- | --- | --- |
| 성공 | `--text-success` | #137B29 | 4.77:1 |
| 주의 | `--text-warning` | #A33A13 | 5.84:1 |
| 오류 | `--text-error` | #B71F1F | 5.41:1 |
| 정보 | `--text-info` | #174CB8 | 6.46:1 |

색상만으로 상태를 전달하지 않고 `저장 완료`, `재시도`, `검토 요청` 등 문구를 함께 쓴다.
대비 판정은 반올림 전 수치로 일반 텍스트 4.5:1, 필요한 비텍스트 정보 3:1을 적용한다.
이 계산만으로 서비스 전체의 접근성 적합성을 인증하는 것은 아니다.
[W3C 텍스트 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html),
[W3C 비텍스트 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).

## 3. 서체·크기·간격 확정

**UI는 SUIT Variable v2.0.5**로 통일한다. 한글 작품명·회차명·버튼, 영문 로고, 숫자가 포함된 시안에서 사용했다.
Pretendard와의 별도 사용자 비교 실험은 진행하지 않았다. 이번 확정은 현재 시안의 가독성과 사용자 지시를 기준으로 한다.

| 요소 | PC / 모바일 | 굵기·행간 |
| --- | --- | --- |
| 페이지 제목 | 28~30 / 24~26px | 700 · 1.35 |
| 작품 대표 제목 | 최대 36 / 24~26px | 700 · 1.35 |
| 섹션 제목 | 22~24 / 20~22px | 600~700 · 1.4 |
| 작품 카드 제목 | 16 / 15~16px | 600 · 1.45 · 최대 2줄 |
| UI 본문·입력 | 16 / 16px | 400 · 1.6 |
| 버튼·탭 | 15 / 15px | 600 · 1.4 |
| 보조 설명 | 14 / 14px | 400~500 · 1.5 |
| 짧은 배지·비필수 보조 | 13 / 13px | 500~600 · 충분한 대비 유지 |
| 소설 본문 | 기존 기본 18px, 독자 설정 우선 | 기존 명조/고딕·크기·행간 선택 보존 |

모든 제목을 800~900 굵기로 만들지 않는다. 본문과 안내 글자를 흐리게 처리하지 않는다.
시안의 편집 본문은 작업면 구성을 설명하는 표본이며 독자 뷰어의 기본 글자 크기를 변경하는 계약이 아니다.
확정 서체는 WOFF2 **624,536 bytes**를 자체 제공하고 `font-display: swap`을 사용한다.
실제 브라우저의 다운로드 시간·레이아웃 이동은 아직 측정하지 않았다. 구현 후 로드 위치와 캐시 정책을 점검한다.
소설 독서 폰트와 Word에서 허용된 문단·굵기·기울임·정렬에는 전역 UI 서체 규칙을 강제하지 않는다.

간격은 4·8·12·16·24·32·48px, 컨트롤 높이는 44~48px, 기본 모서리는 8px, 패널은 12px이다.
필터 배지의 색 면은 작게 표현할 수 있지만 실제 클릭 영역은 높이 44px 이상 확보한다.
작품 표지는 2:3, 본문 웹툰 이미지는 원래 비율을 유지하며 잘라내지 않는다. 아이콘은 기존 Lucide를 유지한다.

폰트와 라이선스는 [assets](assets/manifest.json)에 출처·버전·SHA-256을 기록했다.
[SUIT 공식 배포](https://github.com/sun-typeface/SUIT/releases/tag/v2.0.5), [SIL Open Font License](assets/SUIT-LICENSE.txt).

## 5. 화면과 기능 보존 계약

### 독자

- PC는 상단 탐색과 검색, 최대 1280px 콘텐츠 폭을 기준으로 정리한다. 홈·탐색의 고정 좌측 메뉴는 R3에서 이전한다.
- 모바일은 홈/탐색/서재/내 정보 하단 메뉴와 두 열의 작품 카드를 사용한다. 검색은 상단에서 접근한다.
- 웹소설·웹툰은 같은 깊이의 탐색 메뉴를 제공한다. 검색·장르·상태·정렬·URL query와 뒤로가기 동작을 보존한다.
- 작품 상세는 대표 읽기 행동을 먼저 식별하게 한다. 실제 공개 회차만 읽기 목록으로 연결한다.
- 뷰어는 밝은 기본 화면을 제공하되 기존 독자 테마·글자 크기·서체·읽기 위치를 보존한다.

### 작가

- 메뉴 중심은 `원고 작성·불러오기 → 저장 → 미리보기 → 발행`이다. 썸네일 변경은 작품 설정에 둔다.
- **신규 회차**는 `지금 발행 / 예약 발행`을 작가가 직접 진행한다. 최초 발행에 관리자 검수 단계를 추가하지 않는다.
- **공개된 작품·회차의 수정·삭제**는 `수정 검토 요청 / 삭제 검토 요청`으로 표시한다. 공개된 표지 변경도 기존 검토 흐름을 따른다.
- 공개본 수정에는 예약 발행을 제공하지 않는다. 새 원고/공개본/예약본에 따라 실제 사용 가능한 행동만 노출한다.
- 예약 확인에는 날짜·시각·시간대(Asia/Seoul)를 명시한다. 서버의 기존 저장·발행 상태가 실제 표시의 근거다.
- 소설은 기존 Word 안전 변환과 자동 저장·revision·기기 사본·복구를 보존한다. 임의 HTML·스크립트·외부 CSS 허용으로 바꾸지 않는다.
- 웹툰은 번호·썸네일·파일별 상태를 표시하고 순차 업로드, 위/아래 이동, 실패한 파일 재시도를 제공한다. 재시도는 실패한 항목에만 노출한다.
- 웹툰 뷰어·미리보기는 화면 폭 안에서 원본 비율을 유지한다. 고정 높이·`object-fit: cover`를 본문 컷에 적용하지 않는다.
- 모바일 편집 화면에서는 독자 하단 메뉴를 중복 고정하지 않는다. 가상 키보드·safe-area와 조작부 겹침은 R5 인수 대상이다.
- 동일 Author가 웹소설과 웹툰을 모두 등록할 수 있다. `/creator`, `CreatorDraftEditor`, `creator-*` ID와 인증·소유권 계약을 유지한다.

관리자·계정·정책 페이지와 상세 뷰어 시안은 이번 5종에 포함하지 않았다. R4·R6에서 같은 기준으로 확장한다.
결제·PASS·SMTP의 실제 신청 및 운영 인수는 기존 37단계 계획으로 별도 관리한다.

## 6. 검증 범위

`verification-loop`의 단계를 디자인 산출물 범위에 맞춰 적용한다. 실행 결과는 [verification.json](verification.json)에 기록한다.

- 색상: 47개 토큰, 원본값 보존, 사용하는 텍스트·포커스·입력선 조합의 상대휘도 대비를 정적으로 검증.
- 파일: HTML 파싱, 문서 내부 링크·CSS·폰트·이미지 참조, 이미지 alt와 크기, 자산 해시·라이선스 확인.
- 시안: 10개 PNG의 크기·글자 경계와 실제 생성 이미지를 확인. 이 보드는 Sharp와 SUIT TTF로 합성했으며 **브라우저 화면 캡처가 아니다**.
- 보안: 외부 실행 스크립트·폼 제출·API 호출이 없는 검토 자료인지 확인하고 변경 파일의 비밀 패턴을 점검.
- 변경: 제품 코드·DB·배포 설정 변경 여부, 기존 작업 파일 보존, 커밋 대상만 확인.

제품 빌드·TypeScript·기능 테스트·커버리지는 제품 코드가 변경되지 않아 이번에는 적용 대상이 아니다.
저장소 규칙에 따라 localhost/브라우저 검증을 수행하지 않았다. 실제 반응형 동작·키보드 조작·폰트 로딩·접근성 인수는 구현 후 명시 요청 시 진행한다.

## 7. 다음 단계 — UI-R2

예상 범위는 1~2 작업일이다. 실제 소스 영향 조사와 검증 결과에 따라 조정한다.

1. `public/styles.css`와 기능별 CSS의 기존 변수를 확인하고 확정 토큰·SUIT를 공통 스타일에 연결한다. `--bg-main`, `--bg-surface`, `--border-color`는 호환 별칭으로 유지한다.
2. `--cdg-pink` 등 글자·배경 혼용은 용도별로 나눈다. 버튼·입력·탭·카드·알림의 기본/선택/hover/focus/disabled/오류 상태를 적용한다.
3. 서체를 로컬 자산으로 제공하고 기존 로딩·CSP·정책을 확인한다. 작가 원고·독자 본문 서체 설정은 전역 규칙에서 보호한다.
4. 기존 동적 생성 UI와 인라인 스타일에도 색상 역할을 연결한다. 헤더·메뉴·페이지의 큰 재배치는 R3~R6 범위로 남긴다.
5. 변경 범위에 따른 타입·빌드·DOM/권한/원고 회귀·색상 검증을 마치고 독립 커밋·push한다. 기능 플래그나 DB를 디자인 작업 때문에 변경하지 않는다.

**R2 완료 기준:** 활성 UI의 주요 글자 대비 충족, focus 식별, 원본 토큰 보존, 로컬 폰트 라이선스 포함, 기존 계정·원고·발행 계약 회귀 없음.
실제 레이아웃 전환 순서는 **R3 독자 홈·탐색 → R4 상세·서재·뷰어 → R5 작가 → R6 관리자·공통 → R7 통합 인수**다.
